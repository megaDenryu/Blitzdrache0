# 物理基盤の工程

## これは何か

物理基盤の工程とは、物理基盤(`crates/blitz_sim`・`crates/blitz_collision`・`crates/blitz_math` の数値表現)の欠陥を直すときと、その数値表現・時間の意味・状態の寿命・CPUとGPUの境界を変えるときに、親が守る作業の順序のことである。順序は **契約 → 責務層 → 反証 → 一次計測 → 設計裁定 → 本実装** であり、親はこの順を飛ばさない。

この工程で使う語を先に定める。契約とは、その系が満たすべき不変条件(例: 静止摩擦係数0.6の十分内側では姿勢によらず保持する)のことである。責務層とは、契約が破れる原因になりうる処理の層(幾何・接触の候補・履歴・状態の表現・拘束の式・連立の解法・許容差・速度の再構成・速度段階・時間の離散化)のことである。一次計測とは、症状(試験の合否)ではなく生の物理量(位置・速度・乗数の合計・力積など)を細分ごとに比較する測定のことである。設計裁定とは、一次計測の結果を材料に、どの層をどう変えるかを本実装の前に決める短い判断のことである。

制定の経緯: Issue #59「静止摩擦の保持・滑走境界を座標の単精度と解法許容差から独立させる」と PR #97 の往復で、親は初期に「いま見えている失敗を塞ぐ最小の差分」へ早く着地し、探索のための機構(候補D)を原因の確定前に本番の候補へ育てすぎた。一方、後半の「力積の収支まで追って所有権を証明する」「効果の証明が無い機構を1317行ごと外す」は今後の標準になった。オーナーは2026-09-08にこの工程を物理基盤の標準と裁定した。

## 工程(この順で行う)

### 1. 契約: 症状と破れている契約を最初に分けて書く

親は、作業の開始時に必ず次の2行を書く。

```text
観測された症状:
破れている物理または数値の契約:
```

例: 「正接0.55の坂の箱が滑る」は症状であり、契約は「静止摩擦係数0.6の十分内側では、姿勢・支持の範囲内の平行移動・妥当な解法の許容差によらず保持する」である。作業者が症状だけを目的にすると、対処はその1場面を通す局所の修正へ寄る。

### 2. 責務層: 原因の候補を層ごとに列挙し、触る層と除外した層を書く

親は、少なくとも次の層を候補として考え、「今回触る層」と「計測で除外済みの層」を書く。

```text
幾何 / 接触の候補と特徴 / 履歴 / 状態の表現 / 拘束の式 / 連立の解法 / 許容差 / 速度の再構成 / 速度段階 / 時間の離散化
```

親は、コードの差分が小さいことを第一の目的にしない。親が選ぶのは「最小の意味的な変更」である。実装員は、原因が時間の契約なら時間の契約を、位置の表現なら位置の表現を、接触の識別なら接触の識別を、解法の受理条件なら解法を直す。親は、別の層へ許容値や補正の状態を足して症状を相殺する案を、原因の層そのものを変えられない理由を説明できる場合だけ候補にする。

### 3. 反証: 本実装の前に、自分の案を壊す反例を最低3つ作る

親と実装員は、実装の案を思いついたら、コードを書く前に最低3つ、その案を壊す反例を作る。最低でも次の種類から選ぶ。

- 同じ現象を別の向き・別の姿勢にした場合
- 2つの参加者で誤差が逆符号になる場合(例: 同じ粗い中心に +0.3刻み と −0.3刻み)
- 静的世界との境界
- 世界を平行移動した場合
- 刻み幅・細分数・反復数・許容差を変えた場合
- CPUとGPU、または別のクレートの境界を通した場合

PR #97 の「+0.3刻み / −0.3刻み」の反例は、実装者の側で最初の衝突境界の案を実装する前に出せたものである。親と実装員は、反例がオーナーのレビューで初めて出る形にしない。

### 4. 一次計測: 仮説を表で確かめ、原因を確定または棄却する

親は、仮説の実装を探索のためにコードへ入れることを許す。ただし、親は仮説を細分ごとの表(位置のビット表現・補正・再構成した速度・乗数の合計など、一次の物理量)で確かめ、原因を確定または棄却してから次へ進む。「候補Dで消える」「量子化は(x,y)成分」の2つの仮説を、親は表で覆した。

新しい失敗を別のissueへ移してよいのは、次の3つが揃ったときだけである。(1)変更の前から同じ機構が在ったことの一次計測 (2)今回の変更がその機構を露出または増幅した経路 (3)直すべき責務が今回の変更箇所と別である説明。Issue #98 はこれを満たした。「1.06%なので別issueへ」の段階では満たしていなかった。

### 5. 設計裁定: 一次計測を材料に、採用する案を決めてから本実装へ進む

親は、次に当たる変更について、本実装の前に短い設計裁定を取る(巨大な設計書は要らない。症状・契約・責務層・候補・反証3件・一次計測だけでよい)。

- 数値表現を変える
- 時間の意味を変える
- 接触の履歴・乗数・残差などの寿命を変える
- 許容値・許容帯・履歴依存の判定を追加する
- CPUとGPU、またはクレートの境界で情報を落とす
- 粘着と滑走、休止と起床などの物理の状態遷移を変える

親と実装員は、調査用の実装と本番の候補を混ぜない。順序は、仮説の実装 → 一次計測 → 原因の確定または棄却 → 設計裁定 → 採用したものだけを本番のPRへ残す、である。実装員は、探索で有効だったというだけの機構を本番のPRの責務に抱き合わせない。

### 6. 本実装

実装員は、設計裁定で採用した案だけを実装する。親は、実装を `.claude/skills/実装ハーネス/SKILL.md` の手順で委譲し、検収を `.claude/skills/レビューハーネス/SKILL.md` で行う。

## 報告の形

親は、PRの完了報告に、試験の一覧より先に一次の物理量の因果を書く。

```text
変更前: どの一次量がどう壊れていたか
変更: どの意味を変えたか
変更後: 予測した一次量がどう変わったか
副作用: 他の保存量・分類・性能がどう変わったか
```

親は試験の一覧を最後に置く。PR #97 の動摩擦の後退で力積の収支まで追った報告が手本である。

## 副官との相談

親は、工程1・2・5(契約の書き出し・責務層の列挙・設計裁定の案)を `副官`(`.claude/agents/副官.md`)へ見せ、反論を受けてから進む。副官とは、親が判断を固める前に反論と代案を返す相談相手のことであり、実装も検収の合否の判定も行わない。
