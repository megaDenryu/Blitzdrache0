# スキルの書き方

AIはスキルを書くと、何でも番号付きの手順と確認項目にする。さらに、1回の失敗や成功の形をそのまま規則にし、文を長く積む。手順にされた判断は、手順に無い場面で判断できなくなる。

- 手順を書くのは、順序に意味があり、踏んだかどうかを確かめられる作業だけにしろ(ビルド・配置・検証の列、GitHub の操作)。
- 判断が要るもの(説明・命名・設計)は、手順でなく、AIの振る舞いにどういう問題があり、なぜ起きるかを書け。原因が分かれば、AIは手順に無い場面でも判断できる。
- 1回の事例から規則を作るな。その事例でたまたま効いた形(対比を使った、例を先に置いた)を、一般の規則にするな。
- 短く書け。要求が2行なら、スキルも数行でよい。
