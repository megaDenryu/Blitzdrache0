# 設計解釈マーカーの思想

AIは、意味の拘束を無視した、意味の分からない語彙をどんどん増やしていく。設計解釈マーカーは、それを防ぐための意味論の基盤である。型が設計上何であるかを印で宣言し、その印が守るべき性質を公理として置く。`M不変データ` の不変性は、その公理の1つである。

- マーカーの役目は、AIに気づかせることである。「これは不変にしないといけない。そして今後もそれに固定されていないといけない」と、型を書く・直すAIが思うために印がある。
- AIが実際に犯す間違いは、不変性という観点を持たず、不変にすべきものを不変にしないことである。印を付けたのに書き換える、という間違いは、いまのAIも人もしない。
- だから、印の違反を完全に機械で検知する仕組みは要らない。それを作ろうとすると、起きない間違いのために検査が膨れ上がる(PR #177 では約100ファイル・約5,600行に膨れた)。
- 現実に起きうるのは、印を付けた型の `impl` を別のファイルに書き、印を見ないまま書き換えることである。印が目に入らない場所に実装を書かせるな。印を付けた型の実装は、定義と同じファイルに置け。
- 新しい型を足すときは、それがどのマーカーの意味に当たるかを考えろ。どのマーカーにも当たらない型が増えるなら、その型が設計上何であるかを説明できていない。
