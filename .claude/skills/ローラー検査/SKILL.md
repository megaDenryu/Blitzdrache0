# ローラー検査

## これは何か

ローラー検査とは、リポジトリの全域を区画へ切り、区画ごとに観点別の検査員を走らせ、検査済みの範囲を台帳へ記録していく周回のことである。差分の検収(レビューハーネス)が「いま変えたもの」を見るのに対し、ローラー検査は「**誰も触らないまま残っているもの**」を見る。

制定の根拠はグローバルCLAUDE.mdの「日本語命名の受理条件」の運用節にある。「触るときに直す」は接触しないコードを永遠に残すため、待ち時間に検査員を未検査領域へ派遣し、結果を台帳へ記録する。

**台帳が完了を定義する。** 記録の無い検査は行っていないものとして扱う。記録先は `_doc/計画/検査の網羅台帳.md` である。

**検査員の報告は全文をファイルへ保存する。** 保存先は `_doc/検査報告/<領域>_<軸>_YYYY-MM-DD.md` である。台帳の1行には結果の要約しか入らず、是正の工事はその要約からは書けない。報告はサブエージェントの出力にしか存在せず、親のセッションが要約されるか閉じると失われる。2026-09-04に`blitz_app`の第1区画でこれが起きた。台帳に10個の概念の名前と5段の構成は残ったが、各概念が持つもの・見せるもの・見せないものの内訳と、工程20とフィールドの対応表は失われた。是正の工事(Issue #45)はその内訳を必要とするため、分解員を走らせ直すことになる。

## 差分の検収との違い

| | レビューハーネス(差分) | ローラー検査(全域) |
| --- | --- | --- |
| 見る対象 | `git diff` の範囲 | 区画に切った既存コードの現状 |
| 走る契機 | 委譲成果の検収のたび | 待ち時間、節目の定点、規約の制定直後 |
| 終わり方 | その差分を見終われば終わり | 台帳の全区画が埋まるまで終わらない |
| 記録 | 検収の報告に含める | 台帳へ1行(領域・検査日・時点・結果) |

## 対象のエージェント

**検査を担当するもの**(領域を指定すれば差分が無くても走る)。

| 観点 | 担当 | モデル | 1区画の重さ |
| --- | --- | --- | --- |
| 命名 | 命名チェック員 | haiku | 軽い |
| 構造 | 構造チェック員 | sonnet high | 重い |
| まとまりとつながり | 溶けた概念の分解員 | Opus 5 medium | **最も重い** |
| 孤立した実装 | 孤立実装チェック員 | sonnet low | 軽い |
| 契約の整合 | 契約整合チェック員 | sonnet low | 軽い |
| 行数と分割の質 | 行数と分割の質チェック員 | sonnet medium | 中 |
| テストの実効性 | テスト実効性チェック員 | sonnet high | 重い |
| 設計正本との整合 | 設計正本整合チェック員 | sonnet high | 重い |
| 文章 | 文章チェック員 | sonnet medium | 中 |

**補助**: 検証再実行員(sonnet low)。周回のあいだ1体だけ走らせ、検証の結果を親が受け取る。

**是正を担当するもの**(検査では使わない): リネーム員(命名の違反)、機械的置換員(判断の残っていない置換)、層ごとの実装員(構造・設計の是正)、実装員(横断する是正)。

**ローラーでは使わないもの**: レビュー員とそのFable版。総合の差分検収向けであり、全域では観点別に分けた方が速く、水増しも減る。

## 区画の切り方

**1区画は40ファイルを上限にする。** 台帳の実績が根拠である。30から45ファイルの区画では全数の直読が成立した一方、60ファイルの区画では検査員が「パターンの一貫性」を理由に20ファイルしか読まず、残り40ファイルが抜き取りのまま暫定になった。431ファイルを1区画として渡した回は、識別子の抽出だけが行われ直読は6ファイルにとどまった。

- 区画はディレクトリの境界で切る。責務がまとまっている単位ほど、検査員の判断が安定する
- 上限を超えるディレクトリは子のディレクトリで割る。割れないなら、ファイル名の並びで機械的に割ってよい(この場合は区画の名前へ「第n区画」と範囲を書く)
- **区画の名前と範囲は台帳へそのまま記録する。** 後から「どこまで見たか」を復元できる形にする

## 同じ区画へ複数体を走らせる3つの形

**形1: 観点の並列(常時こうする)**

同じ区画へ、違う観点の検査員を同時に走らせる。読み取り専任なので互いに競合しない。これが基本形である。

**形2: 区画の並列(スループットのため)**

同じ観点の検査員を、違う区画へ同時に走らせる。区画が独立なので競合しない。

**形3: 同じ観点の二重化(信頼度を測るため)**

**同じ区画・同じ観点へ2体を走らせ、結果を突き合わせる。** 目的は取りこぼしと甘い判定の検出である。台帳には、検査員が明文の違反を「モジュール名で文脈が明確」として合格にし、親裁定で違反へ補正した記録が複数ある。1体の判定は甘い方へ倒れる。

- **2体の結果の差が、その区画のその観点の信頼度である。** 差が大きい区画は、片方が読み飛ばしているか、判定基準の解釈が割れている。どちらであるかを親が現物で確かめる
- コストが倍になるため、全区画では行わない。**過去に暫定で終わった区画**と、**違反密度が高かった区画**(同じ観点で違反が10件を超えた区画)に限る
- 2体には**同じプロンプトを渡す**。違うプロンプトを渡すと、差が能力差なのか指示差なのか分からなくなる

## 並列の上限と競合の回避

- **読み取り専任は同時8体程度まで出してよい。** ファイルを書き換えないため競合しない。上限はレート制限で決まるので、失敗が出たら減らす
- **`cargo` を走らせるのは1体だけにする。** ビルドの排他ロックで待ちが出るため、検証は検証再実行員へ集約し、他の検査員には「検証は走らせず読み取りだけ」と指示する
- **親は周回のあいだ、対象の区画を触らない。** 検査中のファイルを親が編集すると、報告の行番号がずれる
- 是正は検査の周回が終わってから行う。検査と是正を同時に走らせない

## 読み飛ばしを検出する

検査員は、大きな区画を渡されると抜き取りで済ませ、それを報告に書かないことがある。**書かせる形にする。**

委譲プロンプトへ次を必ず書く。

- **「直読したファイル数」と「grepだけで済ませたファイル数」を報告の末尾に書け。** 区画のファイル数と一致しないなら、その旨を明記せよ
- **「パターンが一貫しているので残りは省略した」を認めない。** 省略するなら、省略した範囲と理由を書け

報告で直読数が区画の全数に満たないものは、台帳へ**「抜き取りの暫定」と明記して記録する**。暫定は完了と数えない。次の周回で優先的に再検査する。

## 検査済みは永久ではない

**規約の軸が増えたら、それ以前の検査は新しい軸で見ていない。** 台帳の命名検査には2026-08-09の記録があるが、2026-08-27に制定された分割の条文はその時点に存在しない。古い検査は、古い軸での検査である。

- 台帳へ記録するとき、**その時点で有効だった軸の一覧か、規約の版が分かる情報(コミット)を書く**
- 新しい軸を制定したら、**その軸については全域が未検査に戻る**。台帳のその軸の表を作り直すか、既存の行へ「この軸は未検査」と書く
- 周回の優先順位は次のとおりである
  1. 一度も検査していない領域
  2. 抜き取りの暫定で終わっている領域
  3. 検査が古く、その後に軸が増えている領域
  4. 違反密度が高かった領域(同じ形が再発しやすい)

## 是正の回し方

**検査と是正を混ぜない。** 検査員は修正しない。是正は別の担当が別のコミットで行う。

1. 検査の周回を終え、違反の一覧を親が受け取る
2. 親が指摘を吟味する(前提整合・実害・過剰防衛・二重管理リスクの4軸)。**検査員の判定をそのまま採用しない**。台帳には親裁定で補正した記録が複数ある
3. 採用した違反を、種類ごとに是正の担当へ回す
   - 日本語識別子の違反 → リネーム員(LSPの参照ベースの改名を第一手段にする)
   - 判断の残っていない置換・移動 → 機械的置換員
   - 構造・設計の是正 → 層ごとの実装員、横断するなら実装員
4. **是正は機能変更と別のコミットにする**
5. 是正が済んだら、台帳の結果の欄を更新する(「検出n件、mコミットで是正済み」の形)

## 周回の手順

1. **台帳を読む。** どの領域のどの軸が未検査か、暫定か、古いかを確認する
2. **区画を決める。** 上限40ファイル。区画の名前と範囲を書き出す
3. **観点を選ぶ。** その区画の性質に当たる観点だけを選ぶ(Rustのクレートに文章チェック員は要らない)
4. **並列で起動する。** 形1と形2を組み合わせる。同じ観点の二重化(形3)は、暫定の区画と違反密度の高い区画に限る
5. **報告を受け取り、直読数を確認する。** 全数に満たないものは暫定として扱う
6. **親が吟味し、違反を確定する**
7. **報告の全文を保存し、台帳へ記録する。** 保存先は `_doc/検査報告/<領域>_<軸>_YYYY-MM-DD.md` である。台帳には領域・検査日・台帳更新日・時点のコミット・結果の要約と、保存した報告への相対パスを書く。暫定ならその旨を明記する
8. **是正を別コミットで回す**

## 違反のサイン(この周回自体が形骸化している兆候)

- 台帳に「暫定」の行が増え続け、減らない
- 同じ領域が何周も未検査のまま残っている
- 報告に直読数が書かれていない
- 検査員の指摘をそのまま全部採用している(親の吟味が働いていない)
- 是正が検査と同じコミットに混ざっている
- 新しい軸を制定したのに、台帳のその軸の表が無い
