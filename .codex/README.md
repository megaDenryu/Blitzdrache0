# Codex / GPT-6 Astra のハーネス

この文書は、GPT-6 Astraを使うCodexの調査・実装・検証・引き継ぎの手順を管理する。ハーネスとは、AIが作業を進めるための指示・道具・検証・引き継ぎの仕組みのことである。

## 配置と適用範囲

| 場所 | 責務 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | Codexが読むリポジトリの入口である。 |
| [.codex/README.md](README.md) | Codex固有の運用を保持する。入口がこの文書の読了を要求する。 |
| [CLAUDE.md](../CLAUDE.md) と [.claude/](../.claude/) | 既存の共通規約とClaude固有の運用を保持する。 |
| [_doc/](../_doc/) | 両方の実行環境が参照する設計・計画・用語・記録を保持する。 |

Codexはこの文書を、ユーザーが求めた専用ハーネスとして `.codex/` に置く。設計文書一般の置き場は従来どおり `_doc/` とする。Codexは [.agents/](../.agents/) にある既存の連携設定を変更しない。

OpenAIの[AGENTS.mdの仕様](https://learn.chatgpt.com/docs/agent-configuration/agents-md)では、Codexはプロジェクトのルートから作業ディレクトリまでの指示を読み込む。この文書単体には自動読み込みを期待せず、ルートの入口から参照する。新しいセッションが更新後の入口を読み込むことと、現在のセッションが手動で文書を読むことを区別する。

この構成はモデル選択を変更しない。利用者はCodex側でGPT-6 Astraを選択する。Codexは未確認のモデル識別子・推論設定・権限設定を設定ファイルへ固定しない。モデル固有の性能や費用の優劣は、実測なしに運用の根拠にしない。

## 調査から実装まで

1. 親は `AGENTS.md` が指定する規約を読み、現在のブランチと未コミット差分を確認する。
2. 親は要求を完了条件へ分解し、関係する設計正本・呼び出し元・型・状態遷移・依存の配線を読む。
3. 親は変更リスクを一文で書く。複数の工程がある場合、親は依存する工程を先に置く。
4. 親は既存規約が要求する設計相談を読み取り専任の担当へ依頼する。担当は反例・規約との衝突・代案を返し、親が判断する。担当は実装しない。
5. 親は対象範囲の実装を行い、または独立した担当範囲へ委譲する。親は作業を途中の計画提示だけで終えない。

物理基盤を変更する場合、親は [.claude/skills/物理基盤の工程/SKILL.md](../.claude/skills/物理基盤の工程/SKILL.md) の契約・責務層・反証・一次計測・設計裁定・本実装の順序を維持する。Codexはモデルの変更を設計裁定の省略理由にしない。

## 委譲の実行方法

親は実行環境にある協働ツールを使い、Claude用の役割定義を自動登録済みのCodexエージェントと見なさない。親はモデルを原則として現在のセッションから継承し、他モデルへの変更は利用可能な設定と上位指示に従う。

親は委譲先へ、背景・設計正本・編集可能なファイル・禁止する編集範囲・完了条件・検証の担当・コミットの可否を渡す。親は同じファイルを複数の担当へ編集させず、型契約を使う実装は契約確定後に始める。読み取り専任の相談役は変更権限を持たない。

親は進行中の差分を確認し、根拠のある指摘を担当へ送る。親は担当の完了報告だけで合格とせず、現物の差分と検証ログを確認する。親は中断した担当の成果を、現在の差分とコミットから確かめて引き継ぐ。

## 検証の責任と実行場所

親は検証の範囲と結果に責任を持つ。複数の実装担当がいる場合、親は検証を1担当へ集約して直列に実行する。短い作業では親自身が検証を行う。Codexは待機だけの担当を形式的に常駐させない。

ビルド担当は既存の専用チェックアウト `C:/devs/Blitzdrache0_build` を使う。担当は利用中の作業を確認してから検証対象の先端を揃え、作業ディレクトリをそのチェックアウトに指定する。担当は他セッションの未コミット変更を消さず、専用チェックアウトが使用中なら並行して切り替えない。担当は作業ツリーごとにビルドの出力先を増やさない。

コードの標準検証は、専用チェックアウトを作業ディレクトリとする `cargo xtask verify` である。担当は実行前に入口の現行実装を読み、実画面操作を含む検査の許可範囲を確認する。親は終了コードと道具が出力するログを読み、検証対象のコミットと合わせて判断する。検証対象と手元の差分が違う場合、親は検証済みと報告しない。

文書のみを変更した場合、親は文書の内容・参照先の実在・READMEの索引登録・差分の空白エラーを確認する。親はエンジン全体のビルドやGUI操作を文書変更の検証として追加しない。

## 自己レビューと引き継ぎ

親は設計、規約、呼び出し側の接続、検証、差分全件を確認する。指摘には対象と根拠を付け、親は推測だけの問題を確定事項にしない。文書の参照関係も呼び出し側の接続として確認する。

親は完了報告に、変更内容・実行した検証・未確認事項を記載する。後続の担当へ作業が残る場合、親は目的、現在の完了条件、変更したファイル、対象の先端、実行した検証と結果、未完了事項、次の操作を記録する。親は進行中の個別タスクの状態を、この恒久的な運用文書へ書き込まない。

- [文章規範](../.claude/skills/doc-writing/SKILL.md)は、命名とは別に文章の受理条件を定めている。

共通規約の正本は現時点でClaude用の場所にも残っている。この構成は実行手順を分離するものであり、規約の保存先まで完全に独立させる移動ではない。Codexは正本の変更を専用文書へ複製せず、共通規約の中立な場所への移設は参照元全体を調査する別の変更として扱う。
