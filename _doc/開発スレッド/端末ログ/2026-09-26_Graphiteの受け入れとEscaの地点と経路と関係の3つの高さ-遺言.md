- **Cargo.lock の `[[patch.unused]] sengen_egui` の4行**は、このマシンの cargo の設定と IDE の rust-analyzer が書き足す。コミットに入れない(`git checkout -- Cargo.lock` で捨てる)
- **ビルド専用のチェックアウト `C:/devs/Blitzdrache0_build` は本体と同じリポジトリの作業ツリー**なので、コミットは fetch せず `git -C C:/devs/Blitzdrache0_build checkout --detach <ハッシュ>` で切り替える。短いハッシュでの fetch は失敗する
- **graphite-check は、入れた生成器が Cargo.lock の固定の版から入っているかを `~/.cargo/.crates.toml` で確かめる。** 手元のパスから入れた生成器は落ちる。入れ直しは `cargo install --git https://github.com/megaDenryu/Graphite --rev 8d264e19bd7c44c54d45316a17c10aa03cb9d9e3 graphite-cli --force`
- **Graphite の生成は実装員が走らせない規約**なので、親が `(cd <クレート> && cargo graphite generate)` で作り、生成物だけを `git commit -- <パス>` でコミットした

## 6. 学びと注意

- **対話は1問ずつ、具体例で。** オーナーは「まとめて言われてもわからん」「何言ってるかあんまわからない」と2度言った。層の話は、ボードゲームの盤面や崖崩れの峠道のような具体の場面と表で説明すると通った(逐語の対話10〜14のあたり)
- **基盤にすでに正しい仕組みがあるなら、別案として並べない。** 「時刻の到来を出来事として扱う案2」を並べたところ、イベント反応(設計オントロジー3.5.7)という既存の正しい実装方法があり、オーナーに「ややこしいからいちいち案2として出さないで」と言われた
- **基盤の契約の話に、ドメインの規模を理由に「まだ要りません」と答えない。** `M遷移関数` の状態の受け渡しの費用を聞かれて Esca の規模で答え、「基盤を作ってる話やのになんでドメインの話してるねンボケ」と叱られた。基盤の問いには基盤の契約として答える
- **オーナーの趣旨: マーカーは形式の依存ではない意味(分類)を与えるもの。** 「下位型である」を関係の線にしていたのは層の混同だった。関係には仕様・設計・プリミティブの3つの高さがあり、上の高さは下の高さの組み合わせで定義される。最終的に書きたいのは仕様の関係(町Aと町Bはつながっている)。これが #193 になった(逐語の「設計関係グラフてなんだっけ」から「あってそう」まで)
- **Graphite はゲームのロジックに使う。エンジンの内側の基盤には積極的に使わない**(オーナーの方針)。Graphite は並べて決まる関係を書く道具で、規則で決まる関係(チェスの駒の動き)と遷移は型と関数で書く
- **副官の反論は毎回効いた。** G1 の型の契約を実装員に任せる前に止められた(`M不変データ` と Graphite の Clone の食い違い)。G2 では親の推奨(観測として渡す)が設計オントロジーの定義と逆だと正された
- **総合レビュー員は差分の外の欠陥を捕まえる。** G2 の「境目の外に着いて永久に動けなくなる」は再現の試験で実在した。検査の指摘は「再現してから直す」を委譲プロンプトに書くと確実になった
- 実装員が本体のチェックアウトで誤って `cargo fmt --all` を走らせた事故が1回あった。委譲プロンプトに `--manifest-path` を明記してから再発していない
