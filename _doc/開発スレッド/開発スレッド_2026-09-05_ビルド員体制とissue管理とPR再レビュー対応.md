## 葉: どの検査を並列にできるか

| 検査 | 並列化 | 理由 |
| --- | --- | --- |
| 命名 / 構造 / 行数と分割の質 | **コミットごとに走らせる** | 1コミットの差分だけで判定でき、後の段に依存しない |
| 文章(文書の差分) | コミットごと | 同上 |
| 契約整合 / 孤立実装 | 最後の段の後 | 「配線されていない」は全部が揃うまで判定できない |
| テスト実効性 / 設計正本整合 | 最後の段の後 | 試験の全体像と正本の対応表が要る |
| 検証再実行(verify) | 最後の段の後 | 実装員自身が回す |

### 6. 学びと注意

- **並走の検査をコミット単位に限定してはならない。** 起点は時間と差分の量。途中の状態の検査を受け入れる。経緯は逐語の「コミットごとにすれば問題にならないはおかしい」

- **記録を書くのは道具であり、エージェントではない。最初から恒久の形を作る。** 経緯は「ビルド員が書き出すの?」「ちゃんと考えてくれよ」「なんで最初から恒久の形にしないねん」

- **正本の時間意味と実装の頻度を一致させる。** 「60細分」と書いた値が実装では60基本刻みだった。判断18(単位)と判断19(工程の図)の食い違いは、Claudeの追加計測で露出した。契約は物理時間(0.125秒)で書き、個数は導出の結果にする

- **積み直しで消えた台帳の更新は、新しい様式へ写す作業として親が機械的に行ってよい**(受理後の機械的な競合解消は再裁定不要、とオーナーが明示した)
