1. 全体レイヤー 2. フレーム構成 3. GPU資源束縛 4. シミュレーション 5. ストリーミング 6. データとツール 7. 機械的強制

01クレートのレイヤー構造

依存方向は Cargo ワークスペースのクレート分割でコンパイル時強制。unsafe と ash 型は blitz_render の実装内部へ封じ込め、公開APIには安全な日本語語彙の型だけを出す。

021フレームの実行順序

blitz_engine が「フレーム段階」の列を宣言し（フレーム構成）、blitz_render が各段階を1つ以上のGPUパスへ展開する。依存は宣言順のまま実行し、バリアはレンダーグラフが入出力宣言から自動導出する。

03GPU資源束縛の分離

scene系パイプラインのレイアウトは更新頻度で4つのディスクリプタセットへ分ける。材質テクスチャは索引表（bindless）。set 0・set 2・set 3 はパス先頭で1回だけ結び、描画発行ごとに結ぶのは set 1 だけ。

04シミュレーションと介入

切断線は「表現はドメイン、数学は基盤」。プレイヤーイベントは型付きの「介入」として GPU シミュレーションへ流し込み、結果バッファは描画パスとゼロコピー共有する。

05ストリーミング（エンジンフェーズ2の柱）

世界をチャンク分割し、プレイヤー位置に応じて非同期ロード/アンロード。RAM・VRAM の予算管理と、描画はカメラ相対レンダリング（f32精度の崩壊を回避）。

06アセットの流れとツールの入口

ソースアセット（glTF・画像・高さ格子）はオフラインで検証・変換され、版付きの実行時形式へ落とされる。エンジンは実行時に汎用パースをしない（理論値志向）。

07機械的強制と検証列

規約の多くはコードレビューでなく機械検査で強制する。検証列が通らないコードはコミットしない。

ワークスペース lint（緩和する変更は禁止）

denyunwrap_used / expect_used / as_conversions — テストモジュールでの局所 allow のみ可
unsafeblitz_render 実装内部のみ。他クレートは #![forbid(unsafe_code)]。unsafe 直前には「安全性:」コメント必須
型安全性数値の as キャスト禁止（From/TryFrom）、失敗は層ごとの thiserror 型付きエラーを ? で伝播
命名ドメイン層は日本語命名・略語禁止・フルスペル。数学DDD は幻影型で単位と座標系を区別
