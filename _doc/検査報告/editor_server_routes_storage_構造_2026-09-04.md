- 検査員: 構造チェック員(sonnet・effort high)
- 対象: `crates/editor_server/src/routes/`(25ファイル)と `crates/editor_server/src/storage/`(10ファイル)
- 検査日: 2026-09-04
- 時点のコミット: `271e8530`
- 直読: 35 / 35(grepだけで済ませたファイル 0)
- 作業ツリーの汚染: **無し**

この領域の構造検査は2026-08-19が最後であり、その後に2026-08-26「Rustの書き方の選択」、2026-09-04「処理側に所有すべき状態が無いなら処理側の型を作らない」「モジュールに分けても依存の向きは決まらない」「常に揃って渡される引数の組」の条文が増えている。本検査はそれらの新しい軸を含む。

## 親の吟味の結果

**検査員は違反10件を報告したが、親が吟味して1件を採用し、9件を却下した。** 却下の理由と、却下の過程で見えたより重い指摘を下に書く。

## 採用した違反: モジュールの外へ依存を運ばせている

`crates/editor_server/src/routes/world_layout_lookup.rs:13`

```rust
pub(super) fn 保存済み区画割りを読む(状態: &サーバー状態) -> Result<世界の区画割り, Box<Response>> {
    let 構造 = 状態.保管庫().大域世界の構造を読む().map_err(...)?;
    ...
}
```

**破っている条文**: グローバルCLAUDE.md「サービスの依存保持とコールバックの限定」条1の「判定単位は公開の呼び出し境界であり、モジュール外の呼び出し側に依存を運ばせない」。

`pub(super)` でモジュールの境界を越えて公開され、3つの兄弟のモジュールが `状態` を持参して呼んでいる。

- `routes/chunk_heightmap_put.rs:12,32`
- `routes/chunk_splat_weights_put.rs:11,31`
- `routes/world_heightmap_put.rs:7,22`

条1が認める例外は「サービス内部のモジュール私有ヘルパー」に限られ、それは「親のサービス型が依存を保持している限り」である。`world_layout_lookup` は `サーバー状態` 自身のモジュールではないため、この例外に当たらない。

**是正の方向**: `サーバー状態` のメソッドへ昇格し、`状態.保存済み区画割りを読む()` の形で呼ぶ。

## 却下した違反9件

検査員は次の9つの私有関数を、`サーバー状態` を外部の引数に取る形として違反に挙げた。

1. `routes/world_structure_put.rs:16` `fn データを検証して保存する(状態: &サーバー状態, 本文: &[u8])`
2. `routes/material_board_put.rs:18` `fn データを検証して保存する(...)`
3. `routes/music_put.rs:24` `fn 検証して保存する(...)`
4. `routes/world_heightmap_put.rs:21` `fn 検証して保存する(...)`
5. `routes/chunk_structure_put.rs:26` `fn データを検証して保存する(...)` と `:46` `fn 粗マスの一辺を区画割りと突き合わせる(...)`
6. `routes/building_grid_put.rs:25` `fn 検査して保存する(...)`
7. `routes/source_asset_export_post.rs:44` `fn ソースアセットの書き出しとベイクを実行する(...)`
8. `routes/chunk_heightmap_put.rs:31` `fn 検証して保存する(...)`
9. `routes/chunk_splat_weights_put.rs:30` `fn 検証して保存する(...)`

**親が現物を確かめたところ、9本すべてに `pub` が付いていない。** つまり定義したモジュールの中でしか見えないモジュール私有の関数である。

CLAUDE.mdの「サービスの依存保持とコールバックの限定」条1はこう定める。

> **判定単位は公開の呼び出し境界であり、モジュール外の呼び出し側に依存を運ばせない。** サービス内部のモジュール私有ヘルパーが依存を引数で受けるのは、親のサービス型が依存を保持している限り工程分割として許す。

`サーバー状態` は依存(保管庫・リポジトリルート・建物の格子の保存係)を構築時に受け取り保持している。したがってこの9本は条文どおり合法である。**却下する。**

## 却下の過程で見えた、より重い指摘

9本を却下する過程で、検査員が言わなかったものが見えた。

**`サーバー状態` が外へ見せるメソッドは7つあり、その全部が中身をそのまま返す口である。**

`crates/editor_server/src/server_state.rs` より。

| 行 | メソッド | 種別 |
| --- | --- | --- |
| 52 | `保管庫()` | 取り出す口 |
| 56 | `プロジェクト情報()` | 取り出す口 |
| 60 | `静的配信ディレクトリ()` | 取り出す口 |
| 66 | `リポジトリルート()` | 取り出す口 |
| 70 | `ソースアセット書き出しの排他権()` | 取り出す口 |
| 75 | `建物の格子の保存係を借りる()` | 取り出す口(施錠つき) |
| 86 | `建物外形カタログの写しを取る()` | 取り出す口(写しつき) |

命令も判断も1つも無い。

グローバルCLAUDE.md「設計」はこう定める。

> **判定は、束ねた型が外へ見せるメソッドの名前を全部列挙して行う。列挙が中身をそのまま返す口だけなら入れ物であり、1つでも命令や判断があるなら概念である。**

**`サーバー状態` は入れ物である。** そして「検証して保存する」という判断は、その外側に9本の私有の自由関数として散っている。1本ずつは合法だが、同じ形が9回複製された時点で、これは形の問題である。

新しい保存の経路を足すたびに、同じ形の私有関数が1本増える。`サーバー状態` 自身は「貸すだけ」の薄い顔をしたまま、実際の業務のロジックの所在が型の定義から追えない。

**是正の方向**: 保存の経路が持つ不変条件(区画割りとの整合・カタログとの整合・識別子の一致)を `サーバー状態` のメソッドか、依存を保持する専用の操作サービスへ昇格する。ただしこれは規約違反ではないため、着手の判断は別に要る。

## 境界事例(違反に数えない)

**1. 経路パラメータの型化がPUTとGETで非対称である**

`routes/building_grid_put.rs:27` と `music_put.rs:32` は、URLの経路の識別子を `&str` のまま本文側のドメイン型の `.綴り()` と生の文字列で比較している。一方 `routes/building_grid_get.rs:8` は経路のパラメータを即座に `建物定義ID::生成する` で型化している。プリミティブ執着の疑いはあるが、比較の結果自体は正しく機能する(不正な綴りは自然に不一致として拒まれる)ため、違反でなく設計上の非対称として記録する。

**2. 保存係から2つの値を同じ地点で取り出している**

`routes/source_asset_export_post.rs:64-68` が `保存係.現在のカタログ()` と `保存係.格子の台帳()` をこの1つの呼び出し地点でだけ組にして取り出し、別々の引数として渡している。「常に揃って渡される引数の組」の疑いがあるが、この対が他の呼び出し箇所でも常に揃って現れるかは検査の対象範囲外を読まないと確定できないため保留する。

## 違反なしと判定した領域

- **`storage/file_repository/` の各ファイルが `&編集データディレクトリ` を引数に取る形**は、`file_repository/mod.rs` の冒頭コメントが明記する「切り出しの根拠義務」第3項(触れるフィールドが限定された操作の分離)に該当し、`ファイル保管庫` という親のサービス型が依存を保持した上での工程の分割であるため違反としない。`編集データディレクトリ` 自体は役割を持つパス型として自分の配置を知っており、プリミティブ執着にも当たらない
- **`json_io.rs` の各関数が `&Path` を引数に取る形**は、`Path` が「構築時に受け取り複数回の呼び出しをまたいで保持し続ける依存」ではなく毎回渡される値であること、および「切り出しの根拠義務」第5項に該当することから違反としない
- **`chunk_heightmap_get.rs` 等の `Path((x, z)): Path<(i32, i32)>`** は、axumの抽出子が要求する境界の形であり、受け取った直後に `チャンク座標::生成する(x, z)` へ変換しているためプリミティブ執着の違反としない
- **`&mut` の連鎖・同時にSomeとNoneになるOption群・処理側に所有すべき状態が無いstruct・マジック値の密輸・長い無名クロージャ**: 全ファイルの直読と横断の確認の結果、該当する形は1件も見つからなかった。`spawn_blocking` へ渡す無名クロージャはすべて名前付きの関数への1行の委譲であり許容の範囲内、`要求本体` と `応答本体` はserdeのデータ運搬用の型であり無意味なサービスオブジェクトではない
