## 違反1: 主語のある純粋な変換が自由関数になっている

`crates/blitz_sim/src/rigid_body/kinematic_velocity.rs:18-38`(検査時点で未追跡)

```rust
pub fn 運動学的剛体の速度を導出する(
    現在の配置: &配置,
    次の配置: &配置,
    基本刻み: 秒,
) -> Result<運動状態, 運動種別の遷移エラー>
```

**破っている条文**: グローバルCLAUDE.md「Rustの書き方の選択」条2。

**何が違反か**: `現在の配置` と `次の配置` は前後の役割を持つ非対称な入力であり(対等な計算ではない)、自由関数の許容条件の(a)入力同士が対等・(b)主語が一意に決まらない工程のどちらにも該当しない。

同じクレートの `rigid_xpbd/previous_state.rs:39` の `前の状態::確定した配置から速度を再構成する(&self, 確定: &配置, 刻み幅: 刻み幅)` が、全く同型の計算(前後の配置から速度を再構成する)を正しくメソッドにしている。**こちらだけが自由関数になっており、理由の記述も無い。**

**実害**: 同型の計算が一方はメソッド・一方は自由関数という一貫性の欠如を生み、後続の実装が「配置がらみの計算は自由関数でよい」と誤って学ぶ。呼び出し側(`ledger_transition.rs:56`)は `運動学的剛体の速度を導出する(剛体.配置(), &次の配置, 基本刻み)` と書いており、`剛体.配置().運動学的速度を導出する(&次の配置, 基本刻み)` のような自然な読みの順にできない。加えてこの関数は `lib.rs:45` から公開されており、公開の呼び出し境界に当たる。

**是正の方向**: `配置` 型へ `運動学的速度を導出する(&self, 次の配置: &配置, 基本刻み: 秒)` として移す。

## 違反2: 角度が型を剥がされて公開されている

`crates/blitz_sim/src/rigid_body/kinematic_velocity.rs:15,29-34` と `crates/blitz_sim/src/rigid_body/transition_error.rs:12-13`(どちらも検査時点で未追跡)

```rust
pub const 運動学的回転量の上限: f32 = FRAC_PI_2;
...
let 回転量 = 回転ベクトル.長さ().値();
if 回転量 > 運動学的回転量の上限 { ... }
...
回転量が上限を超えている { 回転量: f32, 上限: f32 },
```

**破っている条文**: グローバルCLAUDE.md「数学DDD」と「プリミティブ執着禁止はパス・テキスト・名前にも適用する」。

**何が違反か**: `回転ベクトル.長さ()` は既に型付きの `ラジアン` を返す(`blitz_math/src/frame/rotation_vector.rs` が `三成分の量を定義する!(回転ベクトル, ラジアン)` で宣言し、`vector_quantity.rs:42-44` の `長さ()` が `ラジアン` を返す)。にもかかわらずこのファイルは `.値()` で即座に生の `f32` へ剥がし、生の `f32` の定数と比較している。エラー型の枝も生の `f32` のフィールドである。

**証拠**: 試験の側(`kinematic_velocity_tests.rs:20`)が `ラジアン::生成する(運動学的回転量の上限 + 0.05)` と、定数をわざわざ `ラジアン` へ包み直している。**型があるのに剥がし、使う側で包み直している。**

**実害**: 角度の次元が公開API(`mod.rs:59` と `lib.rs:45` で再公開)から失われ、度とラジアンの取り違えや別の角度量との混同を型が検出できない。

**是正の方向**: `運動学的回転量の上限` を `ラジアン` 型の定数にし、`回転ベクトル.長さ()` をそのまま比較する。エラー型のフィールドも `ラジアン` へ。

## 境界事例(違反に数えない)

**a. `rigid_xpbd/reference_test_fixtures.rs:87`**

```rust
pub(super) fn 剛体を参照する(参照計算: &剛体の参照計算, 識別子: 剛体の識別子) -> &剛体
```

所有者を外部の引数に取る形そのものである。ただし `#[cfg(test)]` 配下からのみ参照される `pub(super)` の試験の補助関数であり、「サービスの依存保持とコールバックの限定」条1が明示する判定の単位である「公開の呼び出し境界」には当たらない。判断が割れる理由は、規約の文言の上では該当し得るが、適用の趣旨が主に想定するのは本番の公開境界であるためである。

**b. 同じファイル `:64`** の `動的剛体を登録する(台帳: &mut 剛体の台帳, 配置: 配置, 質量特性: 質量特性)` も同型であり、aと同じ理由で境界事例とする。

**c. `rigid_body/ledger.rs:67-69`** の `剛体の識別子から索引の識別子へ写す(識別子: 剛体の識別子)` は、`impl 剛体の台帳` の中にありながら `self` を一切使わず、自然な主語は `剛体の識別子` である。ただし直後の逆方向の変換(台帳の参照が要る)と対で「判断23」のコメントに沿って意図的に並べて置かれており、文書の上での対応関係を優先した配置とも読める。優先度の低い境界事例とする。

## 合格として確認した範囲

- **自由関数の許容条件**: 上記2件と境界事例a・bを除き、全ファイルの自由関数は試験用フィクスチャの純粋なコンストラクタの補助(`位置を作る`・`角速度を作る` 等)のみであり、依存を持参して仕事をする自由関数は無い
- **所有者を外部引数にした静的関数**: 境界事例a・b・c以外に該当なし。本番コードの `impl` はすべて `&self` と `&mut self` を正しく使う
- **プリミティブ執着によるマップのキー化**: `剛体の識別子` はu32を隠したnewtypeのまま内部でのみ添字を使い、外部への露出は `値()`(GPU境界向けと明記あり)のみ。座標・速度・慣性等はすべて `blitz_math` の単位型で統一されている
- **`&mut 親型` の自由関数の連鎖**: 本番コードには存在しない
- **常に揃って渡される引数の組**: `剛体の拘束の一覧`(4つのバッチをまとめた構造体)・`一刻みの作用の蓄積器` 等、共に生まれ共に消える値は既にまとめられている
- **同時にSomeとNoneになる複数のOption**: `Option` の使用は `body_kind.rs` の1箇所のみで単独。該当なし
- **処理側に所有すべき状態が無いstruct**: `細分の予測器`・`点の細分の状態`・`細分の中の剛体` はいずれも継続する状態(刻み幅・重力・前の位置・質量特性等)を実際に所有しており、名前空間の代わりのstructは無い
- **無名クロージャとセッション型の欠如**: コールバックを渡す箇所は無く、1回きりの括り(細分の反復、工程1から3)はすべてメソッドの列で表現されている
