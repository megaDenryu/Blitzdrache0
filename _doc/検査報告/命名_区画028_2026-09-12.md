### 1. 識別子への英字(ASCII)混入 — 軸名をX・Zの1文字で表している

`crates/blitz_asset_compiler/src/loader/contract/archetype_ground_origin_scan.rs:16-17,24-25,32-33,53-54`

```
enum 原点に乗ることを見る成分 {
    底面の高さ,
    X軸方向の中心,
    Z軸方向の中心,
}
```

- 識別子: `X軸方向の中心`、`Z軸方向の中心`(および同ファイル内の呼び出し `箱.x軸方向の中心の原点からのずれ()`、`箱.z軸方向の中心の原点からのずれ()`。この2メソッド自体の宣言は`mesh_bounds.rs`にあり本区画の外だが、呼び出し名が本区画に現れる)
- 落ちた条件: 呼称と語の選択(全プロジェクト共通CLAUDE.md)の「識別子への英字混入禁止」、日本語命名の質
- なぜ読めないか: `X`・`Z`という英字1文字がそのまま識別子に混じっている。同じリポジトリの`_doc/計画/ユビキタス言語.md`は「クラスタ格子のセル添字」「クラスタ格子の分割数」等で同じ3軸の概念を一貫して「横・縦・奥行き」という完全な日本語の語で表しており、`Y軸`のような英字表記は「天頂軸(ワールドのY軸)」のように括弧書きの補足としてしか出てこない。この枝だけがX・Zという英字を識別子の主要部に採用しており、既存の日本語呼称の慣習とも整合しない
- 改名の素案: glTFはY-upであるため、地面に平行な2軸は横方向・奥行き方向に対応する。`横方向の中心`・`奥行き方向の中心`(呼び出し先のメソッド名も揃えて改める)

- 落ちた条件: 受理条件7(直訳の検出質問)、日本語命名の質(英語の頭字語・省略語を日本語の中に混ぜない)

- 改名の素案: `バイナリチャンク種別`

### A. `材質スロットの参照`という名前が実体(番号+代表プリミティブの組)を言い切れているか

`crates/blitz_asset_compiler/src/loader/contract/slot_materials.rs:13,18`

```
pub(super) struct 材質スロットの参照<'文書> {
    pub(super) 番号: u32,
    pub(super) プリミティブ: gltf::Primitive<'文書>,
}
```

- 落ちた可能性のある条件: 受理条件1(受理テスト)
- 理由: 名前だけを読むと「材質スロットへの参照」(スロットを指すポインタ的な何か)に見えるが、実体は「スロット番号」と「そのスロットを最初に参照したプリミティブ」の組である。型定義直前のコメントで補われて初めて読めるため、名前単独では実体を言い切れていない疑いがある
- 改名の素案(参考): `材質スロットと代表プリミティブ`
