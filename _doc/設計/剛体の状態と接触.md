# 剛体の状態と接触

変形しない動的物体(剛体)が何を状態として持ち、どう時間発展し、世界の形や他の剛体と触れたときどう運動するかの設計正本である。Issue #7「物理基盤: 剛体の状態・運動・接触解法」のオーナー裁定(2026-08-28の設計ノート19節と裁定候補18項、2026-09-01の接触解法の要求10項・XPBD共通拘束基盤へ載せる具体契約12項・実装境界の追記)を正本化し、Issue #5の横断裁定(2026-09-01。#7〜#11の拘束数学をXPBD中心へ統一する)とIssue #33の実装ロードマップ(子IssueはIssue #39・#40・#41・#43)に接続する。数理契約の候補と根拠の全文はIssue #7の裁定材料コメント(2026-08-28)にある。

本文書は `_doc/設計/XPBD共通拘束基盤.md` の上に載り、`_doc/設計/世界の形と衝突基盤.md` を消費する。拘束の数学(拘束違反・勾配・コンプライアンス・ラグランジュ乗数・刻み幅)と一刻みの工程の順序はXPBD共通拘束基盤が正本であり、本文書はそれを剛体へ適用したときに剛体の側で決まる事項だけを持つ。接触点集合・連続衝突・動く形の空間索引の幾何の契約は世界の形と衝突基盤が正本であり、本文書はそれをどう受け取りどう使うかだけを持つ。

用語は `_doc/計画/ユビキタス言語.md`「XPBD共通拘束基盤の語彙」「世界の形と衝突の語彙」「時間の規律の語彙」に従う。本文書が新しく導入する語は「用語」の節に定義し、制定時にユビキタス言語へ「剛体の語彙」として登録する。

## 目的

Issue #7が成立させたい現象は、箱が落ちて床に止まる・球が転がる・坂の上で静止または滑落する・箱を複数積める・物体の端を押すと回転する・重い物と軽い物の衝突結果が異なる・破片が大量に飛んで再衝突する、の7つである。本文書の目的は3つである。

1. 剛体という存在が持つ状態(配置・運動状態・質量特性・実行状態・運動種別)を、特殊値を使わない型として決め、ゲーム側が「力・衝撃・状態・材質」の意味だけで扱える公開面を決める
2. 剛体の姿勢自由度をXPBD共通拘束基盤の反復へ参加させる数学(予測・補正・速度の再構成)を、CPUの参照計算が持つ正典として決める
3. 世界の形と衝突基盤が返す幾何学的事実(接触点集合・接触の特徴の識別・初回接触時刻)を剛体の運動へ写す接触解法(非貫通・静止摩擦・動摩擦・反発・時間継続・接触島・休止)を決める

本文書は「箱」「車」「破片」というゲーム上の物体のAPIを定めない(Issue #7の非目標)。関節と駆動はIssue #8(実装はIssue #41)、破壊による構成の変化はIssue #16、質量特性と衝突形状の制作時の生成はIssue #19、キャラクターの移動の意味付けはIssue #3が持つ。

## 用語

本文書が新しく導入する語である。制定時にユビキタス言語へ「剛体の語彙」として登録する。以下の判断はこれらの語を定義済みとして使う。

- **剛体**とは、変形しない1つの動的物体のことである。識別子・配置・質量特性・運動種別・実行状態を持つ
- **運動種別**とは、剛体の運動を誰が決めるかの区別のことである。静的(物理計算中に配置が変わらない)・運動学的(外部が配置を決め、接触には速度を持つ物体として参加する)・動的(力・衝撃・接触・拘束で物理が運動を決める)の3枝であり、枝ごとに持つ状態が違う
- **配置**とは、剛体の重心の世界位置と姿勢の組のことである。動的剛体の物理位置の正本は重心である
- **姿勢**とは、剛体の重心局所座標からワールド座標への回転を表す単位四元数(3次元の回転を長さ1の4つの数で表す)の型のことである。生成が長さを検証し、演算の戻り値の生成が正規化を行う
- **質量特性**とは、質量・物体原点から見た重心・重心まわりの慣性(主慣性と主軸)の組のことである。衝突形状の属性ではなく剛体が別に持つ
- **主慣性と主軸**とは、重心まわりの慣性を対角化したときの3つの正の固有値と、その固有ベクトルが張る座標系の回転のことである。生成が正値と三角不等式を検査する
- **ジャイロ項**とは、剛体の角運動量が角速度と共に回転することで生じる角運動方程式の非線形な項 −ω × (I ω) のことである。外から回転力を加えなくても角速度の向きを変える
- **一刻みの作用の蓄積器**とは、動的剛体が1つの物理刻みの間だけ受け取る合力・合回転力・衝撃・回転衝撃の和のことである。工程2で取り出されて空になる
- **一般化逆質量**とは、剛体上の点に単位ベクトルの向きで作用する拘束について、逆質量に腕と向きの外積を逆慣性で挟んだ回転の寄与を足した量のことである。単位は毎キログラムであり、点自由度の逆質量と同じ式に載る
- **剛体接触拘束**とは、接触点集合の1点を剛体の運動へ写した非貫通の片側拘束のことである。参加者の組(剛体と剛体、または剛体と静的世界の接触相手)ごとに別のバッチ(同じ種類の拘束を密に並べた一覧)を持ち、細分ごとに生成して捨てる
- **静的世界の接触相手**とは、剛体と静的世界(高さ場の升目・建物の子形状・静的衝突メッシュの三角形)の接触で、剛体でない側を表す名前付きの参加者のことである。識別子(コンポジションルートが発行する全順序を持つ番号)・形(衝突数学層の型)・材質の識別子を持ち、配置も速度も質量特性も持たない
- **クーロン円錐**とは、接線方向の乗数の大きさが法線方向の乗数に摩擦係数を掛けた値以下でなければならないという制約 |λ_t| ≤ μ λ_n が、接線平面上の2次元の乗数の空間に作る円錐のことである
- **錨**とは、接触が始まった細分で保存した両参加者の接触点(剛体なら重心局所の点、静的世界の接触相手なら世界位置)のことである。静止摩擦がそこからの接線変位を零へ戻し、クーロン円錐を超えたときに置き直す
- **表面物性**とは、静止摩擦係数・動摩擦係数・反発係数の組のことである。衝突形状の子形状が材質の識別子で参照する
- **混合則**とは、2つの表面物性から接触1つの接触物性を作る規則のことである。既定則(摩擦は相乗平均・反発は最大値)と材質対ごとの上書き表を持ち、可換である
- **接触の履歴**とは、参加者の組の識別子と接触の特徴の識別を鍵に刻みを跨いで保持する、錨と前の細分の接触法線のことである。参加者の組ごとに別の一覧を持ち、全順序の併走で対応付ける
- **静穏**とは、動的剛体の速度と角速度が休止の閾値以下で、全接触の貫通が接触余白以下で、錨が置き直されていない状態のことである。島の全剛体が連続して静穏である細分が閾値の個数続くと島が休止する
- **剛体の台帳**とは、剛体の生成と破棄・運動種別の遷移・作用の投入・配置と速度の読み出し・材質の設定を公開する操作サービスのことである。接触の履歴・島・休止・動く形の空間索引への登録を内部に持つ
- **連続衝突の方針**とは、剛体ごとに選ぶ、離散の接触だけ・掃引を使う・自動で昇格する、の3枝のことである

| 衝突数学層 | `blitz_collision`(既存) | 接触点集合・連続衝突・動く形の空間索引・形状の表現(既存のまま)。接触の特徴の識別への全順序の導出を足す | 既存のとおり |

## 記法

本文書の数式は次の記法で書く。すべて3次元であり、断りが無ければベクトルはワールド座標の成分で書く。

- x ∈ R³ [m] は重心の世界位置、q ∈ S³ は姿勢、R(q) ∈ SO(3) はqが表す回転行列(重心局所座標からワールド座標へ)である
- v ∈ R³ [m/s] は重心の並進速度、ω ∈ R³ [rad/s] は角速度である
- m ∈ (0, ∞) [kg] は質量、w = 1/m [1/kg] は逆質量である
- J = diag(J₁, J₂, J₃)(各J_k ∈ (0, ∞) [kg·m²])は主慣性、P ∈ SO(3) は主軸(主軸座標から重心局所座標への回転)である。重心局所座標の慣性は I_ℓ = P J Pᵀ、その逆は I_ℓ⁻¹ = P J⁻¹ Pᵀ、ワールド座標の逆慣性は I⁻¹ = R(q) I_ℓ⁻¹ R(q)ᵀ であり、いずれも対称正定値の3×3行列である(単位は [kg·m²] と [1/(kg·m²)])
- h [s] は細分1本の刻み幅(基本刻み H = 1/60秒を整数nで割った長さ。判断19)である
- r̄ ∈ R³ [m] は剛体の重心局所座標で表した点、p = x + R(q) r̄ はその世界位置、r = p − x はその腕(重心から見た世界の変位)である
- 接触では第1の参加者をA、第2の参加者をBとし、n ∈ S² は共有の単位法線(AからBへ向かう)である。Bが静的世界の接触相手のときは p_B が世界に固定された点である
- C [m] または [rad] は拘束違反、λ [kg·m] または [kg·m²] はラグランジュ乗数、α̃ [1/kg] または [1/(kg·m²)] はコンプライアンスの刻み依存量(α ÷ h²)である。式はXPBD共通拘束基盤の判断1のとおり Δλ = (−C − α̃λ) ÷ (有効逆質量 + α̃) である
- vec(q) は四元数のベクトル部、re(q) は実部、[a]× は a との外積を表す3×3行列である

## 主要な設計判断

### 判断1: 剛体力学は `blitz_sim` に置き、`blitz_sim` が `blitz_collision` へ依存する

剛体の状態・作用・姿勢自由度の数学・接触解法のCPUの参照計算・接触の履歴・接触島・休止・剛体の台帳・GPUレイアウトの契約を `blitz_sim` の剛体のモジュール群へ置く。`blitz_sim` の `Cargo.toml` へ `blitz_collision` の依存を足し、接触点集合の型を `blitz_sim` が直接読む。接触の候補(どの剛体の対と、どの静的世界の接触相手を詳細に調べるか)を作るのは `blitz_app` の物理の配線であり、`blitz_sim` は候補の供給を受けて接触点集合を作り拘束へ写す。

Issue #8の実装境界(2026-09-01)が `blitz_sim` を「点自由度と姿勢自由度の数学・拘束族ごとの型とCPUの参照計算・GPUレイアウト契約」の置き場と定め、Issue #39の完了条件が「`blitz_sim` に姿勢を持つXPBD参加者の参照状態と計算がある」と書いている。接触点集合を `blitz_sim` が読まないと、接触拘束の型を `blitz_sim` に置けないか、接触点の型の写しを2つ持つことになる。世界の形と衝突基盤の判断4は「既存の `blitz_sim` の布の衝突計算(カプセル)は剛体の着工時に `blitz_collision` の形状型へ揃える」と定めており、この依存の追加はその判断の実行でもある。

捨てた案は3つある。新クレート `blitz_dynamics`(Issue #7の2026-08-28のコメントの案A)は、剛体が `blitz_sim` のXPBDの正典式・拘束グラフ・GPUレイアウト契約をそのまま使う以上、`blitz_sim` へ依存する薄いクレートになり、点自由度と姿勢自由度を同じ拘束へ参加させる型(判断10)が2クレートに割れる。`blitz_collision` の内部モジュールに置く案は、「衝突数学は幾何学的事実まで」という同基盤の判断10に反する。`blitz_sim` が接触点集合を知らず `blitz_app` の配線が接触拘束のデータへ写す案は、写す責務が配線へ漏れて剛体接触のCPUの参照計算を `blitz_sim` の検査で閉じられない。

機械で強制する方法は次のとおりである。`cargo xtask conform` のクレート依存の白リストへ `blitz_sim → blitz_collision` を足す。`blitz_sim` は引き続き `blitz_engine`・`blitz_render`・`blitz_app` を知らず、白リストがそれを課す。剛体のモジュール群は `blitz_sim` の中で `rigid_body/`(状態と作用)・`rigid_xpbd/`(姿勢自由度の数学)・`contact/`(接触拘束・履歴・島・休止)に分け、`blitz_collision` を読むのは `contact/` の生成の工程だけにする(モジュールの可視性で他のモジュールから `blitz_collision` の型を見せない)。

### 判断2: 剛体の状態は4群に分け、運動種別は状態を持つ枝の列挙で表す

1つの剛体は識別子と次の4群を持つ。配置(判断3)、質量特性(判断4)、運動(運動種別の枝)、実行状態(起きているか休止しているか。判断18)である。運動種別は3枝の列挙であり、枝ごとに持つ状態が違う。

```text
運動種別
├─ 静的            持つ状態: なし(速度を持たない)
├─ 運動学的        持つ状態: この刻みの並進速度と角速度(外から与えた次の配置から導く。判断7)
└─ 動的            持つ状態: 並進速度・角速度・一刻みの作用の蓄積器(判断6)・休止の判定に使う静穏の連続細分数(判断18)
```

Issue #7の裁定候補1・2・8のとおり、静的を「質量∞の動的」、運動学的を「毎刻み瞬間移動する動的」という特殊値で表さない。静的が速度の欄を持たないことを型で表すと、「静的なのに速度が残っている」状態が作れない。運動学的が速度を持つのは、裁定候補3(運動学的剛体も速度を持つ物体として接触へ参加する)のためである。質量特性を運動種別の外に置くのは、裁定候補7と8(質量特性は衝突形状と分離し、種別を質量で表さない)と、種別が遷移しても質量特性は変わらないためである。解法が静的と運動学的を「動かさない自由度」として実効の逆質量0で扱うのは導出であって正本ではない(XPBD共通拘束基盤の判断3)。

4群を1つの構造体へ平らに並べる案は、静的な剛体が速度と作用の蓄積器を持つことになり、「静的は速度を持たない」を運用で守ることになるため捨てる。運動種別を状態を持たない列挙にして速度を全種別が持つ案も同じ理由で捨てる。

機械で強制する方法として、運動種別の列挙の枝がデータを持ち、速度の読み出しは `Option` でなく「動的または運動学的の速度」という枝の一致で取り出す(静的からは取り出せない)。実効の逆質量と逆慣性は解法の内部の関数が運動種別から導き、剛体の型に「逆質量0」を書き込む口を持たない。

### 判断3: 配置は重心の世界位置と単位四元数の姿勢であり、正規化は姿勢の型が守る

動的剛体の物理位置の正本は重心の世界位置 x である(裁定候補5)。姿勢 q は単位四元数を専用の型「姿勢」で持つ。「姿勢」は生成で長さを検証し(長さが1から1e-4以上ずれた値と非有限を型付きエラーで拒む)、積分と補正の演算はすべて新しい「姿勢」を返す形で書き、その戻り値の生成が正規化を行う。呼び出し側が正規化を忘れられる経路を作らない。物体原点の世界位置は x − R(q) c̄(c̄は物体原点から見た重心。判断4)で復元し、描画とゲーム側が読む物体原点の変換はこの復元の1箇所で作る。

裁定候補6(姿勢が数値誤差で回転でなくなる状態を許容しない)の実装形である。単位四元数は積分(判断8)が長さを1からずらすため、正規化の位置を型の生成に閉じるのが最も漏れが少ない。剛体の並進の運動方程式が重心について書かれるため、位置の正本を重心にすると腕 r = p − x が接触点の力の回転効果をそのまま与える。

回転行列(9つの数)は正規直交性の維持に3×3の再直交化が要り、GPUのバッファも四元数の16バイトに対して36バイトになるため捨てる。オイラー角は特異点(ある姿勢で1自由度が失われる)を持ち、角速度の積分に向かない。物体原点を位置の正本にする案は、並進と回転が連成した運動方程式になり、接触の腕を重心から測る接触点集合の設計(両形の上の点を持つ理由)と合わない。

機械で強制する方法として、「姿勢」型は `blitz_math` の `クォータニオン<ローカル, ワールド>` を包む新型であり、生の4成分を取り出す口はGPUのバイト列化と描画の変換の生成の2箇所だけにする。検査は、乱数の角速度で1万細分積分した後の長さが1から1e-5以内であること、および正規化を外した反証で長さが1から離れることを固定する。

### 判断4: 質量特性は質量・物体原点から見た重心・主慣性と主軸で持ち、生成で物理的な有効性を検証する

質量特性は3つの値を持つ。質量 m は `blitz_math` の `キログラム`(正の有限値。既存)である。物体原点から見た重心 c̄ は物体の局所座標の変位(判断5の型)である。重心まわりの慣性は主慣性 J = (J₁, J₂, J₃)(各値が正の有限の [kg·m²])と主軸 P(主軸座標から重心局所座標への回転。「姿勢」と同じ単位四元数の型)の組である。生成は J₁ + J₂ ≥ J₃・J₂ + J₃ ≥ J₁・J₃ + J₁ ≥ J₂ の三角不等式(等号は平面に分布した質量)を検査し、破れを型付きエラーで拒む。逆質量 w と逆主慣性 J⁻¹ は生成時に1度だけ導いて保持する。任意の対称3×3行列を受け取って対角化する仕事は制作時(Issue #19)に置き、実行時の型は対角化済みだけを受ける。質量特性は衝突形状の属性にせず、剛体が別に持つ(裁定候補7)。

裁定候補9(慣性は物理的に有効な質量分布に対応する値として検証できる)を、正値と三角不等式という3つの不等式だけで書けるのが対角化済みの形である。任意の3×3行列を実行時に受けると、対称性・正定値性・三角不等式の検査に固有値分解が要り、その数値誤差の扱いが実行時に入る。ワールド座標の逆慣性 I⁻¹ = R(q) P J⁻¹ Pᵀ R(q)ᵀ は姿勢が変わるたびに変わるため状態として持たず、使う場所で組む(行列積2回であり、接触1件あたりの費用の中で無視できる)。

3×3の対称行列を状態に持つ案は上の理由で捨てる。単一の慣性スカラーは方向依存を表せず裁定候補9に反する。ワールド座標の逆慣性を状態に持つ案は、姿勢が変わるたびに書き換える冗長な状態になる。

機械で強制する方法として、質量特性の型は私有フィールドと検証付きの `生成する()` だけを持ち、質量0・負・非有限、主慣性の0・負・非有限、三角不等式の破れがそれぞれのエラーの枝になることを検査で固定する。箱・球・カプセルの解析式(一様密度)から質量特性を作る関連関数を `blitz_sim` が持ち、Issue #19が焼き込む日までの初版の生成経路とする。

### 判断5: 力学の量は単位と座標系を持つ型で持ち、`blitz_math` へ足す

`blitz_math` へ次の型を足す。ベクトルの量は座標系の幻影型(`ワールド` と、剛体ごとの重心局所を表す `ローカル`)を持つ。速度 [m/s]・角速度 [rad/s]・力 [N]・回転力 [N·m]・衝撃 [N·s]・回転衝撃 [N·m·s] の6つのベクトル型と、慣性 [kg·m²] と逆慣性 [1/(kg·m²)] のスカラー型(主慣性の成分)である。次元の合成を演算子で書く。力 × 秒 = 衝撃、衝撃 × 逆質量 = 速度、速度 × 秒 = 変位、変位 × 力(外積)= 回転力、回転力 × 秒 = 回転衝撃、回転衝撃 × 逆慣性(ワールドの3×3)= 角速度、である。次元の合わない加算はコンパイルで落ちる。生の `f32` へ戻すのは `gpu_layout` のバイト列化と描画の変換の生成だけである。

グローバルCLAUDE.md「数学DDD」と、裁定候補11(力と衝撃を型で区別する)の実装形である。力と衝撃を同じ型の倍率違いにすると、ゲーム側が力を毎刻み加えるつもりで衝撃を加える誤りを型が止められない。現在の `blitz_math` は `メートル毎秒` と `ラジアン毎秒` をスカラーとして持つだけであり、ベクトルの速度型・角速度型・慣性型・力の型が1つも無い(2026-09-02時点の調査)。

`変位<ワールド>` を速度の代わりに使い「1刻みの変位」として持つ案は、細分の刻み幅が変わると意味が変わる量を状態にすることになり、細分数を品質方針として外から与える規律(判断19)と合わないため捨てる。慣性を `blitz_sim` 側の型にする案は、Issue #19の焼き込みが `blitz_math` の型で慣性を書けなくなる。

機械で強制する方法として、新型はすべて `#[repr(transparent)]` または3成分の私有フィールドの構造体であり、`値()` 以外に生の成分を返さない。`cargo xtask conform` の禁止文字列で、剛体のモジュール群の中の `f32` の3つ組(`[f32; 3]`)の宣言を落とす。

### 判断6: 永続状態と一刻みの作用を分け、任意点への作用は剛体の側が回転力へ写す

動的剛体は一刻みの作用の蓄積器(合力 F [N]・合回転力 τ [N·m]・衝撃の和 P [N·s]・回転衝撃の和 L [N·m·s] の4つ)を持つ。蓄積器は物理刻みの工程2(ゲームからの介入の適用。XPBD共通拘束基盤の判断8)で所有ごと取り出され、取り出しと同時に空の蓄積器へ置き換わる。刻みの外で蓄積器に値が残っている状態は作れない。取り出した4つの量の使い方は2つに分かれる(判断19の細分の工程の中で行う)。合力と合回転力はその刻みの入力として保持され、n本の細分すべてで v ← v + h(g + w F)、ω ← ω + h I⁻¹ τ として積分される(n本の合計で H·F と H·τ の運動量の変化になる)。衝撃と回転衝撃は最初の細分の予測の前に1回だけ v ← v + w P、ω ← ω + I⁻¹ L として適用され、2本目以降の細分には効かない。ゲーム側が与える作用は次の6つの操作であり、任意点への作用から生じる回転力と回転衝撃は剛体の側のメソッドが腕の外積で計算する。

```text
重心へ力を加える(力)                  F += 力
重心へ衝撃を加える(衝撃)              P += 衝撃
回転力を加える(回転力)                τ += 回転力
回転衝撃を加える(回転衝撃)            L += 回転衝撃
点へ力を加える(作用点, 力)            F += 力、τ += r × 力
点へ衝撃を加える(作用点, 衝撃)        P += 衝撃、L += r × 衝撃
```

作用点は「世界位置」と「重心局所の点」の2枝の列挙であり、腕 r は世界位置なら 世界位置 − x、局所の点なら R(q) r̄ である。腕の計算は作用点の型のメソッドであり、呼び出し側は腕を計算しない。

裁定候補10(一刻みの作用が意図せず次の刻みへ残らない)・11(力と衝撃を区別する)・12(任意位置への作用。ゲーム側が回転力を手計算しない)の実装形である。力は時間発展を通じて運動量を変え、衝撃は瞬間に運動量を変えるため、同じ蓄積器から取り出しても細分への配り方が違う。力を全細分で積分するのは、細分数を変えても1刻みで与える運動量の変化が H·F のまま変わらないためであり、衝撃を最初の細分だけに与えるのは、n本の細分で n 回加えると n 倍になるためである。

力を「持続する作用」として刻みを跨いで保持し解除の操作を持つ案は、解除忘れが永続状態へ混入するため捨てる。ゲーム側が毎刻み加え直す形が、蓄積器が刻みの中でだけ生きる規律と合う。衝撃を「1刻みの間だけ効く大きな力」として力の型で表す案は候補11に反する。衝撃を細分数で割って全細分へ配る案は、最初の細分で衝突の速度が立たず、反発の判定(判断14)が衝撃の直後の細分で衝突前の速度を読めない。

機械で強制する方法として、蓄積器は動的の枝だけが持ち(判断2)、静的と運動学的の剛体へ作用を投入する操作は型付きエラー(`静的な剛体へ作用を加えようとした` 等)を返す。工程2の取り出しは蓄積器を所有で受け取って「一刻みの入力」(保持する力と回転力)と「一度だけ適用する衝撃」の2つの型に分けて返し、後者は最初の細分が所有で消費するため2本目以降の細分へ渡せない。休止中の剛体へ作用を投入すると島が再開する(判断18)。

### 判断7: 運動種別の遷移は台帳の専用の操作であり、遷移後の状態は一意に決まる

運動種別の変更は剛体の台帳の3つの操作(`動的にする(初速の並進速度, 初速の角速度)`・`運動学的にする()`・`静的にする()`)で行い、次の安全な境界(物理刻みの工程1。構造変更の反映)で反映する。遷移が整合させるものは4つである。速度(動的へは引数の初速、運動学的へは前の刻みの配置との差から導いた速度、静的へは無し)・休止(動的へ遷移した剛体は起きた状態から始める)・接触の履歴(その剛体を含む履歴をすべて捨てる)・接触島(次の細分で組み直す)である。動く形の空間索引への所属は3種別とも変わらない(静的な剛体も索引に載り、動的剛体との対の列挙に現れる)。

運動学的剛体の速度の導出は、外から与えた次の配置 (x', q') と現在の配置 (x, q) から行う。並進は v = (x' − x) ÷ H である。回転は Δq = q' ⊗ q⁻¹(実部が負なら符号を反転して短い弧を取る)の対数写像 ω = (2 · atan2(|vec(Δq)|, re(Δq)) ÷ |vec(Δq)|) · vec(Δq) ÷ H である(|vec(Δq)| が1e-8未満なら ω = 0)。1刻みの回転量が π/2 [rad] を超える配置の指定は型付きエラーで拒む。回転の対数写像が半回転に近づくと不定になるためであり、その大きさの回転を1刻みで与える運動学的剛体は仕様の外である。運動学的剛体の細分の中の配置は、現在の配置から次の配置へ細分の番号の比で線形に(姿勢は最短の弧で)進める。

裁定候補4(運動種別の変更は正式な状態遷移として扱い、変更後の状態が一意に定まる)の実装形である。列挙の枝の書き換えだけにすると、静的から動的へ変わった剛体が速度も休止も持たない不定の状態になる。Issue #7の追加の論点2(運動学的の速度の導出式が未定義)は上の式で定める。

遷移を即時に反映する案は、拘束の反復の途中で自由度の集合が変わり、島と履歴が反復の途中で壊れるため捨てる(XPBD共通拘束基盤の判断8の工程1の理由と同じ)。運動学的剛体の回転量の上限を課さず対数写像の不定をそのまま許す案は、半回転の付近で角速度の向きが入力の丸めで反転する。

機械で強制する方法として、遷移の操作は台帳のメソッドであり、剛体の型に運動種別を直接書き換える口を置かない。遷移の予約は構造変更の待ち行列に積まれ、工程1だけがそれを取り出す。検査は、動的→静的→動的の往復で速度と履歴が引数どおりに初期化されること、運動学的の回転量の上限超過がエラーになること、を固定する。

### 判断8: 姿勢自由度の予測は速度・位置・角速度・姿勢の順で行い、ジャイロ項は陰的に解く

細分1本(刻み幅h)の予測を次の順で行う。前の状態(x_前, q_前)を保存し、並進は v ← v + h(g + w F)、x ← x + h v とする(g は重力加速度、F は判断6の一刻みの入力の合力)。回転は重心局所座標で角速度 ω_ℓ = R(q)ᵀ ω を取り、ジャイロ項を陰的に1段(ニュートン法1回)解く。

```text
f(ω₁) = I_ℓ (ω₁ − ω₀) + h · ω₁ × (I_ℓ ω₁)                  解きたい式(f(ω₁) = 0。角運動量の保存を後退オイラー法で離散化した形)
Jf    = I_ℓ + h · ( [ω₀]× I_ℓ − [I_ℓ ω₀]× )               ω₀ でのヤコビ行列
ω₁    = ω₀ − Jf⁻¹ f(ω₀) = ω₀ − Jf⁻¹ (h · ω₀ × (I_ℓ ω₀))    ニュートン法1回
```

その後に回転力を陽的に足し(ω₁ ← ω₁ + h I_ℓ⁻¹ τ_ℓ。τ_ℓ = R(q)ᵀ τ)、ワールドへ戻して ω ← R(q) ω₁、姿勢を q ← q + (h/2)·(ω_四元数 ⊗ q)(ω_四元数 = (ω_x, ω_y, ω_z, 0))として正規化する(判断3の型の生成が行う)。運動学的剛体は判断7の細分の配置へ進み、静的剛体は何もしない。

細分の中で予測し、姿勢を1次の更新と正規化で進める形は、剛体XPBD(Müller・Macklin・Chentanez・Jeschke・Kim「Detailed Rigid Body Simulation with Extended Position Based Dynamics」2020年)の予測の形であり、細分の刻み幅を小さくするほうが反復を増やすより同じ計算量で誤差が小さいという結果(Macklinら「Small Steps in Physics Simulation」2019年)に基づく。ジャイロ項を陰的に解くことは、その論文の形ではなく本文書の数値方針である(同論文はニュートン・オイラー式の陽的な更新を細分で回す)。陰的に解くのは、陽的に足すと角速度が主慣性の逆数と刻み幅で決まる大きさを超えたときに発散し、省くと細長い物体の回転が中間軸で反転する現象(裁定候補18の「高速回転」)が再現されないためである。局所座標で解くのは I_ℓ が定数であるためであり、3×3の逆行列1回で済む。

この数値法が保証する不変条件は次の2つに限る。有限の刻み幅で角運動量の大きさが増えないことも保存されることも保証しない。後退オイラー法そのものが数値散逸を持ち、収束させないニュートン法1回には単調性の一般の保証が無いためである。保証するのは、(a)発散しないこと(外力なしの自由回転で角運動量の大きさが初期値の (1 + ε) を越えない。ε は暫定値であり実測から置く)と、(b)散逸が刻み幅とともに減ること(刻み幅を半分にしたとき、同じ実時間の後の角運動量の大きさの減少量が減る)である。角運動量を保存する回転積分(暗黙の中点法を細分ごとに収束まで反復する形)は採らない。細分ごとに3×3の非線形の反復を収束まで回す費用と決定性の検証が増えるうえ、接触の位置拘束が毎細分の反復で角速度を書き換えるため、回転積分の保存性は接触している剛体では成り立たず、自由回転の見た目の忠実さは陰的1段の散逸を細分数で下げることで足りるからである。

陽的なジャイロ項は上の理由で捨てる。ジャイロ項の省略は、剛体の回転のエネルギーが保存されず、角運動量の向きが姿勢に依らず固定されるという物理的に誤った挙動になる。姿勢の積分に指数写像(回転ベクトルから四元数を作る)を使う案は三角関数が細分ごとに要り、1次の更新と正規化で同じ次数の精度が出るため採らない。

機械で強制する方法として、予測の関数は「前の状態」と「予測の状態」を別の型で返し、拘束の補正は予測の型だけに掛かる。検査は4つであり、いずれも主慣性 (1, 2, 3) [kg·m²]・細分の刻み幅 h = 1/480秒(n = 8)・外力なしで行う。(1)発散しないこと: 主軸の外の初期角速度 (3, 7, 5) [rad/s] で600細分進めた後のワールド座標の角運動量 R(q) I_ℓ R(q)ᵀ ω の大きさが初期値の (1 + ε) を越えないこと(ε の暫定値は1e-2であり、実装時の実測で置き直す)。(2)散逸が刻み幅とともに減ること: 同じ初期値で h を半分(1/960秒)にして同じ実時間(1.25秒)を進めたとき、角運動量の大きさの減少量が h = 1/480秒のときより小さいこと。(3)中間軸の反転: 初期角速度 (0.01, 10, 0) [rad/s](中間軸に小さい非零の摂動を乗せた値。摂動が厳密に0なら厳密解でも反転しないため摂動を明記する)で角速度の中間軸の成分の符号が有限の細分数で反転すること、およびジャイロ項を外した反証では反転しないこと。(4)陽的なジャイロ項の発散の反証: 主軸の外の初期角速度 (0, 200, 150) [rad/s](主軸上の初期値では ω × (I_ℓ ω) = 0 が厳密に成り立ち陽的でも変わらないため、2成分を非零にする)でジャイロ項を陽的に足した更新を100細分進めると、100細分以内のいずれかの細分で角運動量の大きさが初期値の2倍を越えるか非有限になること(各細分で検査し、最初に越えた時点で反証の成立とする。陽的更新は倍精度で17細分目に2倍を越え、その後に非数へ発散するため、最後の値だけを比べると非数との比較が偽になって反証が落ちる)、および陰的1段では同じ初期値と細分数で (1 + ε) を越えないこと(倍精度の見積りで100細分後の比は約0.85)。

### 判断9: 拘束の勾配から並進と回転の補正を一般化逆質量で分配し、確定後に速度と角速度を再構成する

世界の点 p(腕 r = p − x)に勾配 n(単位ベクトル)で作用するスカラー拘束について、その剛体の一般化逆質量を w̃ = w + (r × n)ᵀ I⁻¹ (r × n) [1/kg] とする。回転だけに作用する拘束(軸 n のまわりの角度の拘束)では w̃ = nᵀ I⁻¹ n [1/(kg·m²)] である。参加する自由度の w̃ の和が有効逆質量であり、点自由度が参加するときはその逆質量(勾配の2乗は1)を足す。Δλ をXPBD共通拘束基盤の判断1の式で求め、剛体への補正は次のとおりである(符号は勾配の向きに従う。距離拘束の規約と同じく、aからbへ向かう n に対して a の勾配は −n である)。

```text
点に作用する拘束:   Δx = w · Δλ · n
                    Δq = (1/2) · [ I⁻¹ (r × (Δλ · n)) ]_四元数 ⊗ q      (正規化は姿勢の型が行う)
回転だけの拘束:     Δq = (1/2) · [ I⁻¹ (Δλ · n) ]_四元数 ⊗ q
静的・運動学的:     補正なし(実効の w̃ = 0 として有効逆質量に足さない)
```

細分の反復を終えた後、速度と角速度を確定した配置と前の状態の差から再構成する。v = (x − x_前) ÷ h、Δq = q ⊗ q_前⁻¹、ω = 2 · vec(Δq) ÷ h(Δq の実部が負なら符号を反転する。細分1本の回転は小さいため1次の形で足りる)。運動学的剛体は判断7の速度を持ち続け、再構成しない。角速度は再構成の結果を保持する永続状態であり(判断2)、次の細分の予測(判断8)と速度段階(判断14)と休止の判定(判断18)がそれを読む。

Issue #7の追加設計(2026-09-01)の「剛体接触の位置補正では回転も必ず反映する」の実装形であり、Issue #39の完了条件(逆慣性を含む姿勢補正)である。一般化逆質量は、点への力が回転を生む効果を「その点をその向きへ動かすのに要する仕事」として1つの逆質量に畳んだ量であり、点自由度の逆質量と同じ次元を持つため、点自由度と姿勢自由度を同じ Δλ の式に載せられる。速度を位置差から再構成するのは、位置拘束が変えた運動を速度へ反映するためであり、裁定候補6の「角速度は独立した運動状態」は「再構成の結果を永続状態として保持し、観測・介入・休止・速度段階がそれを読む」という意味で成立する(Issue #7の追加の論点2の裁定)。

速度を位置差から作らず位置と独立に発展させる案(速度基準の解法)は、Issue #5の横断裁定(位置と姿勢の補正という数学へ統一する)に反する。回転の補正を無視して並進だけ補正する案は、箱の角の接触で転倒が起きず、Issue #40の完了条件に反する。

機械で強制する方法として、補正の式は `blitz_sim::rigid_xpbd` のCPUの参照計算1箇所が持ち、GPUの写しは同じ符号・同じ演算順で書く(XPBD共通拘束基盤の判断1と同じ運用)。検査は2段に分ける。補正の適用の関数(Δλ を固定して受け、Δx と Δq を返す)については、重心へ作用する拘束(r = 0)で回転が生じないこと、質量を2倍にすると並進の補正が半分になり主慣性を2倍にすると回転の補正が半分になること(Δλ が同じなら補正は w と I⁻¹ に比例する)を固定する。一回の射影の全体(Δλ の分母に有効逆質量が入る)については上の比例は一般に成立しないため、剛体1つと世界固定点の目標点拘束(判断10)で解析的に求めた1回の補正と一致することを固定する。再構成した角速度は微小な回転で解析値と相対1e-4以内で一致することを固定する。

### 判断10: 点自由度と姿勢自由度は参加する自由度の組ごとの密なバッチで同じ拘束へ参加し、Issue #39は3つの拘束で検証する

拘束族は参加する自由度の型の組ごとに別の密なバッチを持つ(点と点・剛体と剛体・剛体と点・剛体と世界の点・剛体と静的世界の接触相手)。「自由度参照 { 種類, 添字 }」のような1つの列挙で複数の種類を指す型を作らない。Issue #39が最初に作る検証拘束は3つである。

```text
剛体の局所点を世界の目標点へ一致させる拘束(剛体と世界の点)
    C = |p − 目標|、n = (目標 − p) ÷ C、参加は剛体1つ(w̃ は判断9)。既存の目標拘束の姿勢自由度への一般化
2剛体の局所点どうしを一致させる拘束(剛体と剛体。接続拘束)
    C = |p_A − p_B|、n = (p_B − p_A) ÷ C、A の勾配は −n、B の勾配は +n。距離拘束の静止長0の形を姿勢自由度で解く
```

剛体と点のバッチ(布の頂点を剛体の局所点へ接続する拘束・剛体の面と布の頂点の接触)は型と式だけをIssue #39で置き、実証はIssue #43(強結合)で行う。剛体と静的世界の接触相手のバッチは判断11が定める。

Issue #39の原則(粒子・剛体・棒を同じドメイン型にしない。共通なのは拘束が参加者の自由度へ補正を返す数学)と、Issue #18の実装境界(強結合用の拘束型は組合せごとに持ってよい)の実装形である。3つの検証拘束は、目標拘束(点自由度で実装済み)の姿勢自由度版・接続拘束(XPBD共通拘束基盤の判断6が用途が立った日に足すとした)・ねじり(Issue #9の棒の基礎)であり、Issue #41の蝶番と固定関節はこの3つの組合せで書ける。ねじりの拘束違反をA局所座標で閉じて計算し勾配だけをワールドへ写すのは、相対姿勢の回転ベクトルと軸を同じ座標系で内積するためである。

1つの列挙で点と剛体を指す案は、拘束の射影が毎回枝を分ける費用と、GPUのカーネルが両方の配列を読む複雑さを全拘束族へ課すため捨てる。ねじりの拘束を四元数の差の全成分(3自由度)で書く案は、蝶番のような軸まわりの自由を残す拘束へ再利用できない。

### 判断11: 接触拘束は接触点集合から細分ごとに生成する一時のバッチであり、参加者の組ごとに別のバッチを持ち、座標系の写しは剛体の側が行う

剛体接触拘束のバッチは2つである。剛体と剛体の接触拘束と、剛体と静的世界の接触相手の接触拘束である。運動学的剛体と静的な剛体は剛体であり、前者のバッチに載る(判断9のとおり実効の重み0で解く)。静的世界の接触相手は剛体でないため、識別子・形・材質だけを持つ名前付きの型として後者のバッチの参加者になる。1点の接触拘束は次を持つ。


接触点集合(世界の形と衝突基盤。最大8点)1つが1つの接触多様体であり、その全部の点を接触拘束として保ち、1点へ潰さない。接触点集合は形の局所座標(2つの形が共有する1つの座標系)で両形の上の点を返すため、剛体の側が2つの形をその座標系へ置き(初版はワールドを共有の座標系とし、倍精度の位置を単精度へ狭めるのは接触点を局所へ写す1箇所である)、返った点を各剛体の重心局所座標へ写す。静的世界の接触相手の点はワールドのまま持つ。生成の工程は細分ごとに次を行う(判断19)。

```text
索引の更新:     予測した細分の変位で伸ばした箱(細分の始点と終点の形を包む箱にゆとりの幅0.1メートルを足したもの)で動く形の空間索引を更新する

接触点集合:     対ごとに予測した配置で接触点集合を作り、特徴の識別で履歴へ対応付け(判断16)、接触拘束の2つのバッチを作り直す
```

Issue #7の追加設計の第2節(接触拘束の正本データ)と実装境界(接触拘束は刻みごと生成する一時バッチ)の実装形である。参加者の組ごとにバッチを分けるのは判断10の規則に従うためであり、静的世界(三角形・建物・高さ場)には剛体の識別子も重心局所点も無いため、剛体Bを要求する1つの型へ潰せない。局所接触点で持つのは、細分の間に剛体が動いても現在の姿勢で貫通量を再評価できるようにするためであり(判断12)、接触点集合が両形の上の点を持つのはこのためであると同基盤が明記している。Issue #7の追加の論点5(接触点の座標系の写しの責務は#7側)をここで定める。細分ごとに索引を更新して候補を列挙するのは、索引のゆとりの幅0.1メートルが基本刻み全体の移動を覆わず、刻みの頭に1回の列挙では後の細分で新しく近づく相手を候補に含められないためである。細分の変位で伸ばした箱を登録することが保証するのは、「細分の終点で重なる対を候補から落とさない」ことだけである(箱の更新の遅れで、終点で重なっているのに候補に出ない事故を防ぐ)。細分の途中で触れて終点では通過し終えている対は、候補に入っても終点の配置で作る接触点集合が空になり、この工程では止まらない。細分の途中の衝突時刻を扱うのは判断20の連続衝突の方針であり、初版(Issue #40)ではその方針を「離散の接触だけ」で閉じる。細分ごとに接触点集合を作り直すのはIssue #18の実装境界(接触候補を刻みの最初に1度生成して終わりと固定しない。初版は細分の単位を基本とする)に従う。

接触点を世界座標だけで持つ案は、細分の間の剛体の回転で貫通量を再評価できないため捨てる(オーナーの実装境界が禁じている)。剛体と静的世界を「任意の参加者」の1つの列挙で束ねる案は判断10に反する。候補の列挙を基本刻みの頭に1回だけ行う案は上の理由で捨てる。接触点集合を刻みの頭に1回だけ作り細分では局所点の再評価だけを行う案(判断8の2020年の手法の形)は費用が小さいが、Issue #18の裁定に反し、変形体との接触へ広げたとき(Issue #43)に更新頻度が2系統になる。計測で細分ごとの生成が予算を圧迫したときに、剛体どうしの対だけを落とすことを候補として残す。

機械で強制する方法として、接触拘束のバッチは細分の開始で生成し細分の終了で捨てる型であり、刻みを跨いで持つ口が無い(履歴は判断16の別の型)。静的世界の接触相手の識別子は `blitz_sim` が定義する全順序を持つ新型であり、その発行は `blitz_app` の物理の配線が行う(動く形の識別子と同じ契約)。接触点の受け皿は接触点の上限8×対の数の固定長で確保を起こさず、上限超過は型付きエラーである。検査は、同じ配置から生成した接触拘束の局所点を世界へ戻すと接触点集合の点と1e-6メートル以内で一致すること、法線がAからBへ向くこと、1細分でゆとりの幅0.1メートルより長く動く剛体(h = 1/480秒で秒速60メートル。1細分の変位0.125メートル)が細分の終点で重なる相手が候補に入ること(伸ばした箱を外した反証では箱の更新の遅れで候補から落ちること)、を固定する。細分の途中で通り抜ける場合を止めることはこの検査の対象ではない。

### 判断12: 非貫通は法線方向の片側のXPBD位置拘束であり、貫通しているときだけ効く

接触拘束1点の非貫通は、p_A = x_A + R(q_A) r̄_A、p_B = x_B + R(q_B) r̄_B(静的世界の接触相手なら固定の世界位置)、隔たり d = (p_B − p_A) · n [m] について C = d ≥ 0、λ_n ≥ 0 の片側拘束である。生成時は接触点集合の不変条件(第2の形の上の点は第1の形の上の点から法線の向きへ貫通量だけ戻った点)から d = −貫通量 ≤ 0 である。反復1回の計算は次のとおりである。

```text
d ≥ 0 なら:   この点は反復で読まず、λ_n は変えない(離れている・離れていく接触へ押し戻しを加えない)
d < 0 なら:   C = d、Δλ = (−C − α̃ λ_n) ÷ (w̃_A + w̃_B + α̃)、λ_新 = max(0, λ_n + Δλ)、Δλ ← λ_新 − λ_n
              B へ +Δλ n の補正(判断9)、A へ −Δλ n の補正、λ_n ← λ_新
```

コンプライアンス α は0(硬い接触)を既定とし、正の値は柔らかい接触として型が受ける。接触余白(既定0.005メートル。世界の形と衝突基盤の判断10の数値方針)は休止の判定の貫通残差の基準(判断18)に使い、拘束の式には入れない。静的と運動学的の剛体と静的世界の接触相手は w̃ = 0 であり、運動学的剛体の細分の中の配置の変化(判断7)は p_B の変化として拘束へ入る(境界運動)。深い初期重なり(貫通量が形の最小の厚みの半分を超える)も同じ式で解き、1細分あたりの補正の長さの上限を形の最小の厚みとして切り詰め、数細分で回復させる(オーナーの追加設計の第3節が許す「通常接触とは別の回復方針」はこの切り詰めだけである)。バウムガルテ安定化(貫通量に比例した押し戻しを速度へ注入する手法)は採らない。

Issue #7の追加設計の第3節(非貫通は片側XPBD拘束)とIssue #40の対象の実装形である。位置の言葉で貫通を解消すると「細分の終わりの配置が d ≥ −接触余白 を満たす」を状態の不変条件として検収に書ける。λ_n ≥ 0 の切り詰めは、離れている物体を引き寄せないための片側性である。バウムガルテ安定化は単位の無い係数がエネルギーを注入し、静止すべき塔を微振動させる(オーナーの要求1に反する)。

速度基準の逐次衝撃と位置の別解消(Issue #7の裁定材料の案A)は、Issue #5の横断裁定で退けられた。線形相補性問題の直接法(案C)は実装の費用が1桁大きく退化した入力に弱い。接触余白を拘束の目標(d ≥ 余白)に入れる案は、静置した箱が余白ぶん浮く見た目になり、余白の値が挙動へ漏れる。

機械で強制する方法として、非貫通の射影は `blitz_sim::contact` のCPUの参照計算1箇所が持ち(2つのバッチは参加者Bの点の取り方だけが違い、式は同じ関数を読む)、結果の型は補正した枝と「離れている」「両方が動かせない」の理由の枝を持つ(距離拘束と同じ様式)。検査は、λ_n が負にならないこと、d ≥ 0 で λ_n が変わらないこと、箱1個を床へ落として静止した後の貫通が接触余白以下であること、深い初期重なりが非数を出さず有限の細分数で回復すること、を固定する。

### 判断13: 静止摩擦は錨からの接線変位を零へ戻す位置拘束であり、クーロン円錐の内側でだけ効く

接触が始まった細分で両参加者の接触点を錨(ā_A, ā_B。判断16の履歴が持つ)として保存する。各細分の非貫通の射影の後、錨の世界位置 a_A = x_A + R(q_A) ā_A、a_B = x_B + R(q_B) ā_B(静的世界の接触相手なら固定の世界位置)から接線変位 Δ_t = (a_A − a_B) − ((a_A − a_B) · n) n を求め、|Δ_t| > 0 なら C = |Δ_t|、t = Δ_t ÷ |Δ_t| で位置拘束として Δλ_t を求める(有効逆質量は t で組む一般化逆質量の和 w̃_t = w̃_A,t + w̃_B,t)。接線の乗数は接平面上の2次元ベクトル λ_t として累積し、|λ_t + Δλ_t t| ≤ μ_s λ_n(μ_s は静止摩擦係数、λ_n はその細分の法線の乗数)のとき、すなわちクーロン円錐の内側にあるときだけ補正を適用して λ_t を更新する。超えたときは補正を適用せず、錨を現在の接触点へ置き直し、その接触点をこの細分では滑走中と印す(動摩擦は判断14の速度段階が担う)。接線2軸を独立に切り詰める箱近似は採らない。

オーナーの要求2(坂の上の物体が静止でき、限界を超えると滑り出し、滑走中の抵抗は静止中の保持と別)と追加設計の第4節の実装形である。静止摩擦を速度の言葉で近似すると、定常の荷重の下で接線方向の微小な滑りが毎刻み残り、坂の箱がじわじわ下る。錨からの変位を位置で零へ戻す拘束はこの残留が構造的に零である。円錐の内側でだけ効かせ超えたら錨を捨てる形は、位置の静止摩擦と速度の動摩擦が同じ細分で二重に効くことを避ける。等方の判定(2次元の乗数の長さで比べる)にするのは、追加設計の第4節が「接線2軸を完全に独立にクランプした結果、方向によって摩擦強度が不自然に変わる問題」(クランプは上限で切り詰めること)を検収対象にしたためである。

円錐の側面へ射影して切り詰めた補正を適用する案(射影ガウス・ザイデル型。拘束を1つずつ順に解いて上限で切り詰めながら即座に反映する反復)は、同じ細分で速度段階の動摩擦とあわせて抵抗が二重になるか、速度段階を静止摩擦の成否で分岐させる複雑さを生むため捨てる。接線の乗数を1次元(滑る向き1本)で持つ案は、滑る向きが細分の間に回るとき乗数の意味が壊れる。

機械で強制する方法として、静止摩擦の射影は非貫通の射影と別の関数であり、λ_n を引数で受けて円錐の判定を自分の中で行う。検査は、坂の傾き tan θ < μ_s の箱が3600刻みで1ミリメートル以下しか動かないこと、tan θ > μ_s で滑り出すこと、接線軸の取り方(箱の姿勢を鉛直軸まわりに0度・30度・45度回す)で滑り出す傾きが変わらないこと(等方性)、静止摩擦の位置化を外した反証で坂の箱が下ること、を固定する。

### 判断14: 反発と動摩擦は速度段階で衝撃として1箇所ずつ適用し、低速の反発は零に落とす

細分の速度の再構成(判断9)の後、接触点ごとに接触点の相対速度 v_相対 = (v_B + ω_B × r_B) − (v_A + ω_A × r_A) [m/s](静的世界の接触相手は速度0)、法線成分 v_n = v_相対 · n、接線成分 v_t = v_相対 − v_n n を求める。速度の変化は衝撃(単位はニュートン秒 = キログラム・メートル毎秒)として計算し、両参加者へ等しく反対向きの一般化衝撃として分配する。衝撃 P を B へ +、A へ − で与えると、v_B ← v_B + w_B P、ω_B ← ω_B + I_B⁻¹ (r_B × P)、v_A ← v_A − w_A P、ω_A ← ω_A − I_A⁻¹ (r_A × P) であり、相対速度の向き u の成分の変化は |P| · w̃_u(w̃_u = w̃_A,u + w̃_B,u は向き u で組んだ一般化逆質量の和 [1/kg])である。

```text
動摩擦(滑走中の接触点だけ):   t̂ = v_t ÷ |v_t|、j_t = min(μ_d λ_n ÷ h, |v_t| ÷ w̃_t) [N·s]、P = −j_t t̂
                              μ_d λ_n ÷ h [kg·m ÷ s] は法線反力 f_n = λ_n ÷ h² [N] が細分の時間 h の間に与えうる摩擦の衝撃の上限であり
                              |v_t| ÷ w̃_t [m/s ÷ (1/kg)] は接線の相対速度を零にする衝撃である
反発:                          j_n = (−v_n + max(−e · v_n⁻, 0)) ÷ w̃_n [N·s]、P = j_n n
                              v_n⁻ [m/s] は細分の予測の前(外力の速度更新の後)の法線相対速度、e は反発係数
低速の抑制:                    |v_n⁻| ≤ v_閾値 なら e = 0                                   v_閾値 の初期値は 2 · |g| · h(1細分の自由落下で付く速度の2倍)
```

反発係数 e は0以上1以下、動摩擦係数 μ_d は0以上μ_s以下であり、判断15の混合則が与える。既に離れていく接触(v_n > 0 で d ≥ 0)へ反発を再注入しない。v_閾値 と後述の休止の閾値は `blitz_sim::contact` の定数の1箇所に置き、値の根拠を行末に書き、箱の塔と落下球の実測の日に確定する。

オーナーの要求3(反発は低速接触を不安定化させない)と追加設計の第5節(反発は速度レベル)、Issue #5の横断裁定(速度レベルで扱うほうが自然な現象はXPBD後段の速度処理として正式に許可)の実装形である。反発と動摩擦は衝突前の速度を参照する現象であり位置だけからは書けない。式を衝撃で書くのは、本設計が単位を型で強制するためである。判断8の2020年の論文の式は質量を無次元として係数を省いており、その形(h μ_d |f_n| と |v_t| を直接比べる)は速度と衝撃を比べることになって単位が合わない。衝撃の上限 μ_d λ_n ÷ h と、速度を零にする衝撃 |v_t| ÷ w̃_t の小さいほうを採ると、クーロン摩擦の上限の中で接線の相対速度を止める動摩擦になる。ニュートンの反発則 v_n⁺ = −e v_n⁻ は落下球の跳ね返り高さ h' = e² h という解析解と直接突き合わせられる。低速の抑制は、重力由来の微小な接近速度を衝突と誤認して静置した箱が毎刻み微小に跳ねることを断つ。

ポアソン型(圧縮と復元の2相)は解析解との突き合わせが直接できないため捨てる。動摩擦を全接触点へ常に適用する案は、静止摩擦が保持している接触点に速度段階が抵抗を重ねる。反発の閾値を刻み幅と無関係な定数にする案は、細分数を変えると1細分の自由落下の速度が変わり閾値の意味が壊れる。速度の変化で式を書く案(|Δv_t| = min(w̃_t μ_d λ_n ÷ h, |v_t|))は同値だが、分配の式が速度を衝撃へ戻す割り算を持つため、衝撃で書く形を採る。

機械で強制する方法として、速度段階は非貫通と摩擦の射影と別のモジュールであり、位置と姿勢を書き換える口を持たない(速度と角速度だけを書く)。衝撃は `blitz_math` の衝撃の型で持ち、速度との比較はコンパイルで落ちる。検査は、落下する箱の跳ね返り高さが e² h と相対誤差3パーセント以内であること、e = 0.8 の箱を静置しても3600刻みで跳ねないこと、滑走中の箱の減速度が g(sin θ − μ_d cos θ) と相対誤差1パーセント以内であること、接線の相対速度が1細分で零になる衝撃より上限が小さいときだけ上限が効くこと、を固定する。

### 判断15: 接触物性は両表面の物性から混合則で決め、既定則と材質対の上書き表を持つ

表面物性は静止摩擦係数 μ_s・動摩擦係数 μ_d・反発係数 e の3つを持つ型であり、生成が 0 ≤ μ_d ≤ μ_s と 0 ≤ e ≤ 1 と有限を検査する。世界の形と衝突基盤の判断10のとおり、衝突形状の子形状が表面物性への参照(不透明な材質の識別子)を持ち、剛体の台帳が材質の識別子から表面物性を参照する表を持つ(静的世界の接触相手の材質の識別子も同じ表で参照する)。接触1つの接触物性は、混合則の型が2つの表面物性から作る。既定則は摩擦が相乗平均 √(μ₁ μ₂)(静止と動それぞれ)、反発が最大値 max(e₁, e₂) である。材質対ごとの上書き表を混合則の型が持ち、対が登録されていればその値を返す。混合則は可換である(引数の順で結果が変わらない)。ゲーム固有の材質の名前(木・氷・ゴム)は `blitz_sim` へ持ち込まず、識別子は番号である。

オーナーの要求4(接触物性は接触する両者から決まる。木×木・木×氷・ゴム×石で異なる接触特性を作れる)と追加設計の第6節の実装形である。混合則に物理的な正当性は無く(摩擦係数と反発係数は本来「材質の対」の性質である)、既定則は挙動の既定値であって物理法則ではないため、対ごとの上書きの口を最初から置く。相乗平均は μ = 0 との混合が0になり(氷の上では相手に依らず滑る)可換である。反発の最大値は、よく弾む側が知覚を支配する(よく弾む球は床の材質に依らず弾む)。

算術平均は氷(μ = 0)と木の混合が木の半分の摩擦になり、氷の上で滑らないため捨てる。最小値は反発でよく弾む球が硬い床で弾まなくなる。混合則を1つに固定して上書きの口を持たない案は、オーナーの要求4の「優先指定」の候補を閉じる。

機械で強制する方法として、混合則は物性の型のメソッド1箇所であり、接触拘束の生成だけがそれを呼ぶ。検査は、既定則の可換性を全順序の対で確かめること、μ_d > μ_s と e > 1 が生成で落ちること、上書き表の登録が既定則より優先されること、を固定する。表面物性の参照が登録されていない材質の識別子は接触拘束の生成で型付きエラーになる(黙って既定の物性を当てない)。

### 判断16: 接触の履歴は参加者の組ごとに特徴の識別を鍵に全順序の併走で対応付け、暖機はしない

接触の履歴は接触拘束のバッチ(判断11)と同じ2つに分かれる。剛体と剛体の履歴の鍵は(剛体Aの識別子, 剛体Bの識別子, 接触の特徴の識別)の3つ組であり、A < B に正規化する。剛体と静的世界の履歴の鍵は(剛体の識別子, 静的世界の接触相手の識別子, 接触の特徴の識別)である。接触の特徴の識別の型(`直方体どうしの接触の特徴の対`・`直方体と三角形の接触の特徴の対`)へ全順序を与え、履歴は鍵の昇順に並べた固定長の一覧で持つ。細分ごとに新しい接触点集合の鍵を昇順に並べ、前の履歴と併走して対応付ける(鍵が一致すれば継続、履歴にだけあれば終了、新しい側にだけあれば開始)。継続する接触が引き継ぐのは2つである。静止摩擦の錨(判断13)と、前の細分の接触法線(法線の急変を検出して錨を置き直すのに使う)である。法線のラグランジュ乗数は細分の開始で0へ初期化し、前の細分の値から始める暖機はしない。特徴の識別が変わった接触は新規として扱い、古い履歴を引き継がない。履歴は刻みを跨いで剛体の台帳が保持し、剛体の破棄と運動種別の遷移でその剛体を含む履歴を捨てる。

裁定候補15(接触点集合の時間継続)とオーナーの要求6(前刻みの接触を利用できる)、追加設計の第7節(接触履歴)の実装形である。世界の形と衝突基盤は特徴の識別を「次の刻みで同じ接触を見つけ直すための綴りであり、追跡そのものは拘束の解法の担当」と定めており、本判断がその担当である。全順序の併走は確保を起こさず、順序が入力だけで決まるため決定的である。暖機をしないのは、細分が収束を担うため(判断19)乗数の持ち越しが要らず、XPBD共通拘束基盤の判断5(既定では刻みを跨がない)に従うためである。暖機が要る日は、刻み幅の変化に対する尺度の変換を含めて別の仕様を書く。

接触点の世界位置の距離で対応付ける案は、閾値が挙動へ漏れ、箱の面が滑って隣の特徴へ移ったときに誤対応するため捨てる。ハッシュ表で対応付ける案は確保を起こし、走査の順が実装の詳細に依る。乗数の暖機は、Issue #7の裁定材料が「温存を無効化すると挙動が別物になる」と述べたとおり反証の独立性を下げる。

機械で強制する方法として、接触の特徴の識別の型へ `Ord` の導出を `blitz_collision` で足す(値の並びに意味は無く、決定的な全順序であればよい)。履歴の型は鍵の昇順を生成で検査し、併走の関数は2つの昇順の一覧だけを受ける。検査は、箱を床の上で1メートル滑らせても面と面の接触の錨が滑走の判定まで保たれること、特徴が変わった接触が新規になること、を固定する。

### 判断17: 接触島は動的剛体の連結成分であり、島の中の反復の順序は鍵の辞書式昇順である

接触島は、接触拘束と関節(Issue #41)で結ばれた動的剛体の連結成分である。静的と運動学的の剛体と静的世界の接触相手は島を結合しない(壁を挟んだ2つの箱は別の島である)。島は細分ごとに接触拘束の生成の後に組み直す(連結成分の併合は接触の数に対して線形である)。島の中の拘束の反復の順序は、剛体と静的世界の接触拘束を鍵(剛体の識別子, 静的世界の接触相手の識別子, 特徴)の昇順で先に、剛体と剛体の接触拘束を鍵(剛体Aの識別子, 剛体Bの識別子, 特徴)の昇順で次に、関節をその後に同じ規則で並べる。島の順序は含まれる最小の剛体の識別子の昇順である。CPUの参照計算は島の中を逐次(`反復の更新の順序::逐次`)で解き、並列化は島の間だけに許す。島は反復・休止と再開・並列化・デバッグ表示の論理単位であり、データを1つの配列へ混ぜることは要求しない。GPU化のために島を消さない。

裁定候補16(接触・拘束で繋がった剛体群を独立な問題の単位へ分ける)と追加設計の第8節の実装形である。逐次の反復は順序で結果が変わるため、順序を契約に書かないと検収決定性が実装の詳細に依る。動く形の空間索引が列挙を識別子の昇順に固定したのと同じ規律である。静的世界との接触を先に解くのは、床との接触が塔の土台であり、逐次の反復では最後に解いた拘束がその細分の配置を決めるため、土台を先にして上の箱の接触を後にするほうが積み上がりが沈みにくいからである。島の間の並列は、島がデータとして独立であるため決定性を壊さない。

島を刻みの頭に1回だけ組む案は、細分の中で新しく触れた対が島を結合できず、反復の順序が細分の途中で崩れるため捨てる。島を持たず全接触を1つの列で解く案は、離れた物体群の休止を個別に行えず、並列化の単位が無い。

機械で強制する方法として、島の型は含まれる剛体と2つの接触拘束のバッチの添字の区間を持ち、反復は島を1つ受けて島の中の拘束だけを読む関数である。検査は、離れた2つの箱の塔が別の島になること、静的な床を挟んだ2つの箱が別の島になること、同じ配置から2回組んだ島の順序と拘束の順序が一致すること、を固定する。

### 判断18: 休止は島の単位で行い、物理の結果を変えない最適化として再開の条件を型で持つ

島の全部の動的剛体が静穏(|v| ≤ v_休止 かつ |ω| ≤ ω_休止 かつ その剛体の全接触の貫通が接触余白以下 かつ 静止摩擦の錨が置き直されていない)である細分が連続して N_休止 個続いたとき、島を休止させる。休止した島の剛体は予測・接触点集合の生成・反復・速度段階を省略し、速度と角速度を0にして配置を保つ。動く形の空間索引には載り続ける。再開の条件は6つであり、いずれかで島全体が起きる。作用の投入(判断6)・起きている動的剛体または速度が0でない運動学的剛体との新しい接触(候補の対に現れ、接触点集合が空でない)・拘束(関節・目標拘束)の着脱・運動種別の遷移(判断7)・剛体の生成と破棄を含む構造変更・その島の剛体が触れうる区域の読込の完了(未決定の事項2)である。休止している島どうしの対は接触点集合を作らない。閾値(v_休止・ω_休止・N_休止)は判断14の定数と同じ1箇所に置き、初期値の候補を v_休止 = 0.01メートル毎秒・ω_休止 = 0.05ラジアン毎秒・N_休止 = 60細分とし、箱の塔の実測の日に確定する。

裁定候補17(休止は接触島との整合を取る)とオーナーの要求9(休止は性能最適化であり物理法則を変えない。安定した接触島はまとめて休止でき、外力・衝撃・接触相手の運動・運動学的物体・拘束変更で正しく再開する)の実装形である。速度が小さい1個の剛体だけを休止させると、積み上がった上の箱が休止したまま下の箱が動く不整合が起きる。「物理の結果が本質的に変わらない」の意味は、休止に入る閾値が速度を0とみなせる範囲(1細分で接触余白より小さく動く速度)であることで担保する。

剛体ごとの休止は上の理由で捨てる。休止した剛体を索引から外す案は、起きている剛体との新しい接触を検出できず再開の条件が壊れる。休止の判定に拘束誤差を使わず速度だけを使う案は、貫通したまま速度0で休止する状態を許す。

機械で強制する方法として、実行状態(判断2)は「起きている」「休止している」の2枝であり、休止の判定と再開は台帳のメソッドが島を受けて行う。検査は、箱10段の塔が600刻み以内に休止すること、休止した塔の最下段の箱へ衝撃を加えると塔の全部の箱が起きること、運動学的な床が動き出すと上の箱が起きること、休止の有無で1000刻み後の配置が接触余白以内で一致すること、を固定する。

### 判断19: 剛体は基本刻みを整数nで細分し、細分1本の中で予測・接触・反復・速度再構成・速度段階を回す

剛体のシミュレーションは時間の規律の判断5の「固定刻みで必ず進む」区分に属し、基本刻み H = 1/60秒を整数nで細分する(同判断7の規律4条。最初の利用者)。nと1細分あたりの反復回数は剛体の品質方針として `blitz_app` のコンポジションルートが時間進行方針と同じ様式で注入し、実行負荷で変えない。初期値の候補は n = 8・反復回数1(反復を増やすより細分を増やすほうが同じ計算量で誤差が小さいという判断8の2019年の結果に基づく)であり、箱の塔の実測の日に確定する。物理刻み1本の工程は次のとおりであり、XPBD共通拘束基盤の判断8の工程3〜9を細分の中で回す形である。

```text
物理刻み(基本刻み1本)
├─ 工程1: 構造変更の反映(生成と破棄・運動種別の遷移・拘束の着脱)
├─ 工程2: 作用の蓄積器の取り出し(判断6)。力と回転力は一刻みの入力として保持し、衝撃と回転衝撃は1度だけ適用する型として最初の細分へ渡す
├─ 細分 × n
│  ├─ 衝撃の適用(最初の細分だけ。v += w P、ω += I⁻¹ L)
│  ├─ 予測(判断8。前の状態の保存を含む。力と回転力は h ずつ積分する)
│  ├─ 索引の更新と候補の列挙(判断11。細分の変位で伸ばした箱)
│  ├─ 接触点集合の生成と履歴の対応付け(判断11・16)、島の構築(判断17)
│  ├─ 乗数の零化と刻み依存量の導出
│  ├─ 反復 × 反復回数: 非貫通(判断12)→ 静止摩擦(判断13)→ 関節(Issue #41)、島ごとに判断17の順序
│  ├─ 速度と角速度の再構成(判断9)
│  └─ 速度段階(判断14。反発・動摩擦)
├─ 休止の判定(判断18)
└─ 刻み境界の確定(配置の2枚の繰り上げ。描画補間へ供給)
```

細分の途中の配置は刻み境界の外へ公開しない。描画と世界の形への問い合わせは刻み境界の確定した配置だけを読む。描画補間(時間の規律の判断6)は剛体の物体原点の配置を供給値として前と現在の2枚で持ち、台帳が刻みごとに繰り上げる。刻み幅の綴りは時間の規律の正本(`crates/blitz_app/src/game/step_seconds.rs`)からコンポジションルートが受け取り、細分の刻み幅 h = H ÷ n をXPBDの `刻み幅` 型として作る。

時間の規律の判断7(内部細分の規律4条)と、Issue #7の裁定材料の案B(位置基準XPBD + 細分刻み)の実装形である。細分が収束を担うため、乗数の暖機(判断16)と多数の反復が要らない。反復と細分の回数を固定にするのは、毎刻みの費用が読めること・決定性の検証が単純であること・収束判定の分岐が挙動を入力の差で不連続にしないこと、の3つの理由による。衝撃を最初の細分だけへ渡すのは判断6のとおりである。

細分せず反復回数を増やす案は、同じ計算量で位置の誤差が桁で大きい(上の2019年の結果)ため捨てる。収束判定で反復を打ち切る案は上の理由で捨てる。細分の途中の配置を描画へ渡す案は時間の規律の判断7の第3条に反する。

機械で強制する方法として、細分の工程は `blitz_sim` の一刻みの工程の宣言として関数の列で書き、順序の検査(布の `constraint_stage_tests.rs` と同じ様式)で固定する。nと反復回数は正の整数だけを持つ型で受け、0を生成で拒む。検査は、n を 4・8・16 と変えたとき箱の塔の定常の貫通が接触余白以下で変わらないこと(コンプライアンス0の硬い接触では細分数が硬さを変えない)、一定の力 F を1刻み加えた剛体の運動量の変化が n に依らず H·F であること、衝撃 P を加えた剛体の運動量の変化が n に依らず P であること、を固定する。

### 判断20: 連続衝突は剛体ごとの方針で選び、初回接触時刻を得たらその位置で接触拘束を作って同じ反復へ入れる

剛体ごとに連続衝突の方針を3枝の列挙で持つ。離散の接触だけ・掃引を使う・自動で昇格する(1細分の変位の長さが自分の形の最小の厚みの半分を超えたら掃引を使う)である。掃引を使う細分では、予測の後・接触点集合の生成の前に世界の形と衝突基盤の動く形の対の問い合わせ(平行移動の還元)で触れるまでに進んだ割合 t* を得て、剛体の配置を x_前 + t* h v(姿勢は q_前 から t* h ω だけ回した位置)で接触点集合を作り、その接触拘束を同じ細分の反復へ入れる。非貫通の拘束が通り抜けを止め、残りの時間は同じXPBDの反復が解く。別の物理経路へ分岐しない。Issue #40は離散の接触だけを完成させ、方針の型と工程の位置だけを置く。回転を含む連続衝突(保守的前進)は同基盤の未実装のままであり、回転の速い薄い物体の通り抜けは初版の仕様の外である(未決定の事項3)。

オーナーの要求7(高速物体は必要に応じて連続衝突へ接続でき、全剛体へ常時は強制しない)と追加設計の第9節(離散のみ・掃引を用いる・自動昇格を選択可能にし、TOIを得ても別物理エンジンへ分岐せず残り時間のXPBD接触問題へ接続する)の実装形である。接触拘束を初回接触の位置で作ると、XPBDの片側拘束が「その位置より先へ貫通しない」を保証し、時刻で刻みを割る必要が無い。判断11の伸ばした箱は細分の終点で重なる対を候補から落とさないことだけを保証し、細分の途中で触れて終点では通過し終えている対を止めるのは本判断の掃引だけであるという分担である。したがって初版(離散の接触だけ)では、1細分で相手の厚みを越えて動く剛体の通り抜けは仕様の外である。

初回接触時刻で細分を分割する案は、島の中の他の剛体の時刻が揃わなくなり工程が複雑になるため捨てる。全剛体へ掃引を常時強制する案はオーナーの要求7に反する。掃引の結果で位置を初回接触の位置へ戻して速度を落とす(接触拘束を作らない)案は、反発と摩擦が速度段階で扱えない。

機械で強制する方法として、連続衝突の方針は剛体の型のフィールドであり、生成時に与える。掃引の呼び出しは候補の列挙の工程の中の1箇所である。検査(Issue #40の完了後)は、秒速50メートルの薄い箱(厚み0.02メートル)が厚み0.05メートルの静的な板を「掃引を使う」で通り抜けず「離散の接触だけ」で通り抜けること(方針の差が挙動に出ること)を固定する。

### 判断21: 極端条件を仕様の対象として目録に置き、保証の範囲と保証の外の態度を分ける

裁定候補18の10条件を検証の目録へ置く。保証するのは「非数を出さない・発散しない・不正な状態(長さが1でない姿勢、負の乗数、上限を超えた接触点)を作らない」であり、条件ごとに初版の保証の範囲を次のとおり定める。

```text
初期の重なり                    有限の細分数で回復する(判断12)。回復の細分数は形の最小の厚みと細分数で決まり、検収が上限を持つ
極端に重い物体と軽い物体        質量比100:1まで塔が発散しない(崩れてよい。崩れ方が漸近的であること)。それを超える比は非数と発散だけを保証する
非常に小さい・薄い物体          形の下限は衝突基盤の型(半径2^-24メートル・厚み0を拒む)が持つ。剛体は質量特性の下限(主慣性の三角不等式)で受ける
高速移動・高速回転              速度の絶対値の上限を速度の型の生成で課す(1刻みの変位が衝突基盤の座標の上限2^24メートルの1/2を越えない値)。回転の上限は判断7の運動学的の上限と判断8の陰的ジャイロ項
接触面がほぼ平行                接触点集合の側で外積の軸の入れ替えの上界が扱う(衝突基盤の実装順10)。剛体側は複数点の積み上がりの検収で受ける
重心が衝突形状の中心から大きくずれている  判断3と判断4の分離で扱い、偏った重心の物体が転がる検収(Issue #40)で受ける
非対称な慣性                    判断8の中間軸の反転の検収で受ける
同一点付近へ複数接触が集中する  接触点の上限8を型付きエラーで受け、鍵の昇順の反復で順序を固定する
種別の切り替え直後              判断7の遷移で履歴を捨て島を組み直す。切り替えの次の刻みで貫通が接触余白以下へ戻ることを検収する
破壊で複数剛体が生まれる直後    工程1の構造変更として生成し、生成された剛体は起きた状態で始める(Issue #16の日に検収を足す)
```

裁定候補18(初期重なり・極端条件を仕様上の対象から外さない)とオーナーの要求8(極端な質量差を未定義にせず、保証範囲外でも非数・発散・不正状態へ落ちない)の実装形である。保証の範囲を数で書かないと、検収が何を落とすべきか決まらない。

任意の質量比で完全に安定することを要求する案は、重い順に解く追加のパス(衝撃の伝播)を初版に要し、Issue #40の非目標に反するため捨てる。極端条件を「通常は起きない」として未定義にする案は裁定候補18に反する。

機械で強制する方法として、目録の各条件を検収の場面として `cargo xtask` の命令(Issue #40)に登録し、非数と発散の検出は全部の場面で共通に(全剛体の配置と速度が有限で姿勢の長さが1であること)判定する。

### 判断22: CPUの参照計算を正典とし、GPUのレイアウトは剛体の4つのバッファと接触の2つのバッファで契約する

剛体の状態と接触解法のCPUの参照計算が数式の正典であり、`blitz_sim` が持つ。GPU経路(`blitz_render`)はIssue #40の離散の接触が閉じた後にCPUの参照計算と同じ初期条件で突き合わせて導入し(Issue #43)、動的な接触の並列方式はXPBD共通拘束基盤の採用規則2(固定小数の原子加算を第一候補、二段階を代替)に従う。GPUレイアウトは点自由度の32バイトの契約を拡張せず、姿勢自由度の別の密な配列を立てる。バッファは剛体の状態に4つ、接触に2つの計6つであり、毎刻み書き換える量と原則不変の量を混ぜない。

```text
剛体の状態(4つ)
  剛体運動状態バッファ    重心位置 xyz f32 + 詰め物1語・姿勢 xyzw f32・並進速度 xyz f32 + 詰め物1語・角速度 xyz f32 + 詰め物1語(4×16 = 64バイト。実体52バイト、詰め物3語)
  剛体前状態バッファ      前の重心位置 xyz f32 + 詰め物1語・前の姿勢 xyzw f32(32バイト。実体28バイト、詰め物1語)
  剛体質量特性バッファ    逆質量 f32・逆主慣性 xyz f32・主軸 xyzw f32(32バイト。詰め物なし)
  剛体実行状態バッファ    運動種別 u32・起きているか u32 + 詰め物2語(16バイト)
接触(2つ)
  接触拘束バッファ        細分ごと生成。剛体と剛体・剛体と静的世界の2区間を1つのバッファに続けて置く(参加者A添字 u32・参加者B添字または静的世界の接触相手の添字 u32・局所点A xyz f32・局所点Bまたは固定の世界点 xyz f32・法線 xyz f32・物性3 f32・乗数 f32。バイト数はIssue #43のGPU経路で確定)
  接触履歴バッファ        鍵と錨と前の法線(刻みを跨ぐ)
```

1件のバイト数はIssue #39のGPUレイアウト契約の実装で確定し、この判断の下へ追記する。バイト列化は `blitz_sim::gpu_layout::rigid` が持ち、`blitz_render` の読み手は長さと内容(添字の範囲・姿勢の長さ・逆質量の非負と有限)を型付きエラーで検証する。

Issue #39のGPUの節(姿勢自由度のGPUレイアウトは点粒子の32バイトのレイアウトを無理に拡張して同一構造体へ統合しない)と、Issue #7の実装境界のGPU候補レイアウト(運動状態・前状態・質量特性・実行状態の4バッファ)、XPBD共通拘束基盤の判断9(静的な引数と毎刻み書き換える状態を同じバッファへ詰めない)の実装形である。3成分の量を16バイト境界へ置くのは、GPUの構造化バッファの読み出しが16バイト単位で最も速く、詰め物1語の費用がそれより小さいためである。CPUを正典にするのは、追加設計の第8節(CPU参照実装では固定順序の逐次反復を基準実装にしてよい)と実装順10(GPU経路はCPU参照結果と比較して導入)に従う。

剛体を最初からGPUで解く案は、島と履歴と休止の検収をCPUの参照計算なしに行うことになり、XPBD共通拘束基盤の目的2(CPUの参照計算を正典として置き、GPUをそれと突き合わせる)に反するため捨てる。状態を1件128バイトの1バッファへ詰める案は、質量特性の不変の量を毎刻み書き換える帯域に載せる。3成分を詰めずに並べる案(1件52バイト)は読み出しが境界をまたぐ。

機械で強制する方法として、1件のバイト数は `cargo xtask conform` の定数の組で書き手(`blitz_sim`)と読み手(`blitz_render`)を結ぶ(布と同じ運用)。CPUとGPUの突き合わせは許容差つきの比較であり、`cargo xtask` の命令として登録する。

### 判断23: 公開のAPIは剛体の台帳が持つ物理の意味の操作だけであり、強結合は同じ実行領域で同じ反復へ参加する

ゲーム側へ見せるのは剛体の台帳(操作サービス。`blitz_sim` の公開面)の次の操作だけである。生成する(質量特性・配置・運動種別・衝突形状の参照・材質の識別子・連続衝突の方針を受け、剛体の識別子を返す)・破棄する・運動種別を遷移する(判断7)・配置と速度を読み出す・作用を加える(判断6の6操作)・材質を設定する、である。ラグランジュ乗数・反復回数・細分数・接触解法の内部表現・島・履歴は台帳の内部であり、切り替えのためだけの `trait 物理ソルバ` を公開面に置かない。開発用の計器(接触数・島の数・休止している島の数・拘束違反の最大値・乗数の代表値・工程ごとの時間)は読み出しの口を別に持ち、Issue #4の計器盤が読む。Issue #18の強結合(剛体と布・剛体とロープ・剛体と体積弾性体)は剛体と点の拘束のバッチ(判断10)で同じ反復へ参加させ、CPUの剛体とGPUの布のように実行領域を跨ぐ双方向の結合を作らない。どちらの領域へ寄せるかはIssue #43が遅延・反復不能・転送費用を明示して決め、本文書はCPUの参照計算がGPUへ移せるレイアウト契約(判断22)を持つことまでを担う。動く形の空間索引の識別子は `blitz_app` の物理の配線が1つの索引に対して発行し、剛体・キャラクター・破片を上位ビットの名前空間で分ける(未決定の事項1)。台帳は自分の剛体の識別子を索引の識別子へ写す口を持つ。

裁定候補の追加設計の第12節(API境界)とXPBD共通拘束基盤の判断10(公開のAPIへXPBDの内部を漏らさない)、Issue #18の裁定(強結合では1フレーム遅延を許容しない。CPU/GPUを跨ぐが何となく双方向という構成を禁止する)の実装形である。

剛体の型そのものをゲーム側へ渡して直接書き換えさせる案は、正規化・種別の整合・履歴の破棄が運用に落ちるため捨てる。`trait 物理ソルバ` を置く案はXPBD共通拘束基盤の判断10で退けられている。

機械で強制する方法として、剛体の状態の型のフィールドはすべて私有であり、台帳のメソッドだけが書き換える。`blitz_game` は `blitz_math` だけを知る現状を保ち、剛体の台帳を呼ぶのは `blitz_app` の物理の配線である(`cargo xtask conform` の白リスト)。

## 性能予算

剛体はCPUの参照計算が初版の本番経路であるため、`_doc/計画/評価軸.md` 3.6のCPU区間予算へ「剛体の1刻み」の行を暫定値0.5ミリ秒で新設する(Issue #7の追加の論点7。未決定の事項6)。見積りは、細分8本・起きている動的剛体256個・接触点1000点で、接触1点の射影が約50ナノ秒として反復の総量が約0.4ミリ秒である。GPU経路を導入した日(Issue #43)に、シミュレーション(M9、コンピュート)の3.0ミリ秒の内訳として剛体の行を別に立てる。正式な枠はIssue #40の箱の塔の実測の日に実測値の1.4〜1.7倍で確定する(既存の作法)。

測るものは次の6つであり、`cargo xtask` の命令が採る。細分1本の工程ごとの時間(索引の更新と候補の列挙・接触点集合の生成・履歴の対応付け・島の構築・反復・速度段階)・接触点の数と島の数と休止している島の数・剛体1個あたりと接触1点あたりの時間(物量に対する線形性の確認)・細分数を4・8・16と変えたときの時間と定常の貫通(品質と費用の関係)・休止の有無による時間の差(休止が効いていることの確認)・GPU経路の導入後のCPUとGPUの時間の比較、である。剛体の物量の上限(同時に登録できる動的剛体の数)は暫定1024個とし(休止を含む登録数。起きている数は予算が決める)、破片が最大の量産者になるIssue #16で見直す。

## 決定性の保証

- 保証する決定性: 検収決定性とゲーム決定性。CPUの参照計算はさらに数値決定性を持つ(単一スレッドで島の順序と島の中の拘束の順序が鍵の昇順に固定され、確保を起こさず、浮動小数の演算順が入力だけで決まる)。島の間を並列化した実行も、島がデータとして独立であり書く先が自分の島の剛体だけであるため数値決定性を保つ。GPU経路は固定小数の原子加算を採るときに数値決定性を持ち(XPBD共通拘束基盤の採用規則2の実測)、GPUとCPUの参照計算の間は許容差つきの比較である
- 条件: 同じ機械・同じビルド・同じ初期状態・同じ入力系列・同じ刻み数・同じ細分数と反復回数・同じ連続衝突の方針・同じ休止の閾値・同じ並列方式であること。島の間の並列化はスレッド数に依らない(島の結果は他の島に依らない)
- 失効する変化: 細分数または反復回数の変更(コンプライアンス0の硬い接触では定常の配置は変わらないが、過渡の軌跡と乗数の値が変わる)・休止の閾値の変更(休止に入る刻みが変わる)・接触の特徴の識別の全順序の変更(反復の順序が変わる)・浮動小数の原子加算を使うGPU方式(数値決定性を持たない)・接触余白とゆとりの幅の変更(候補の集合が変わる)
- 検収の判定: Issue #40の検収は、同じ場面を2回実行した全剛体の配置と速度のビット一致をCPUの参照計算で課し、GPU経路は許容差(位置1e-4メートル・乗数1e-6。布と同じ)で課す

## 未決定の事項

オーナーの裁定が別の案を採りうる事項である。オーナーの指示(「私が考えるべきところはIssueで決まっているはずなので全部完了するまで止まらずに実装する」)に従い、本文はいずれも推奨の側で確定して進める。オーナーが別の案を採るときはその判断を改める。

1. **動く形の空間索引の識別子の空間を剛体・キャラクター(Issue #3)・破片(Issue #16)で共有する。** 確定した案: `blitz_app` の物理の配線が1つの索引を持ち、識別子の上位ビットで種類(剛体・キャラクター・破片)を分けた名前空間を配線が発行する(判断23)。Issue #18の剛体と布・剛体とキャラクターの対の列挙には1つの索引が要る。別の案: 種類ごとに別の索引を持つ(異種の対の列挙に索引をまたぐ覆いの問い合わせが要り、費用が種類の数だけ増える)。世界(`blitz_engine`)が識別子を発行する(世界が剛体を知る向きになり層の定義に反する)
2. **未読込チャンクの区域に居る(または近づく)動的剛体は島ごと強制的に休止させ、読込の完了で再開する。** 確定した案: 静的世界の候補の選別が「評価できない領域を含む」と答えた剛体を、その細分で島ごと休止させ、その区域の読込が完了した刻みで再開する(判断18の再開の条件の6つ目)。落下を止めるだけであり物理法則は変えない。Issue #17(地形変形)の同型の論点(変形中の区域の上の剛体)も同じ再開の条件で受ける。別の案: ストリーミングが「動的剛体の周囲は常に読込済み」を保証する(必要集合の中心が複数になり、Issue #1の判断8の契約を変える)。落下を続ける(未読込の地面を通り抜けて世界の底へ落ち、読込後に深い初期重なりになる)
3. **回転の速い運動学的剛体(回る床の縁)が薄い物を通り抜けない保証は初版の範囲に含めない。** 確定した案: 世界の形と衝突基盤の連続衝突は平行移動の還元だけであり、回転を含む連続衝突(保守的前進)は未実装である。Issue #40は離散の接触で閉じ、判断20の方針の型だけを置く。別の案: 保守的前進を同基盤へ足してからIssue #40を閉じる(Issue #40の完了が同基盤の追加実装に依存する)
4. **初版の対象形状は箱(任意姿勢の直方体)と静的世界だけである。** 確定した案: 同基盤の接触点集合は直方体どうしと直方体対三角形だけであり、球の形状型は無く、カプセルの接触点集合は未実装である。Issue #40の「球を床へ落とす」「反発0と高反発の比較」は箱で代替し、「球が転がる」(Issue #7の現象)は球の形状型と接触点集合を同基盤へ足した日に検収を足す。別の案: 球を同基盤へ足してから着工する(球対平面・球対直方体の接触点集合は1点であり実装は小さいが、Issue #40の完了が同基盤の追加実装に依存する)。カプセル剛体まで含める(キャラクターを動的剛体として積み・押し合いへ参加させる要求が立った日に採る)
5. **剛体の状態と接触解法の精度は単精度である。** 確定した案: XPBD共通拘束基盤の型(`位置<ワールド>`・`逆キログラム`・`ラグランジュ乗数`)が単精度であり、GPU経路との突き合わせとレイアウト契約が同じ精度で書ける。接触点集合は倍精度で判定して返るため、単精度へ狭めるのは判断11の局所点への写しの1箇所である。別の案: 倍精度(Issue #7の裁定材料の1.8節の推奨。XPBDの型を倍精度で二重に持つか総称化することになり、GPU経路の突き合わせが精度の差を含む)。単精度で箱10段の塔の検収が通らなかった日に、倍精度の参照計算を検収専用に足す
6. **CPU区間予算「剛体の1刻み」の暫定値は0.5ミリ秒、登録できる動的剛体の暫定上限は1024個である。** 確定した案: 性能予算の節の見積りに基づく。値はIssue #40の実測の日に確定し、上限はIssue #16で見直す
