# 時間の規律

ゲーム世界の時間をどう進めるかの設計正本である。基本刻み・実時間との関係・一描画で進める刻み数・描画補間・物理内部の細分・時間源と決定性を定める。Issue #2「ゲーム基盤の壁打ち2: 時間の規律(固定の刻みの敷き方)」のオーナー裁定(2026-09-01)を正本化した。候補と根拠の全文は同Issueの裁定材料コメント(2026-08-28)にある。

この規律が属する層はblitz_appの実行方針の層である。ゲームロジック層(blitz_game群)は刻み幅を`秒`型で受けるだけであり、時間の進め方を知らない。物理の各方式(Issue #5の分類)は、この規律の内部細分と決定性の保証の枠の中で各自の設計正本を書く。用語は`_doc/計画/ユビキタス言語.md`「時間の規律の語彙」に従う。

## 判断1: 基本刻みは1/60秒を維持する

ゲーム世界の基本刻みは固定の1/60秒である。物理計算は処理速度によって刻み幅を可変にしない。より細かい刻みが要る物理方式は、判断7の内部細分で対応する。現行実装・アニメーション時刻の固定歩進・Issue #3の起案の定数がすべてこの値を前提にしており、基本刻みを細かくする理由が無い。ゲームごとの設定にする案は、検収の期待値がゲームごとに割れて決定性の検証装置が複線化するため採らない。

## 判断2: 通常プレイは実時間の蓄積による固定更新へ移行する

通常プレイは実時間を蓄積し、基本刻み1つぶん貯まるごとにゲーム世界を固定刻みで1回進める。可変の巨大な刻み幅を作って追いつく方式は採らない。検収・ベンチは従来どおり実時間を1度も読まず、指定された刻み数だけ進める。

移行する根拠は3つある。(1)現行の「1描画=1刻み」はゲームの進む速さが画面の書き換え頻度に比例するため、毎秒120回書き換わるモニターではゲームが2倍速になる。(2)フレームが落ちると、ゲームが実時間より遅く進む。(3)Issue #5の全物理分類を同一世界で動かす基盤として、刻みの頻度と描画の頻度の分離は前提になる。

## 判断3: 一描画で進める刻み数に上限を置き、時間進行方針として外から注入する

一描画で進める固定刻み数には上限を置く。初期値は4を推奨値として採用するが、4をハードコードしない。基本刻み・一描画で進める刻み数の上限・蓄積の上限・超過分の扱いをまとめた時間進行方針として外から注入できる形にする。これらはゲーム固有ロジックの定数ではなくblitz_app側の実行・性能方針に属する。上限は実測によって2・4・6等へ変更できることを前提とする。

## 判断4: 上限を越えて貯まった実時間は捨てる

上限を越えた過去の蓄積時間は保持し続けず、越える分は捨てる。極端な処理落ちでは、現実時間へ完全に追従することより固定刻みの安定性と復帰性を優先し、ゲーム時間が一時的に実時間より遅れることを許容する。遅れを取り戻すために処理量が増え続ける状態にはしない。捨てないと、恒常的な過負荷で蓄積が際限なく育ち、永遠に上限いっぱいの刻みを回し続けるためである。

## 判断5: 固定刻みの中の必須処理を打ち切らない

固定刻みを一度開始したら、確定したゲーム状態を作るための必須処理を途中で打ち切らない。「入力は適用したが物理は時間切れで省略した」のような半端な刻みを確定してはならない。固定刻みの内部では、ゲーム状態・物理・ゲーム上必要なイベント判定など、確定世界へ影響する処理を最後まで完了させる。

処理落ち時に省略・低頻度化できるのは、確定ゲーム状態の意味を変えない処理だけである。「重くなったら途中から適当に処理を捨てる」のではなく、それぞれの系がどの時間意味を持つかを最初から宣言する。時間意味の区分は4つである。

- 固定刻みで必ず進む: 入力の適用・ゲームロジック・キャラクター衝突・同期的に必要な物理・ゲーム上必要なイベントと状態遷移
- 描画機会ごと(その描画自体をしないなら省略できる): 描画・可視判定・描画補間・一部の視覚効果・デバッグ表示・性能表示
- 独自の頻度を宣言できる: NPCの高水準判断・経路探索・遠方世界の更新
- 非同期でよい: アセットの準備等

布はこの区分の最初の実例である(2026-09-02の1つ目の作業是正で確定)。シミュレーションの工程は「固定刻みで必ず進む」に属してその描画の刻み数ぶん積まれ、頂点生成は時間を進めない工程として「描画機会ごと」に属して1本だけ積まれる。布の刻み1本の長さは基本刻みそのものであり、コンポジションルートが `ゲーム更新の一刻みの秒` から受けた値を布素材の定数(`blitz_render::布の刻み幅`)と参照計算の条件へ注入する(レンダラーは刻み幅の綴りを持たない)。

## 判断6: 描画補間は供給値だけを2枚持って混ぜる

ゲーム状態全体は二重化しない。描画へ渡す連続量(動く個体の大域の位置と向き・カメラの注視点等)について、前の確定値と現在の確定値を保持し、蓄積の余りを基本刻みで割った割合で混ぜて表示する。向きは最短の弧で角度を混ぜる。補間した値を次のゲーム・物理更新の入力へ戻さない。

ゲーム状態全体を2つ持つ案を採らないのは、複製の費用を毎刻み払ううえ、補間してよい量(見た目の連続量)と補間してはならない量(進行段階・判別の枝)の区別を型でなく運用で守ることになるためである。

割合の向きは2026-09-02の2つ目の作業の実装で確定した。割合は前の確定値から現在の確定値へどれだけ進んだ位置を描くかを表し、0で前の確定値、1で現在の確定値である。したがって蓄積器を持たない実行が答えるのは1(`現在の確定値そのもの`)であって0ではない。実時間の経路では余りが増えるほど描く位置が前の確定値から現在の確定値へ進むため、0の側が前の確定値になる。ここを逆に取ると、余りが増えるほど描く位置が現在の確定値から前の確定値へ戻り、刻みが確定するたびに2刻みぶん前へ跳ぶ鋸歯になる。検収の経路が求めているのは「補間が現在の確定値そのものになること」であり、その不変は割合の数値ではなく、蓄積器を持たない枝がこの名前の値だけを答えることで機械的に保たれる。

繰り上げは描画ごとではなく刻みごとに行う。混ぜる2枚は必ず1刻みぶんだけ離れている必要があり、描画ごとに1回だけ繰り上げると、4本進めた描画の2枚が4刻みぶん離れて、1刻みぶんの割合で混ぜた値が2枚の間の正しい位置にならない。刻みを経ずに位置を跳ばす局面(高さ場を据えて世界の中心へ置き直す等)は、繰り上げではなく2枚とも据え直す。繰り上げで据えると、跳ぶ前と跳んだ先を混ぜた位置が1描画だけ描かれ、個体が跳んだ距離の途中に現れる。

カメラの注視点は混ぜた位置を読み、ストリーミングの必要チャンク集合の中心は刻み境界の確定位置を読む。2つを分けるのは、常駐するチャンクの集合がゲームの読む高さ場を決めるためであり、混ぜた位置をそこへ通すと、描画のためだけに作った値が次のゲーム更新の入力へ回り込む。混ぜた注視点はヨー・ピッチ・距離を1つも書き換えないため、次のゲーム更新が前へ進む向きとして読むヨーは補間の影響を受けない。

## 判断7: 物理内部の細分の規律4条

1. 物理方式はゲームの1刻みを整数nで分割できる。
2. nは物理方式ごとの品質・実行方針として外から与え、実行負荷に応じて勝手に変動させない。
3. 細分の途中状態を刻み境界の外へ正本として公開しない。描画も世界の形への問い合わせも、刻み境界の確定状態だけを見る。
4. 異なる物理方式どうしが細分中のどの頻度で相互作用を交換するかは、各方式の下位Issueで決める。

実装の細目(2026-09-04、Issue #40の3つ目の作業): 最初の利用者である剛体が4条を実装した。第1条の分割は `細分数` という正の整数だけを持つ型で受け、細分の刻み幅 h = H ÷ n を `刻み幅` として持つ。第2条のnと反復回数は `接触の品質と時間方針` が起動時に受け取って以後変えない。第3条は、細分の途中の配置を工程の中の予測の状態にだけ持ち、刻み境界で確定した配置だけを台帳の剛体へ書き戻す形で守る。第4条は、剛体の内部に他方式との交換が無いためこの作業では扱わない。実装は `crates/blitz_sim/src/contact/pipeline/` にあり、判断の正本は `_doc/設計/剛体の状態と接触.md` の判断19である。

## 判断8: 時間源と決定性

実時間を読む場所は実時間の蓄積器の責務へ閉じる。通常プレイと検収・ベンチの時間源は実行方針として分離し、実行の種類で1度だけ選ぶ(カメラ操作の適用方針・自動露出の経過秒と同じ様式)。時間源をトレイトで差し替える案は採らない。同型の判断が既に2つあり、どちらもenumの方針型で書かれているため、同じ様式で揃えるためである。

決定性は3種類に分けて呼ぶ。

- 検収決定性: 同じ機械・同じ実行条件で指定フレーム数を再実行したとき、検収の合否と読み戻しの値が一致すること
- ゲーム決定性: 同じ初期状態と同じ入力系列から同じゲーム上の結果になること
- 数値決定性: 並列計算の順序まで違っても数値がビット単位で一致すること

全方式が最低限守るのは検収決定性とゲーム決定性であり、数値決定性は既定では要求しない(保証する方式だけが明示する)。各物理方式の設計正本には「決定性の保証」の節を必須で置く。保証の文は「どの決定性を・どの条件で(同じ機械・同じスレッド数・同じ品質設定等)・何が起きると失効するか」の3点で書く。この節が無い正本はレビューで落とす(性能予算の記載が無い正本を落とすのと同じ運用)。

## 判断9: 一描画と一刻みを同一視しない

現行の1描画単位の実行順序(入力確定→世界更新→カメラ等→描画内容抽出→描画)を、描画機会の中で必要な数だけ固定刻みを進める形へ分離する。

```text
描画機会
├─ 入力確定
├─ 必要数だけ固定刻みを進める
│  ├─ 刻み1
│  ├─ 刻み2
│  └─ ...
├─ 描画用状態を組み立てる
└─ 描画
```

巨大な共通ライフサイクルを増築すること自体を目的にしない。固定刻みで必ず進むもの・描画機会ごとのもの・低頻度でよいもの・非同期でよいものという時間意味を分離して設計する。ループの所有権は変えない。実時間の蓄積器は1回の描画機会で固定刻みを何回進めるかを決めるものであり、描画機会そのものの頻度には触れないため、winit所有のループ(パターンA)のままで成立する。`参照: _doc/設計/イベントループとフレームペーシング.md`「判断の記録」。

## 入力の規律(判断2の随伴)

1描画で確定した操作入力とカメラのヨーは、その描画で進める刻みへ配る。入力の確定は描画の頻度で行われるため、刻みごとに入力を取り直す形にはできない。この規律がゲーム決定性の「入力系列」の定義になる。アニメーション時刻と天空の進行も「その描画で進めた刻み数×基本刻み」へ追随させる。

配り方は操作の種類で2つに分かれる(2026-09-02、1つ目の作業の実装時に親裁定で確定)。

- **押下が続く操作と連続量は、その描画で進めるすべての刻みへ同じ値で配る。** 移動の4つの操作とカメラのヨーがこれにあたる。押している間ずっと意味を持つ量であり、刻みが4本進んだ描画で1本ぶんしか歩かないと、移動だけが実時間より遅れる。
- **押した瞬間の操作は、その描画の最初の刻みだけへ配る。** 決定と取り消しがこれにあたる。押し下げが届いたことを表す1回きりの値であり、すべての刻みへ同じ値で配ると1回の押し下げが刻みの本数だけ発火する。処理落ちで刻みが増えた描画ほどタイトルから終了確認まで速く流れることになり、進行段階がゲームの時間ではなく処理落ちの量で決まってしまう。

配り終えたかは配る器が覚え、呼び出し側が刻みの番号を比べる形にしない。番号の比較で守る形は、刻みを回す繰り返しを書き換えたときに1回きりという規律が静かに壊れるためである。実装は`crates/blitz_app/src/input/tick_distribution.rs`にある。

**刻みを1本も進めない描画では、操作入力を確定しない。** 確定は押した瞬間の操作の押し下げの旗を消費するため、刻み0本の描画で確定すると、その旗が刻みへ配られないまま消える。毎秒120回書き換えるモニターでは刻み0本の描画が半分を占め、押して次の刻みより前に離した操作がゲームへ一度も届かない。無期限実行の最初の描画は必ず0本のため、起動直後の押し下げにも同じ穴が開く。旗は最初の実刻みまで入力状態が保持する。
