# ゲームEsca 設計正本

本書は、ゲーム『Esca（エスカ）』のコンセプト、テーマ、世界観、登場人物の役割、ゲーム性の核、およびコード上の型契約を定める設計正本である。

本書の記述は、トップダウンでゲームドメインから最下層のエンジン構造まで完全に開発者の理解とコントロールを取り戻すための指針として運用する。

---

## 1. 開発方針と制作スタイル

### 1.1 理解負債の解消と主客の回復
過去のAI駆動開発で生じた「動くが人間が中身を把握しきれていない」という理解負債を解消する。
AIに一度に大量のコードを書かせず、人間によるマイクロマネジメント（1ステップあたり最大3ファイル修正）のもと、1つ1つのドメイン概念、型、状態遷移を完全に理解・納得しながらトップダウンで組み上げる。

### 1.2 ゲームドメイン主導の垂直貫通
汎用的な仕組みを先行して作らない。まず「Escaというゲームを成立させるための具体的な型とルール」を定義し、それを表現するために必要な分だけエンジン機能（数学、物理、地形、描画）を順次接続していく。

---

## 2. コンセプトとテーマ

### 2.1 一行コンセプト
戦火または混乱に陥った国を、戦えない旅行者として脱出を目指す逃亡・旅行劇。

### 2.2 テーマ
「観察と判断による生存」と「旅路の記憶」。
暴力による問題解決を行えない非戦闘員が、世界の状況を観察し、限られた情報と移動手段をやりくりして危機をかいくぐる。

### 2.3 ゲーム性の核
1. **非戦闘の行動選択**:
   敵を倒すのではなく、観察、交渉、回避、逃走によって事態に対処する。
2. **状況の推移と経路の変動**:
   旅の進行や時間経過に伴い、安全だった道が封鎖され、あるいは新たな抜け道が開かれ、迂回や引き返しが発生する。
3. **旅路の記録**:
   単なる脱出作業にとどまらず、旅の中で見聞きした土地の風景や人々の営みを心と記録に残していく。

---

## 3. 登場人物の基本構図

### 3.1 主人公（プレイヤーの分身・観察対象）
- **属性**: 非戦闘員の旅行者。
- **能力**: 武器を扱って敵を制圧する力は持たない。周囲の状況を注意深く見極める観察力、地形を把握する移動の判断力を武器とする。
- **意志**: 恐怖に震えながらも、生き延びること、そしてこの旅の真実を見届ける意志を持つ。

### 3.2 相棒（旅路を共にする存在）
- **属性**: 旅の途中で合流する同行者。
- **関係性**: 一方的に守られるだけの存在でも、主人公の都合で動く道具でもない。互いの事情と意志を尊重し合いながら、同じ目的地を目指して協力する対等なパートナー。

## 4. プログラミング設計オントロジーと規約

### 4.1 役割マーカー（直交概念）
- **`MDTO`**: 境界を越える純粋データ。参照・ポインタ・内部可変性を持たず、`Clone` を導出する。
- **`M状態`**: 実在し保持・遷移されるゲーム状態。必ず `MDTO` を実装する（状態 is a DTO）。
- **`Mコマンド`**: 主体の意志・選択肢・命令。必ず `enum` で定義し、`&mut self` を持たない。
- **`Mイベント`**: 世界に生じた一過性の出来事・過去の事実。`Clone` を導出し、`&mut self` を持たない。
- **`M規則`**: 世界を律する不変法則・ポリシー。必ず `struct` で定義し、`&mut self` を持たない。
- **`M入力`**: デバイス境界の生シグナル（キー・マウス・ボタン）。ゲーム意味論を持たず、必ず `MDTO` を実装する。
- **`M遷移関数<状態, コマンド, 規則, イベント>`**: `(&状態, &コマンド, &規則, 秒数) -> (状態, Vec<イベント>)` を導出する純粋計算の関数型（fn）。Rust言語仕様上型エイリアスのトレイト境界が強制されないため、構文解析器(Law 7)が静的型宣言 `const _: M遷移関数<...> = 関数;` を走査し、オントロジー4大要素を満たすことを機械検証する。
- **`M射影関数<状態, 射影DTO>`**: `&状態 -> 射影DTO` の一方向観測計算の関数型（fn）。構文解析器(Law 8)が静的型宣言 `const _: M射影関数<...> = 関数;` を走査し、状態とDTOであることを機械検証する。
- **`M解釈関数<入力, コマンド>`**: `&入力 -> コマンド` の純粋解釈計算の関数型（fn）。構文解析器(Law 9)が静的型宣言 `const _: M解釈関数<...> = 関数;` を走査し、入力とコマンドであることを機械検証する。
- **`オントロジートレイト`**: 上記の各マーカートレイトを型安全に照合するための列挙型（enum）。文字列リテラルによるタイポを防ぎ、構文検査を有限集合として厳格化する。

### 4.2 引数DTOと名前付き引数様式（2026-09-18制定）
同型プリミティブが並ぶ引数は順序誤認の温床となるため禁止する。引数はDTO構造体に束ね、構造体リテラル直接呼び出し `(要求DTO { ... }).メソッド()` で呼び出す。

### 4.3 抽象度レイヤーの純化（シナリオ層とメカニズム層の混在禁止、2026-09-18制定）
シナリオ層（進行フロー、画面の流れ、テストケース等）に、それを支える道具・構文解析・計算・固有データ型等のメカニズム層を同居させてはならない。100行未満であっても抽象度レイヤーの異なるコードの同居を禁止し、メカニズムは独立モジュール（`syntax_checker.rs` 等）として分離してシナリオ層を純化する。

## 5. 今後の展開ステップ

1. **第1段階**: 主人公の基本移動と観察（歩行、地形との接触、視界）。
2. **第2段階**: 地点と経路の表現（どこへ向かうか、どの道が通れるか）。
3. **第3段階**: 状況の進行とイベント（何が起き、どう選択肢を選ぶか）。
4. **第4段階**: エンジンへの接続（カメラ、高さ場地形、描画への配線）。
