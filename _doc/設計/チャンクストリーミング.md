# チャンクストリーミング

この文書は、OW2で大域世界の必要部分だけを読み込み、不要部分を安全に解除する契約を管理する。実装と常に一致させて維持する。

## 所有境界

blitz_engineはプレイヤー位置から必要チャンク集合と優先順を決める。後続段でディスク読込とデコード済みデータの準備も所有する。blitz_renderはGPU転送とGPU使用完了後の資源解放だけを所有し、どのチャンクが必要かを判断しない。blitz_appは位置、予算、フレーム境界を配線するだけである。

## チャンク格子

世界はXZ平面を正方形へ分割する。一辺長は0より大きい有限の大域メートルであり、プレイヤーのXとZを一辺長で割って床を取ったi32整数2成分をチャンク座標とする。負座標をゼロ方向へ丸めないため、X=-0.1mは一辺100mならX=-1のチャンクに属する。

チャンクIDはXの32ビット表現を上位、Zの32ビット表現を下位へ格納したu64である。負値を含む異なる座標は異なるIDになり、ファイルパスや実行順に依存しない。

## 必要集合と優先順

先読み半径はu8のチェビシェフ距離で表す。半径0は所属チャンクだけ、半径1は中心と周囲8チャンクである。必要集合は中心を最初に置き、距離1、2の外周へ広げる。同じ外周ではZ差、次にX差の昇順とし、同じ入力から同じ読込要求順を得る。

一辺長の不正、非有限な大域位置、i32範囲を超える座標と先読み範囲は`チャンク格子エラー`として返す。必要集合計算はファイル、スレッド、GPUへ触れない。

## 状態台帳

チャンク台帳は必要性と処理段階をチャンクIDごとに一意管理する。段階列は`読込待ち → 読込中 → 準備済み → GPU転送中 → フレーム反映待ち → 常駐 → 解除待ち`である。呼出し側が段階を飛ばすと型付きエラーになる。

新しい必要集合は、新規チャンクの読込要求を入力の中心優先順で返す。不要になった読込待ちと準備済みのCPUデータは即時削除し、読込中なら完了時にGPUへ送らず破棄する。GPU転送中なら転送完了後、フレーム反映待ちまたは常駐なら直ちに解除待ちへ進める。解除はGPU使用完了が通知された後にだけ台帳から削除する。

解除完了前に再び必要になった場合は新しく読み直さない。常駐由来なら常駐へ、まだシーンへ反映していないGPU資源ならフレーム反映待ちへ戻す。

## 段階導入

第1段は必要集合の純粋計算、第2段は集合差分と非同期処理の状態台帳までを実装した。第3段は版付きカタログで解決した生成物を専用ワーカースレッドから読み、形式検査済みシーン、読込バイト数、所要時間を完了通知として返す経路を実装した。

読込要求キューは64件、シーン実体を保持する完了キューは4件の有界キューであり、投入はメインスレッドを待たせない。要求が満杯なら型付きエラーを返し、呼出し側が次回再試行する。完了が未回収ならワーカー側で背圧を掛け、RAMの無制限な増加を防ぐ。ワーカーは1本で中心優先の投入順を保つ。完了回収も待機せず、未完了なら値なしを返す。要求投入が成功してから台帳を読込中へ進め、完了結果を受け取ってから準備完了へ進める。

ワーカーはglTFや画像を読まず、OW1の版付き実行時シーンだけを復元する。破損生成物は完了通知内の`実行時シーン読込エラー`になる。読込バイト数と所要時間は後続の固定経路計測で集計する。

## メモリ予算と縮退

RAMとVRAMはu64のバイト数で別々に上限と現在使用量を持つ。現在使用量は常駐中と解除待ちの既存資源を含み、候補一覧はこれから追加する新規読込だけを中心優先順で渡す。各候補には読込前の見積量を付け、先頭から両予算へ収まる範囲だけを収容する。途中の候補が収まらなければ、それ以降に小さい候補があっても飛び越さず外周側をすべて除外する。これにより穴のない近傍集合と決定的な退避順を維持する。

結果は全件収容、または最初の除外チャンクとRAM超過・VRAM超過を持つ型付き縮退である。加算オーバーフローも該当資源の超過として扱う。現在使用量が既に上限を超えている場合は入力状態のエラーとして縮退と区別する。

第4段は予算計算と縮退結果までを実装した。チャンクごとの見積量は次段でカタログメタデータと実読込量から作り、台帳の現在使用量へ接続する。その後に実GPU転送、フレーム境界反映、GPU使用完了後の資源解除を接続する。
