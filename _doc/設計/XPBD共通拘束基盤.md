# XPBD共通拘束基盤

剛体・関節・線状物理・面状物理・体積弾性体が共有する拘束の数学を、既存の布から縦切りで本来のXPBDへ移し、他の拘束族へ広げる設計正本である。Issue #5の横断裁定(2026-09-01。#7〜#11の拘束数学をXPBD中心へ統一する)・Issue #8の実装境界(同日)・Issue #33の実装ロードマップ(同日。子IssueはIssue #34〜#43)を正本化した。各拘束族の表現(材料・トポロジー・ゲーム上の意味)は各物理のIssue(#7・#9・#10・#11)と、その着工時に書く設計正本が持つ。

用語は `_doc/計画/ユビキタス言語.md`「XPBD共通拘束基盤の語彙」に従う。時間の語彙は同「時間の規律の語彙」、シミュレーション層の語彙は `_doc/設計/シミュレーション層.md` が正本である。

## 目的

現在の布は「XPBD」と呼ばれているが、実装式は拘束ごとのコンプライアンスとラグランジュ乗数を持たず、距離の誤差を逆質量の比で直接分配する位置ベース動力学(PBD)の硬い拘束である。硬さは過緩和係数と反復回数で決まり、刻み幅と反復回数を変えると物性が変わる。本基盤の目的は3つである。

1. 布・紐・棒・剛体・体積弾性体の拘束を、コンプライアンスとラグランジュ乗数を持つ同じ数学の規約で解けるようにし、硬さを物性の値で与えられるようにする
2. CPUの参照計算を数式の正典として置き、GPUの実装をそれと突き合わせて検収できるようにする
3. 固定と掴みを質量の書き換えでなく拘束の着脱で表し、質量特性と外部との拘束を分ける

統一するのは数学と実行の規律だけである。ゲーム上の表現・材料モデル・トポロジー・拘束のデータ型・GPUの並列方式・流体のような別の解法は統一しない(Issue #5の横断裁定の「統一しない」の一覧)。

## 層の定義

| 層 | 置き場所 | 持つもの | 知ってよいこと |
|---|---|---|---|
| シミュレーション基盤層 | `blitz_sim` | 点自由度と姿勢自由度の数学・拘束族ごとの型とCPUの参照計算・XPBDの共通規約(拘束違反・勾配・コンプライアンス・ラグランジュ乗数・刻み幅)・履歴の規約・GPUレイアウトの契約・一刻みの工程の宣言 | `blitz_math` と `thiserror` だけ。Vulkanも描画も知らない(現状維持) |
| GPU実行 | `blitz_render` | 拘束族ごとのバッファの実体・ディスクリプタ・コンピュートパイプライン・レンダーグラフ上のパスの積み方と同期 | `blitz_sim` のレイアウト契約と工程の宣言 |
| ドメイン表現層 | `blitz_game` と `blitz_app` の配線 | 服・ロープ・肉というゲーム上の意味と、物性の値をコンプライアンスへ写すこと | `blitz_sim` の公開面 |

依存の向きは `blitz_math ← blitz_sim ← blitz_render` であり、既存の `_doc/設計/シミュレーション層.md`「3層構造」のままである。機械強制はクレート境界と `cargo xtask conform` のクレート依存の白リストである。

## 主要な設計判断

### 判断1: 拘束の数学はXPBDの標準形を正典とする

1つのスカラー拘束について、1回の反復で行う計算を次の形に固定する。

```text
C            = 拘束違反(現在の状態から評価する)
α̃            = コンプライアンス ÷ 刻み幅の2乗
Δλ           = (-C - α̃ × λ) ÷ (有効逆質量 + α̃)
λ            ← λ + Δλ
各自由度の補正 = 逆質量(または逆慣性) × 勾配 × Δλ
```

有効逆質量は、参加する自由度の逆質量に勾配の2乗を掛けて足した量であり、姿勢自由度が参加するときは逆慣性による回転の項を含める。コンプライアンス0は硬い拘束であり、Δλの分母が有効逆質量だけになる。この式を `blitz_sim` のCPUの参照計算が持ち、GPUの実装は同じ符号・同じ単位・同じ丸めの順で書く。

#### 距離拘束の符号と単位の規約(2026-09-02 実装順1で確定)

CPUの参照計算 `blitz_sim::距離拘束の一刻みの係数::一回射影する`(`crates/blitz_sim/src/xpbd/distance_canonical_projection.rs`)が持つ規約であり、GPUの実装はこの規約で書く。

- 位置はワールドのメートル、逆質量は毎キログラム(固定した自由度は0)、コンプライアンスはメートル毎ニュートン、ラグランジュ乗数はキログラム・メートル、刻み幅は正の有限の秒である。それぞれ `位置<ワールド>`・`逆キログラム`・`コンプライアンス`・`ラグランジュ乗数`・`刻み幅` の型で持ち、生の `f32` は型の `値()` でしか取り出せない
- d = b − a はaからbへ向かう差であり、n = d ÷ |d| はaからbへ向かう単位向きである
- C = |d| − 静止長 は伸びていれば正である
- 静止長の定義域は0以上の有限のメートルであり、`静止長` の型が生成で保証する(負と非有限は `静止長エラー` で拒む)。0は2点の一致を求める拘束として許す。負には満たせる距離が無く(硬い拘束が距離1で振動して収束しない)、非有限は拘束違反から補正と乗数までを非数にするため、他の量と同じく検査を生成の1箇所へ閉じる。`距離拘束の引数` は検査済みの `静止長` と `コンプライアンス` を束ねるだけであり、その生成は失敗しない
- α̃ = コンプライアンス ÷ 刻み幅² は毎キログラムの次元を持ち(逆質量と同じ)、物理刻みの開始時に1度だけ導いてその刻みの全反復で同じ値を使う(`距離拘束の引数::刻み幅で解く係数を導く`)。有効逆質量へそのまま足せる
- Δλ = (−C − α̃λ) ÷ (wa + wb + α̃) は伸びていれば負である。距離拘束の勾配は単位向きであるため、有効逆質量は wa + wb である
- 補正a = −wa Δλ n、補正b = +wb Δλ n であり、伸びていればaはbの側へ、bはaの側へ寄る。旧式の `距離の誤差を逆質量の比で分配する` と同じ向きである
- 退化: 両方の逆質量が0のとき(コンプライアンスの値に依らない)と、2点の距離が1e-6メートル未満で単位向きが作れないときは、非数を作らずに結果の型 `距離拘束の一回の射影の結果` の理由の枝(`両方が固定`・`向きが定まらない`)を返し、λは変えない。1e-6メートルは現在の布のGPU(`shaders/cloth_constraint.slang`)が距離の2乗に置く下限1e-12と同じ長さである
- λの寿命: 呼び出し側が物理刻みの開始時に `ラグランジュ乗数::零()` から始め、反復ごとに結果の `更新後のラグランジュ乗数` を次の反復へ渡す。永続化の口はAPIに無い(判断5)

### 判断2: 数値量は単位を持つ型で持ち、生値へ戻すのはGPUのバイト列の境界だけにする

`blitz_sim` の現在の参照計算は位置を `[f32; 3]`、逆質量とコンプライアンスと静止長を裸の `f32` で受けている(札#138の積み残し「blitz_simの数学DDD」)。本基盤の最初の便(Issue #34)でこれを是正する。位置と変位は `blitz_math` の座標系つきの型で持ち、逆質量・コンプライアンス・ラグランジュ乗数・静止長はそれぞれ専用の型で持つ。単位の異なる量の加算はコンパイルで落とす。生の `f32` へ戻すのは `gpu_layout` のバイト列化の1箇所だけである。この規律はグローバルCLAUDE.md「数学DDD」の適用であり、性能を理由に緩めない(`#[repr(transparent)]` の新型は費用を持たない)。

### 判断3: 自由度は2系統を持ち、1つの列挙へ潰さない

- 点自由度: 位置・速度・逆質量。布・ロープ・体積要素の頂点が使う
- 姿勢自由度: 重心の位置・姿勢・並進の速度・角速度・逆質量・重心まわりの逆慣性。剛体と、ねじりを持つ棒が使う(Issue #39で足す)

静的・運動学的・動的の運動種別は自由度の型とは別に持ち、静的と運動学的を「逆質量0の動的」として表さない。解法の内部で実効の重みを0として導くことは許すが、それは質量の正本ではない。

### 判断4: 拘束は拘束族ごとの密なバッチを正本にし、巨大なトレイトも巨大な列挙も作らない

距離・曲げ・ねじり・面要素・体積・固定と接続・剛体の接触・関節・可動限界・駆動は、それぞれ必要なデータだけを持つ別々の型で表す。`Box<dyn 拘束>` の列と、全種類の欄を持つ `enum 拘束` は作らない。各バッチは、静的な引数(参加する自由度の添字・静止状態・コンプライアンス・材料の値)と、一刻み内の状態(ラグランジュ乗数)と、必要な永続の履歴(塑性の静止状態・損傷・接触の継続)の3つに分けて持つ。

### 判断5: ラグランジュ乗数は拘束側の一刻み内の状態であり、既定では刻みを跨がない

ラグランジュ乗数は物理刻み(内部細分を使う方式では細分の1本)の開始時に0へ初期化し、その刻みの反復の間だけ累積する。刻みを跨いで持ち越す(暖機)かどうかは拘束族ごとの別の判断であり、持ち越すときは刻み幅の変化に対する尺度の変換を含めて仕様を書く。接触の継続の情報と一刻み内のラグランジュ乗数を同じ概念にしない。

### 判断6: 固定と掴みは拘束であり、質量の書き換えではない

旧い布は固定と掴みを逆質量0への書き換えで表し、離すときに既定の逆質量を復元していた。本基盤では、世界の点への固定・動く目標(スキン済み頂点・骨・手)への追従・掴むと離すを、接続拘束(2つの自由度の点を一致させる)と目標拘束(自由度の点を外から与えた目標へ一致させる)の着脱で表す。硬さはコンプライアンスで与え、0で硬い接続、正で柔らかい追従になる。既存の介入モデル(`_doc/設計/シミュレーション層.md`「介入モデル」)の「拘束の着脱」はこの拘束をそのまま指す。既定の逆質量を復元する仕組みは、Issue #37の完了で消えた。

#### 目標拘束の式と工程の位置(2026-09-02 実装順4で確定)

CPUの参照計算 `blitz_sim::目標拘束の一刻みの係数::一回射影する`(`crates/blitz_sim/src/xpbd/target_canonical_projection.rs`)が持つ規約であり、GPUの実装(`shaders/cloth_target.slang`)はこの規約で書く。

- 目標拘束は、粒子x(逆質量w)を外から与えた目標位置へ一致させる拘束である。式は目標側の逆質量を0とした静止長0の距離拘束そのものであり、d = 目標 − x、n = d ÷ |d|、C = |d|、Δλ = (−C − α̃λ) ÷ (w + α̃)、補正 = −w Δλ n である。CPUは距離拘束の正典式へ静止長0と逆質量0の目標を渡して解き、GPUは同じ `projectDistance` を目標側の逆質量0で読む。式を2つ目に書かない
- 静的な引数は粒子の添字とコンプライアンス(`目標拘束の引数`)、毎刻み与える入力は目標位置と有効か無効か(`目標拘束の目標`)、一刻み内の状態はラグランジュ乗数である。世界固定点は目標を刻みを跨いで動かさない特別な場合であり、別の族を作らない。動く目標(スキン済み頂点)は拘束反復の前の目標の確定の工程でその刻みの値を目標位置バッファへ写す(判断8の工程2に当たる)。掴むは目標位置を与えて有効にする介入、離すは無効にする介入であり、有効でない拘束は反復で読まれず乗数も0のままである
- 退化: 粒子が目標と一致(距離が1e-6メートル未満)なら補正0で乗数を変えず(`目標と一致している`)、粒子の逆質量が0なら動かせない(`粒子が固定`)。どちらも非数を作らない
- 同じ粒子を持つ目標拘束は高々1本であり(`目標拘束のバッチ` の生成が拒む)、バッチ全体が彩色の1色になる。GPUは各反復で距離拘束の色の後ろに目標拘束を1回のディスパッチで積む。後ろに置くのは、各反復の最後に射影した拘束がその粒子の位置を決めるためであり、硬い接続(コンプライアンス0)の粒子は反復を終えるたびに目標の上に載る(旧アタッチが積分の後に位置を書いていたのと同じ見え方を、拘束として保つ)。前に置くと距離拘束が固定の粒子を反復の最後に動かし、固定が緩む
- 1刻みの工程は介入→積分→目標の確定→乗数零化→(距離拘束(色ごと)→目標拘束)×反復回数→(空間ハッシュ→分離)→床とカプセルの押し出し→目標拘束の最終の成立→仕上げ(速度の再構成)である。積分・分離・押し出し・仕上げに逆質量0の枝は無く、全粒子へ同じ規則を当てる。布の粒子の逆質量は全て正であり、`blitz_render::布素材::生成する` が逆質量0と非有限を型付きエラーで拒む
- **目標拘束の最終の成立**(2026-09-02 Issue #37のcodexレビューの是正で確定): 反復の最後に目標拘束を解いた後も、自己衝突の分離と床とカプセルの押し出しが全粒子を再び動かす。旧経路は逆質量0の粒子を分離と仕上げが飛ばしていたため固定とアタッチは最終の位置まで不動だったが、目標拘束の経路では近傍が重なった固定点・掴んだ粒子は分離で目標から押され、目標がカプセルの内側や床の下にある粒子は押し出しで目標から外れ、その位置から速度を作ると次の刻みへ誤った速度を持ち越す。そのため、分離と押し出しの後・速度の再構成の前に、目標拘束を同じシェーダー(`targetConstraintMain`)でもう1回射影する。乗数は反復で累積した値を読み継ぎ、この射影の分も足す(乗数=加えた補正の総量という正典の意味を保つ)。工程の形は、旧仕上げのシェーダー(`shaders/cloth_finish.slang`)を床とカプセルの押し出し(`collisionPushOutMain`。位置だけを書く)と速度の再構成(`finishMain`。速度だけを書く)の2つの入口に分け、その間へ最終の成立を積む形を選んだ。押し出しを分離の側へ寄せる形を採らなかったのは、分離が自己衝突を行う布だけの工程であるのに対し、床とカプセルの押し出しは全ての布が積む工程であり、寄せると自己衝突を行わない布(参照比較の布)が床を失うためである。CPUの参照計算(`crates/blitz_sim/src/cloth/reference/step.rs`)も床で止めた後に目標拘束をもう1回射影する(速度は位置の差であるため仕上げの工程は無い)。検収 `cargo xtask cloth-xpbd-reference` は、同じ吊るし布の下端の右端をその真下の床の下(y=−0.01メートル)の世界固定点にした3つ目の条件(floor)を持ち、最終の成立を欠くとその粒子がCPUと0.01メートル食い違って落ちる。下端の行が床に載る高さから吊るす題材を採らなかったのは、床に載った行が毎刻み床に蹴られる力学が摂動を増幅し(CPUの参照計算で1e-7メートルの摂動が12刻みで6e-3メートルへ育つ)、単精度の演算順の差が許容を越えて突き合わせにならないためである。パス列の順(分離→押し出し→最終の成立→仕上げ)は `cloth_passes/constraint_stage_tests.rs` が固定する
- 目標拘束の乗数は固定とアタッチの反力の観測であり、読み戻しの口(`布の読み戻し::目標拘束のラグランジュ乗数一覧`・`布の参照計算::目標拘束のラグランジュ乗数一覧`)を持つ。破断の判定はこれを読む(破断そのものはIssue #16)

### 判断7: GPUの並列方式は拘束族ごとに実測で選び、共通の1つのカーネルへ統一しない

ラグランジュ乗数を拘束ごとに持つと、現在の「粒子ごとに1スレッドが隣接する拘束を集めて自分の位置だけを補正する」方式はそのままでは使えない(同じ拘束のラグランジュ乗数を2つのスレッドが別々に更新する)。Issue #35で、少なくとも3方式(拘束ごとに1スレッドと原子加算・グラフ彩色による直列のディスパッチ・Δλを拘束側へ書く工程と自由度側で集める工程の二段階)を、規則格子の布と接続数の不均一な拘束グラフの2種類で同じ条件で計測し、拘束族ごとの採用規則として記録する。評価軸は、ラグランジュ乗数が拘束ごとに一意に更新できること・CPUの参照計算との一致・収束・GPU時間・メモリ・ディスパッチ回数・原子演算への依存・決定性・動的な拘束集合への適用しやすさである。

決定性の扱いを先に定める。現在の布の方式は、同じバッファを他のスレッドが同時に補正するため、ビット単位の数値決定性を持たない(`shaders/cloth_constraint.slang` の冒頭の注意)。本基盤が最低限守るのは検収決定性とゲーム決定性であり(`_doc/設計/時間の規律.md`「判断8」)、数値決定性を保証する方式(グラフ彩色・二段階)と保証しない方式(原子加算)のどちらを採るかは、検収の判定がビット一致を要るかどうかで決める。既存の布の検収(`cloth-empty` 等)は絵の構成とパスの数を判定しておりビット一致を要らないが、Issue #36のCPUとGPUの突き合わせは許容差つきの比較で書く。

#### 採用規則(2026-09-02 実装順2で確定)

Issue #35の実測(`_doc/計測/XPBD並列方式_2026-09-02.md`。計測の入口は `cargo xtask xpbd-solver-bench`)から、拘束族ごとに次の方式を採る。3方式はどれも正典式の同じ写し(`shaders/xpbd_projection.slang`)を読み、乗数は拘束ごとのバッファに持って刻みの開始で0へ戻す。

1. **固定トポロジーの距離と曲げ(布・ロープ)はグラフ彩色を採る。** 同じGPU時間で拘束違反が最も小さいためである。規則格子(1024点・3906拘束)では、彩色の1反復(9色、約0.027ミリ秒)の拘束違反の二乗平均平方根が0.065メートルであるのに対し、同時に更新する2方式の4反復(約0.025〜0.029ミリ秒)は0.16メートルであり、彩色の2反復(約0.050ミリ秒)の0.018メートルへ同時の方式が届くには16反復(約0.085〜0.10ミリ秒)でも0.029メートルまでしか下がらない。反復あたりの費用は彩色が同時の方式の約4倍(色の数だけディスパッチが増える)だが、逐次の更新は同時の更新より1反復で進む量が大きく、緩和係数も要らない。彩色の前計算はトポロジーが固定なら生成時の1回で済み(規則格子3906拘束で約0.3ミリ秒、CPU単一スレッド)、色の数は最大接続数8に対して9である。ビット単位の数値決定性を持ち、原子演算を使わず、方式の中でメモリが最も小さい(規則格子で110,896バイト。同時の2方式は127,296と271,248)。Issue #36はこの方式で布を移行し、布の格子の8方向のスロットは色の区間へ置き換える
2. **動的な接触(毎刻み変わる拘束集合)は原子加算を第一候補、二段階を代替とする。** 彩色の前計算が接触の集合ごとに要り(不規則グラフ4663拘束で約0.6ミリ秒、19色)、GPU時間(彩色の4反復で約0.20ミリ秒)より前計算が高くつくためである。原子加算と二段階は不規則グラフでも一刻みが約0.029と0.033ミリ秒であり、どちらも接続数の不均一に影響されない。原子加算を先に置くのは、前計算が点ごとの接続数だけで済み(二段階は隣接の項目の並びも要り、動的な集合では毎刻みの数え上げと並べ替えになる)、メモリが二段階の半分以下(不規則で142,432バイト対316,672バイト)だからである。固定小数の整数の原子加算は結合的であるため数値決定性を持ち(実測で2回の実行がビット一致)、量子化の桁2の-20乗メートル(約0.95マイクロメートル)は接触の許容(ミリメートルの桁)の十分下にある。二段階はCPUの参照計算との差が原子加算より1桁小さい(短い実行で1.7e-6対4.0e-5メートル)ため、量子化を許さない拘束族が現れたときの代替である
3. **同時に更新する方式(原子加算・二段階)は緩和係数を必ず掛ける。** 両端の接続数の大きい方の逆数を乗数の増分と補正の両方へ掛ける(`同時の緩和係数`)。掛けないと接続数の多い点で補正が重なって発散する(現在の布のgather方式が接続数で平均しているのと同じ理由)。乗数と補正へ同じ係数を掛けるのは、乗数が実際に加えた補正の総量であるという正典の意味を保つためである
4. **計測から言えないこと。** 剛体の接触そのもの(接触の生成・接触島・姿勢自由度)は測っていない。動的な集合での二段階の隣接表の毎刻みの構築費用と、原子加算の点ごとの接続数の数え上げの費用は測っていない(規則2の順位はこの費用の見積もりに依る)。異種の拘束族を同じ反復へ混ぜたときの収束は測っていない(Issue #43)

### 判断8: 一刻みの工程は依存順を宣言し、拘束族はその中の反復へ参加する

1つの物理刻みの標準の工程を次の順に固定する(Issue #8の実装境界の第7節)。

1. 前の刻みからの構造変更(生成と削除・拘束の着脱・確定した破断)を安全な境界で反映する
2. ゲームからの介入(力・衝撃・運動学的な目標・目標拘束の更新)を適用する
3. 外力から速度を更新する
4. 予測の位置と姿勢を作り、前の状態を保存する
5. 衝突の候補を生成し、接触の拘束を作り、継続する接触を履歴へ対応付ける
6. ラグランジュ乗数を初期化し、刻み幅からコンプライアンスの刻み依存量を導き、必要なら接触島と拘束の組を作る
7. XPBDの反復。距離・曲げ・ねじり・面と体積の材料拘束・固定と関節と可動限界・接触を同じ反復へ参加させる
8. 確定した位置と姿勢から速度を再構成する
9. 速度の段階。反発・動摩擦・速度の駆動
10. 塑性・損傷・破断の条件を評価し、構造変更を次の安全な境界へ積む
11. 休止・イベント・計器の値を確定する
12. 描画用の形状を生成または抽出する

「同じ反復へ参加する」は同じ巨大なカーネルという意味ではなく、レンダーグラフ上では拘束族ごとの複数のディスパッチになる。現在の布の工程(介入の反映・速度と位置の積分・動く目標の確定・距離拘束と目標拘束の反復4回・空間ハッシュの消去と格納・自己衝突からの分離・床とカプセルの押し出し・目標拘束の最終の成立・速度の再構成の仕上げ)はこの標準の工程の部分列であり、Issue #36と#37でその位置を変えずに中身を置き換えた(アタッチ先への追従は同じ位置の「目標の確定」になり、固定と掴みは目標拘束として反復へ参加した)。目標拘束の最終の成立は工程7の拘束を、工程5に当たる分離と押し出しの後・工程8の速度の再構成の前にもう1回成立させる位置であり(判断6「目標拘束の最終の成立」)、押し出しと速度の再構成を別のディスパッチに分けたのはこの位置を作るためである。Issue #43で他の拘束族と同じ反復へ広げる。工程の位置と刻みの本数は `_doc/設計/時間の規律.md`「判断5」の「固定刻みで必ず進む」区分に属したままである。

### 判断9: GPUのレイアウトは数学の型と分離した契約にする

Rustの数学の型を `repr(C)` でそのままGPUへ流さない。`blitz_sim` の `gpu_layout` が明示の符号化でバイト列を作り、`blitz_render` がそれを読む(現在の `粒子バイト列にする` と同じ向き)。静的な引数と毎刻み書き換える状態(ラグランジュ乗数)を同じバッファへ詰めない。候補のバッファは、点の状態・点の前の状態・姿勢自由度の状態・質量特性・拘束族ごとの引数とラグランジュ乗数・接触の一時的な拘束・接触の履歴である。

#### 布の拘束とラグランジュ乗数のバッファ(2026-09-02 実装順3で確定)

布の統一ディスクリプタセット(束縛番号の正本は `crates/blitz_render/src/vulkan/cloth/descriptor.rs`、表は `shaders/cloth_step.slang` の冒頭)は、静的な引数を b4 の拘束の引数バッファに、一刻み内の状態を b10 のラグランジュ乗数バッファに分けて持つ。

- 拘束の引数バッファ: 1拘束16バイト(a添字u32・b添字u32・静止長f32・コンプライアンスf32)。並びは `布の彩色済み拘束` が色ごとに並べ替えた順であり、バイト列化は `blitz_sim::gpu_layout::xpbd::拘束の引数バイト列にする`(Issue #35の計測と同じ契約)が持つ。構造とせん断のコンプライアンスは `布の物性` が種類ごとに1つ持ち、この写しで拘束ごとの値になる
- ラグランジュ乗数バッファ: 1拘束4バイト(f32)。初期値は `ラグランジュ乗数の初期バイト列にする` の零であり、物理刻みの開始で `lambdaClearMain`(`shaders/cloth_constraint.slang`)が0へ戻す(判断5)。読み戻しの用途(転送元)を持つのは、CPUの参照計算との突き合わせが終了時に1回だけ写すためである
- 色の区間: バッファには置かず、色ごとのディスパッチのプッシュ定数(開始u32・本数u32)で運ぶ。乗数の零化も同じプッシュ定数で全拘束の区間(開始0・本数=拘束の数)を受ける(定数UBOの4語は粒子数・一辺・介入件数・アタッチ件数で埋まっているため)
- 定数UBO(`ClothParams`): 過緩和係数が居た `misc.y` は刻み幅の2乗の逆数になり、シェーダーはコンプライアンスにこれを掛けて刻み依存量α̃を作る。布の硬さを定数UBOで運ぶ経路は無い
- GPU境界の検証: `blitz_render::布素材::生成する` は長さと色の区間に加えて拘束の内容を検証し、端点が粒子数未満で両端が別の粒子であること・同じ色の区間の中で端点を共有しないこと・静止長とコンプライアンスが0以上の有限であることを型付きエラーで課す。粒子数以上の端点はGPUの粒子バッファの範囲外の読み書き、同じ色の端点の共有は1色の中の競合書き込みであり、型が「検証済みGPU入力」であるための不変条件である。読み手はblitz_simへ依存できないため `cloth_material` に置き、1件のバイト数は conform の定数の組で書き手と結ぶ
- 布の刻み幅: 時間の規律の正本(`crates/blitz_app/src/game/step_seconds.rs`)の基本刻みをコンポジションルートが `布の刻み幅` として注入し、GPUの定数(`gravityDt.w` と `misc.y`)と布の参照計算の条件の刻み幅をその1つの値から作る。レンダラーは刻み幅の綴りを持たない。`cargo xtask cloth-xpbd-reference` は報告の刻み幅が正本と一致することを判定し、判定が持つ写しは conform の定数の組が正本と突き合わせる

#### 布の目標拘束のバッファ(2026-09-02 実装順4で確定)

- 目標拘束の引数バッファ(b11): 1本8バイト(粒子添字u32・コンプライアンスf32)。並びは `目標拘束のバッチ` の順(吊るし布とマントでは上端行32本の後に掴みの枠1本)であり、バイト列化は `blitz_sim::gpu_layout::xpbd::目標拘束の引数バイト列にする` が持つ
- 目標位置バッファ(b12): 1本16バイト(目標位置xyz f32・有効f32。有効は1.0、無効は0.0)。初期値は `目標位置の初期バイト列にする` が書き、動く目標は「目標の確定」(`targetUpdateMain`)が、掴むと離すは介入(`interventionMain`)がGPUで書き換える。有効を目標位置と同じ16バイトへ置くのは、介入が目標位置と有効を1語の書き込みで着脱するためである
- 目標の更新対応バッファ(b9。旧アタッチ対応の束縛): 1件8バイト(目標拘束添字u32・スキン頂点添字u32)。動く目標を持つ布だけが件数を持ち、件数はディスパッチのプッシュ定数で運ぶ。0件なら目標の確定のパスを積まない
- ラグランジュ乗数バッファ(b10): 距離拘束の乗数の後ろに目標拘束の乗数を続けて置く(合計で確保し、零化は合計の区間を受ける)。目標拘束のディスパッチは区間の開始(=距離拘束の数)と本数をプッシュ定数で受け、乗数の添字を開始に足して読む
- 定数UBO(`ClothParams`): `counts.w` は目標拘束の数であり、介入の拘束添字の範囲の検査に使う(旧アタッチ件数は消えた)。`capsuleB.w` は予備である(旧既定逆質量は消えた)
- 介入(b3): 1件32バイトのまま、種別0=目標拘束を有効にする(目標位置xyzを運ぶ)・1=無効にする・2=インパルス(予約)であり、第2語は目標拘束添字である。レイアウトの正本は `crates/blitz_sim/src/intervention/encode.rs`
- GPU境界の検証: `布素材::生成する` は目標拘束にも距離拘束と同じ検証を課す。粒子添字が粒子数未満・同じ粒子を持つ目標拘束が高々1本(1色で解くための不変条件)・コンプライアンスが0以上の有限・目標位置が有限・有効が1.0か0.0・更新対応の目標拘束添字が本数未満で対応の間で一意(2件が同じ拘束を指すと目標の確定の2つのスレッドが同じ目標位置へ同時に書き、目標が実行順に依存する)、である。1本のバイト数(8と16)と粒子1件の32バイトは conform の定数の組で書き手と結ぶ
- 1刻みのパス数の上限は10 + (色の数の上限 + 1)×反復回数であり(`一刻みのパス数`。拘束以外の10本は介入・積分・目標の確定・乗数零化・ハッシュ消去・格納・分離・床とカプセルの押し出し・目標拘束の最終の成立・仕上げ)、GPU計測のクエリプールの容量がこれに追随する

### 判断10: 公開のAPIへXPBDの内部を漏らさない

ゲーム側へ見せるのは、服・ロープ・剛体という現象の意味を持つ型と操作(生成と破棄・材質・力と衝撃・拘束の着脱)である。拘束違反・ラグランジュ乗数・反復回数・並列方式は基盤の内部に置き、切り替えのためだけの `trait 物理ソルバ` を公開面に置かない。将来別の解法を試すときも、現象の意味を保ったまま内部の経路を足す。

## 性能予算

シミュレーション(M9、コンピュート)の枠は3.0ミリ秒である(`_doc/計画/評価軸.md` 3.1)。現在の布はその1.7パーセント(約0.051ミリ秒)であり、Issue #36でXPBD化した布の時間を同じ条件で測り、既存の値と比較して記録する。剛体・体積弾性体の枠は各Issueの着工時に、この枠の内訳として制定する。

## 決定性の保証

- 保証する決定性: 検収決定性とゲーム決定性。数値決定性は既定では保証せず、Issue #35で採った方式が保証するときだけ、その拘束族について明示する
- 条件: 同じ機械・同じビルド・同じ入力系列・同じ刻み数・同じ反復回数・同じ並列方式であること。CPUの参照計算は単一スレッドで同じ順に演算する
- 失効する変化: 並列方式の変更・反復回数の変更・浮動小数の原子加算を使う方式でのスレッドの順の変化(その方式は数値決定性を持たない)・刻み幅の変更(コンプライアンスの刻み依存量が変わる)
- 採った方式の数値決定性(2026-09-02 実装順2で実測): グラフ彩色と二段階は書く先が自分の拘束と自分の点だけであり、ビット単位の数値決定性を持つ。固定小数の原子加算も整数の加算が結合的であるためスレッドの順に依らず、数値決定性を持つ。3方式とも同じ入力の2回の実行が位置と乗数のSHA-256の指紋まで一致した(`_doc/計測/XPBD並列方式_2026-09-02.md`)。したがって固定トポロジーの距離と曲げ(グラフ彩色)と動的な接触(固定小数の原子加算・二段階)は、上の条件の下で数値決定性を明示してよい。GPUとCPUの参照計算の間はビット一致ではなく許容差つきの比較である(単精度の演算順が違う)

## 実装順

各段階の様式は既存と同じ(実装→検査員2体→codexレビュー→是正→閉塞)である。段階はIssue #33の子Issueと1対1である。

1. Issue #34: 距離拘束の正典式(コンプライアンス・ラグランジュ乗数・刻み幅)をCPUの参照計算として実装する。判断2の型を同時に入れる。硬い拘束の収束・柔らかい拘束の有限の柔らかさ・刻み幅と反復回数を変えたときにPBDより硬さが崩れないこと・両端固定と2点一致でNaN(非数。0を0で割る等で生じる不正な計算結果)を出さないこと、を単体テストと反証で固定する。既存の布のGPU経路は変えない
2. Issue #35: ラグランジュ乗数を持つGPUのレイアウトと並列方式の実測。判断7の3方式を2種類の拘束グラフで計測し、採用規則を本文書の判断7の下へ追記する。計測は `cargo xtask` の命令として登録し、記録は `_doc/計測/` に残す
3. Issue #36: 布の構造とせん断の距離拘束を本来のXPBDへ移行する。硬さの正本を過緩和係数からコンプライアンスへ移し、構造とせん断で別の値を持てる型にする。CPUの参照計算とGPUの結果を同じ初期条件で突き合わせ、既存の自己衝突・アタッチ・描画の経路を保ち、GPU時間を既存と比較する
4. Issue #37: 固定とアタッチを逆質量の書き換えから接続拘束と目標拘束へ移す。掴むと離すを拘束の着脱で表し、既定の逆質量を復元する仕組みを消す(2026-09-02 完了。接続拘束は布に用途が無く、目標拘束だけを実装した)
5. 以後はIssue #33のとおり並行できる。Issue #38(曲げ。ロープと布で共有)・Issue #39(姿勢自由度)→Issue #40(剛体の接触)→Issue #41(関節)・Issue #42(体積弾性体)を、完成したものからIssue #43(一刻みの工程への統合と異種の強結合)へ足す。剛体の側の設計正本はIssue #39の着工時に別に書く(Issue #7の要求10項と具体契約12項を正本化する)
