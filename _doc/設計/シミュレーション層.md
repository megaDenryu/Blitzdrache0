# シミュレーション層の設計

キャラクターシミュレーション（軟体・布・髪・流体）をプロジェクトとしてどう切るかの設計。
出発点となる観察: 液体ひとつ取っても魅せたい絵によって手法が全く異なり「表現」は汎用化できない。
しかし手法の数学（拘束計算・粒子・空間ハッシュ）は汎用である。
ゆえに切断線は「表現はドメイン、数学は基盤」に引く。

## 3層構造

```
ドメイン表現層（ゲーム固有。blitz_game 側）
   ↓ 部品を組み合わせる
シミュレーション基盤層（汎用。blitz_sim クレート）
   ↓ コンピュートパスとして実行される
blitz_render（GPU実行基盤。レンダーグラフ + リソースシステム）
```

- **ドメイン表現層**: 「唾液」「この服」「この肌のぷにぷに」という見せたい絵ごとの1表現。基盤層の部品を組み合わせパラメータを調整したもの。汎用化しない。ゲームごとに書き捨ててよい。Unityが失敗する場所（表現を汎用部品として全ゲームに同梱する）をこの層に隔離することで、エンジン本体は肥大しない
- **シミュレーション基盤層**: XPBDソルバ、拘束の種類（距離・曲げ・体積・衝突・セルフコリジョン）、粒子系、空間ハッシュ、表面流の土台。手法の数学だけを持ち、特定の絵を知らない。レンダーグラフと同じ立ち位置（グラフは汎用、何を描くかはゲーム側、の相似形）
- **blitz_render**: レンダーグラフがコンピュートパスを第一級で扱い、シミュレーション結果のGPUバッファを描画パスとゼロコピー共有する。非同期コンピュートキューへの振り分けもここが担う

blitz_simはM9で新設済みである。布、介入、表面流、SPHのCPU参照計算とGPUバッファレイアウトを保持し、Vulkan実行はblitz_renderに分離する。

## 流体方式の分担

- 表面流は、物体表面を伝う薄い液膜に使う。UV格子に液膜厚さと接線速度を保持し、2次元の保存的移流を解く。本実装ではGPU側も横方向を含む流束計算と二重バッファを持たせる。
- SPHは、空間内を移動する少量の液滴と粘性流体に使う。M10の全対全探索は性能限界の測定専用であり、本実装は空間ハッシュによる近傍探索を前提とする。
- MPMは、雪、塑性、強い粘弾性が対象ゲームで必要になった場合、またはSPHの表面再構成で必要品質へ届かない場合に再評価する。表面流やSPHと共通のソルバ抽象へ固定しない。

## 介入モデル（プレイヤーイベントのシミュレーションへの流し込み）

前提: ゲームで重要なのは、プレイヤーが発生させるイベントをシミュレーションに介入させられること。
Unityの「イベント→マテリアル→シェーダー」はパラメータを突くことしかできない退化形であり、本エンジンでは介入を型付きの一級概念にする。

介入（intervention）= ゲームロジックがシミュレーションへ渡す型付きの値。種類:

- **インパルス**: 位置 + 力（触る・叩く・風）
- **拘束の着脱**: 点の固定（掴む）、拘束の切断（服を破る・脱がす）
- **放出**: 位置 + 粒子種 + レート（液体の発生源）
- **パラメータ場の書き換え**: 領域 + 物性値（粘性・硬さの局所変更）

フレーム内の流れは一方向:

```
入力 → ゲームロジック → 介入キュー → シミュレーション(GPU) → 描画
```

逆方向（シミュレーション→ゲームのイベント: 引きちぎれ・着地・接触）はGPUからの非同期読み戻しで1フレーム遅れで届く。
ゲームプレイ用途にはこの遅延で足りる。

この設計は入力インテント・エディタ操作コマンドと同型の「境界を越えるものは型付きの値にする」パターンの3例目であり、コーディング憲法（ディスクリミネイテッドユニオン、値オブジェクト）でそのまま表現できる。
