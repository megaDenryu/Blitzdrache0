# 裁定待ちユビキタス言語

裁定待ちユビキタス言語とは、実装の途中でAIが新しく作り、オーナーの裁定をまだ受けていない語のことである。

実装員は、既存の語では表せない概念に出会ったとき、その場で名前を決めてよい。ただし決めた名前は案であり、合意済みの語彙ではない。このファイルはその案を置く場所である。

`_doc/計画/ユビキタス言語.md` は、対話で合意した語彙を記録する正本である。親と実装員は、裁定を受けていない語をそちらへ書いてはならない。
グローバルCLAUDE.md「専門用語の表記」が求める「定義なしで新語を使い始めるのは禁止」は、このファイルへの登録で満たす。

手順の全文はプロジェクトのCLAUDE.md「新しいドメイン概念と語彙の導入」にある。

## 書き方

1件につき次の5つを書く。語を見出しにし、残りの4つを箇条書きにする。

- **区切られたドメイン**: 共通・描画・物理・ゲーム実行・ECS・資産ストリーミング・エディター・開発基盤のどれか。1語1義はこの範囲の中で成り立つ規律であり、区切られたドメインが違えば同じ表記が別の語でありうる。詳細はCLAUDE.md「区切られたドメイン」にある
- **暫定の定義**: 「Xとは〜のことである」の形で書く
- **使っている場所**: その語を識別子または文書で使っているファイルのパス
- **既存語で表せないと考えた理由**: どの既存語を検討し、なぜ足りないと判断したか

裁定が済んだら、親はこの節から項目を消す。親は、採用ならユビキタス言語へ定義を移し、必要なリネームを別のコミットで行う。親は、却下なら既存語へ戻すか、概念そのものを畳む。

## 裁定待ちの語(2026-09-20時点で2件)

### 接触(ディレクトリ名としての採用)

- **区切られたドメイン**: 物理
- **暫定の定義**: `blitz_sim/contact/`が担う、剛体どうし・剛体と静的世界の接触の検出から解決までの責務境界のことである。「接触」という語自体は、`blitz_sim`の公開API(`接触の解法ソルバー`・接触島・接触の履歴・接触拘束・材質の対等)で既に一貫して使われている確立済みの訳語であり、issue #167は、このディレクトリの物理名を`contact/`から`接触/`へ、識別子側の語彙に揃える形で採用する
- **使っている場所**: `crates/blitz_sim/src/contact/`配下全体(識別子)。ディレクトリ名としての適用は未実施
- **既存語で表せないと考えた理由**: 新しい語を作る話ではない。識別子側では既に「接触」が定着しているのに、ディレクトリ名だけが英語`contact`のまま残っており、issue #165が可能にした手段(`#[path]`)で物理名を識別子側へ揃えられるようになったことが動機である

### 場面(ディレクトリ名としての採用)

- **区切られたドメイン**: 物理
- **暫定の定義**: `blitz_sim/contact/scene/`が担う、接触の物理試験(`#![cfg(test)]`専用)のための場面構築(坂の場面・場面の設定・場面の材料組み立て等)の責務境界のことである。「場面」という語自体は、このディレクトリ配下の識別子(`場面の材料`・`場面の設定`・`坂の場面`・`場面の組み立て`等)で既に一貫して使われている確立済みの訳語である
- **使っている場所**: `crates/blitz_sim/src/contact/scene/`配下全体(識別子)。ディレクトリ名としての適用は未実施
- **既存語で表せないと考えた理由**: 接触と同じ理由であり、新語ではない。ただし、オーナーが元issue #165で示した例示(`blitz_sim/scene/`のように`contact/`と並ぶ独立ディレクトリ)と実際の構造(`contact/`の下に入れ子)が食い違っており、この点はオーナーとの対話で確認が要る

## 裁定の記録

裁定の結果はこのファイルに残さない。採用した語はユビキタス言語の定義文に、裁定の日付と裁定を行ったissueの番号を添えて書く。
却下した語は、却下を裁定したissueのコメントに残る。
