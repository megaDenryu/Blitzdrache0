1. 序 — この文書の目的と読み方

この文書は、エンジンのオーナーが宣言した方針「すべてをAAA級のグラフィックを極限まで最高パフォーマンスでやる。まともに実装すれば低性能デバイスでも最高品質がキチンと動くはず」を、技術の言葉に翻訳するための地図である。役割は2つある。第一に、リアルタイムグラフィックスの各技術要素を初歩から解説し、オーナー自身が方針決定に必要な概念を持てるようにする学習資料であること。第二に、このエンジンが目指す野心的な到達形を技術的に定義し、「どの能力を・どの順で・どの品質で作るか」を決める土台になるプレゼン資料であることである。

読み進める前に、この文書全体を貫く2つの区別を頭に置いてほしい。

区別 1

「野心的到達形(能力)」と「現時点の本番方式候補」は別物である。「Lumen級のGI」「Nanite級の仮想ジオメトリ」のような固有名は能力の水準を伝える比較語として使うが、方式名を最終決定として固定しない。技術は進歩し、対象GPUも変わる。この文書では各能力に対して方式候補と、その採用条件・代替手段・破棄条件を添える。これはこのエンジンの憲法「可能性を閉じる決定を早期にしない」の適用である。

区別 2

「決定済み」と「未決定(オーナー裁定待ち)」を明示する。本文中の「現状」はすべて実装済みの事実(出典は性能アーキテクチャ方針・評価軸・各設計正本・計測記録)であり、「到達形」「方式候補」は本文書が提案する未決定の目標である。読み終えたときに決めるべきことは第8章に集約した。

各章の位置づけは次のとおりである。第2章と第3章は前提知識であり、絵が計算される仕組みをゼロから積み上げる。第4章が本体で、7つの技術領域を「定義 → なぜ絵が良くなるか → 現代の代表方式 → このエンジンの現状 → 野心的到達形 → 方式候補と採用条件 → 既存実装への波及」の型で解説する。第5章は全能力を1つの目録表に畳み、第6章は既存実装のうち作り直しに近い改修が要る接合点を正直に列挙する。第7章は「低性能デバイスでも最高品質」という要求の技術的な意味を定義し、第8章で実装順序の提案に落とす。

2. 画素は何で決まるか — 形・材質・光・カメラ

画面は画素(ピクセル)の格子であり、リアルタイムグラフィックスの仕事は「毎秒60回、数百万個の画素それぞれに正しい色を入れること」に尽きる。では1つの画素の色は何で決まるのか。答えは4つの要素の組み合わせである。

  • 形(ジオメトリ): その画素に映っている表面はどこにあり、どちらを向いているか。エンジンでは三角形の集まり(メッシュ)で表す。表面の向き(法線)は明るさ計算の主役である。
  • 材質(マテリアル): その表面は光をどう跳ね返すか。ざらざらの壁は光をあらゆる方向へ拡散し、磨いた金属は鏡のように一方向へ反射する。色・粗さ・金属性などのパラメータで表す。
  • 光(ライティング): どこから、どんな色と強さの光が来ているか。太陽のような遠い光(方向光)、電球のような近い光(点光源)、そして壁や床で跳ね返ってから届く間接光がある。
  • カメラ: 視点がどこにあり、どこを見ているか。3次元の世界を2次元の画素格子へ射影する。

この4要素はそのまま本文書の章立てに対応する。形は第4.5章(物量)、材質は第4.3章、光は第4.1章と第4.2章が扱い、カメラを含めた「1フレームの組み立て」を次の第3章で追う。そして絵の品質とは、この4要素それぞれの近似をどこまで物理的に正しく・破綻なく行えるかの積である。AAA級とはこの積の水準の呼び名にすぎない。「明るさ」を物理の量として単位から定義する丁寧な積み上げは第10章にある — 本文で量の定義に引っかかったらそちらを先に読むのがよい。

3. GPUが1フレームを作る流れ — 現エンジンを教材に

CPUとGPUは分業する。CPUは「このフレームに何をどこに描くか」を決めて描画命令(コマンド)の列を組み立て、GPUはその命令列を大規模並列で実行して画素を塗る。Blitzdrache0では、この命令列の組み立てをレンダーグラフという仕組みが担っている。各描画工程(パス)が「何を読み、何に書くか」を宣言し、グラフは宣言された順序で実行しつつ、その順序に必要な待ち合わせ(バリア)を読み書き宣言から自動で導出する(実行順自体は構築側が明示する)。工程を追加してもバリアの正しさが壊れない器であり、この文書で語る野心の多く(新しいパスの追加)はこの器の上に載る。

現エンジンの1フレームは、およそ次の工程列である(点灯アニメーションは実行順を表す)。

押さえてほしいのは3点である。

  1. 1フレームは複数の絵の合成である。影のための深度だけの絵(シャドウマップ)を先に描き、本番の絵がそれを参照する。AAA級のフレームはこの中間の絵がさらに増える(法線の絵・速度の絵・過去フレームの絵など)。「パスを足す」とは中間の絵を増やすことである。
  2. すべては予算の中で行う。60フレーム/秒なら1フレームの持ち時間は16.6ミリ秒しかない。このエンジンは評価軸文書でGPU合計予算16.6ミリ秒を区間(シーン・シャドウ等)へ配分し、GPU計器で毎フレーム実測している。新しい能力の追加は常に「その能力は何ミリ秒を使うか」とセットで論じる。
  3. 座標の土台は既に大規模世界仕様である。世界座標はf64(倍精度)で持ち、GPUへはカメラ相対のf32(単精度)だけを渡す。km級の巨大座標でも画素が揺れないことを機械検査(cargo xtask origin-invariance)が保証している。これは多くの商用エンジンが後付けで苦しむ部分を最初から解いている、このエンジンの強みである。
現状の要約

フレーム工程列: CSM4帯シャドウ + 布専用シャドウ → forward(前方)シーン描画(PBR・XPBD布込み) → 空(大気のベイク済み画像、時刻駆動) → ブルーム → ACESトーンマップ → 開発UI。レンダーグラフがバリアを自動導出し、GPU計器が帯別・パス別の実測を出す。詳細の正本は _doc/設計/性能アーキテクチャ方針.md と各設計文書。

4. 技術要素の解説

ここからが本体である。7つの技術領域を、絵の理解に自然な順序(光 → 材質 → 画の完成 → 物量 → 世界読込 → 実行基盤)で解説する。各領域は同じ型で書く: 定義 → なぜ絵が良くなるか → 現代の代表方式 → このエンジンの現状 → 野心的到達形(能力) → 方式候補と採用条件 → 既存実装への波及。

4.1 直接光と影

定義

直接光とは、光源から表面へ直接届く光のことである。太陽(方向光)・電球(点光源)・懐中電灯(スポット光)が代表で、計算は「光源の方向・距離・強さ」と「表面の向き・材質」から明るさを求める、リアルタイムグラフィックスで最も確立された部分である。影とは、光源と表面の間に遮蔽物があるとき直接光が届かないことの表現であり、影は直接光計算の一部である(影が別機能に見えるのは、遮蔽の判定に専用の仕組みが要るからにすぎない)。

なぜ絵が良くなるか

影は物の接地感と空間の奥行きを1枚で伝える。影が無い絵では物体が浮いて見え、影の解像度が足りない絵では輪郭がギザつき、影が硬すぎる絵では晴天の正午しか表現できない。現実の影は、遮蔽物から離れるほど輪郭がぼける(半影)。この距離依存のぼけまで再現できると、絵は一段と写真に近づく。

現代の代表方式

  • シャドウマップ: 光源の位置から世界の深度(奥行き)だけを描いた絵を作り、本番の描画で「この画素は光源から見えているか」を深度比較で判定する。リアルタイム影の標準方式。
  • CSM(Cascaded Shadow Maps。カスケードシャドウマップ。意訳すると「段々重ねの影地図」— cascadeの原義は段々滝で、同じものを段階的に何段も重ねる構成の呼び名): 方向光用の拡張で、カメラからの距離帯ごとに解像度の違うシャドウマップを持つ。近くは細かく、遠くは粗く、という解像度予算の配分方式である。
  • 影の多数決ぼかしとその発展(PCF / PCSS): 影かどうかの判定を周囲の数点の多数決にして境界を滑らかにする方式(PCF)と、遮蔽物からの距離に応じてぼけ幅を変えて本物の半影を再現する方式(PCSS)。数理は第10.6節。
  • レイトレーシング影: GPUのレイトレーシング(光線追跡)機能で光源への遮蔽を直接問い合わせる。シャドウマップの解像度・漏れの問題が原理的に消えるが、GPUの対応と時間予算が要る。
このエンジンの現状

方向光1 + 点光源1 + 環境光係数1つの固定構成。方向光の影は4帯CSM(帯あたり2048px、D32深度の4層配列)が実装済みで、実用分割(近くを密に、遠くを粗く配分する分割式)・テクセルスナップ(カメラ移動で影がちらつくのを止める格子吸着。静止物の影のテクセル座標が不変であることを機械検査済み)・帯境界の重みブレンド・帯別GPU計器まで持つ。布には布専用のシャドウ経路がある。点光源の影は未実装。影のぼけはPCFの基本形で、PCSS級の距離依存半影は未実装。検収入口: cargo xtask csm-seam ほか。

野心的到達形(能力)

(a)任意個数の点光源・スポット光が影を持てる。(b)影の輪郭が遮蔽距離に応じてぼける(PCSS級)。(c)接触部の微小な影(接触影)が拾える。(d)影の品質がカメラ距離・光源数に対して破綻せず、予算内で自動配分される。

方式候補と採用条件

  • 点光源影: キューブマップシャドウ+アトラス管理。採用条件は多光源(4.2でなく本節の光源数拡張)着手と同時。代替はRT影(対応GPUのみ)。破棄条件は仮になし(標準技術)。
  • PCSS級ソフト影。採用条件はCSMの品質定点で「半影の欠如」が絵の弱点として確認されたとき。費用はシーン描画のサンプル数増。
  • RT影(ハイブリッド): 対応GPUで太陽影の遠距離帯やアーティファクトが出やすい細物(草・髪)をRTで置き換える。採用条件は第4.2章のradiance query基盤の成立後。非対応GPUではCSM+PCSSが正本のまま(縮退の型は第7章)。

既存実装への波及

CSM基盤・レンダーグラフ・帯別計器はそのまま土台になる。波及が大きいのは光源の入力型で、現在の「方向光1+点光源1」という固定フィールドは光源の集合(配列)へ置き換える必要がある(作り直し級接合点、第6章(d))。

4.2 間接光と反射 — 絵の説得力の本丸

定義

間接光とは、光源から出た光が壁・床・物体で1回以上跳ね返ってから表面へ届く光のことである。GI(Global Illumination。大域照明・間接光の計算)はこの跳ね返りを扱う技術の総称で、鏡面的な跳ね返りは反射、環境全体からの光はIBL(Image-Based Lighting。周囲の絵を光源として使う照明)、近くの遮蔽で間接光が減る現象はAO(Ambient Occlusion。環境光遮蔽)と、それぞれ名前が付いているが、物理的にはすべて同じ「跳ね返った光」である。

直接光と間接光を言葉で述べると「表面の明るさは、直接届く光と、他の表面で跳ね返ってから届く光の合計である」となる。この関係を1行の式にしたものがレンダリング方程式であり、グラフィックスの全技術はこの式の近似解法だと言える。重要なのは式そのものではなく、「跳ね返りの合計」は原理的に世界全体を見なければ計算できないという性質である。1画素のために世界全体を見る、これが間接光が難しい理由のすべてである。この式の由来(放射輸送理論)と、量の定義を単位から積み上げた丁寧な解説は第10章に置いた。

なぜ絵が良くなるか

現代のAAA級の見た目を決めている支配要因は、直接光ではなく間接光である。定数の環境光(全方向から一様な明るさ)で照らした絵は、影の中が平坦なグレーに沈み、屋内が嘘くさく、時間帯の変化が「明るさのスライダー」にしか見えない。間接光が入ると、影の中に色が宿り、狭い場所が自然に暗くなり、白い壁の部屋全体が柔らかく明るくなる。夕日が部屋の奥まで赤く染める、その1枚がGIの価値である。

現代の代表方式

間接光の解法は「どこに事前計算した光の情報を置き、実行時にどこへ問い合わせるか」で分類できる。

  • スクリーン空間法(SSAO・SSR・SSGI): いま描いた画面自体を「世界の近似」として使い、画面内の情報だけで遮蔽・反射・跳ね返りを推定する。安価だが、画面外・遮蔽裏の情報は原理的に得られない。
  • プローブ法(イラディアンスプローブ・DDGI級): 世界に測定点(プローブ)を格子状に置き、各点で「全方向からの光」を保持・更新する。表面はプローブから補間して間接光を得る。画面外も扱えるが、細かい遮蔽は苦手。
  • 表面キャッシュ+レイトレーシング(Lumen級): 世界の表面に光の計算結果をキャッシュし、レイトレーシング(ハードウェアまたはソフトウェア)で「この方向の先に何があるか」を問い合わせる。現世代AAAの実用解。
  • パストレーシング: 跳ね返りを確率的に全部追う。理論上の正解(参照解)であり、リアルタイムでは最上位GPU+強力なデノイズ(ノイズ除去)が要る。オフライン検証の物差しとしての価値が高い。
設計目標: 共通radiance query

この文書が置く設計目標は、GI・反射・(将来の)RT影を個別機能の寄せ集めにせず、radiance query(放射輝度問い合わせ。「この点からこの方向を見たとき、どれだけの光が来るか」という統一の問い)を1つの入口として設計することである。問い合わせの実装は「スクリーン空間 → プローブ/表面キャッシュ → ハードウェアRT」の優先順位付きの階層で答える。安い情報源で答えられるなら安く、答えられないときだけ高い情報源へ進む。この階層構造そのものが、第7章の縮退設計(低性能機では階層の上位を外す)と直結する。

このエンジンの現状

間接光は環境光係数1つ(定数環境光)のみ。IBL・AO・SSR・GIはいずれも未実装。空はOW5第7段(2026-07-30)でHillaire系ベイク済み画像+Bruneton系参照検証を本番方式として確定し、縦切りだったHosek-Wilkie解析式は資産ごと削除した(正本: _doc/設計/空と時間帯と遠距離シャドウ.md)。つまり光の輸送の観点では、大気散乱は本番方式に達したがIBL・AO・SSR・GIは未着手であり、ここが野心と現状の最大のギャップである。

野心的到達形(能力)

(a)時刻・天候・屋内外を問わず、間接光が動的に成立する(事前ベイク一発焼きへの依存で世界を静的にしない)。(b)鏡面反射が画面外の情報も拾える。(c)AOが接地・隅の暗さを安定して出す。(d)大気は物理ベース(Hillaire系のベイク済み画像)で、体積雲・froxel体積霧(視錐台をセル分割して霧の濃さと光を計算する方式)まで到達する。(e)全体がradiance queryの1階層に統合され、GPU能力に応じて階層の深さが変わる。

方式候補と採用条件

  • 第1段: IBL+SSAO(空と天空状態から作る環境マップ+スクリーン空間AO)。採用条件は多光源より先でよい(現在の定数環境光の置換として最小で最大の画質改善)。破棄条件なし(後続方式の下地としても残る)。
  • 第2段: プローブGI(DDGI級の動的更新プローブ)。採用条件はIBLで「影の中の色」の欠如が品質定点で確認されたとき。
  • 第3段: 表面キャッシュ+RTハイブリッド(Lumen級能力)。ソフトウェアRT(距離場等)を基本にハードウェアRT対応機で精度を上げる。採用条件はradiance query設計の壁打ちを経てから。方式名は固定しない: この階層は技術進歩が最も速い領域であり、着手時点で最良の解法を採用審査する。
  • 参照検証: パストレーサー。リアルタイム経路とは別に、同一シーンの参照解を出すオフラインのパストレーサーを検証入口として持つ(大気でBruneton系を参照に使う構図の一般化)。「正しさを機械で検査する」このエンジンの流儀を光の輸送にも適用する。

既存実装への波及

環境光係数の入力型は光の輸送の設定型へ置換する(第6章(d)と同時)。UBO(GPUへ渡す固定サイズの設定領域)の共通区画464バイトはプローブ・環境マップの参照情報を持てないため、frame constants(フレーム定数)とディスクリプタインデクシングへの分離(第6章(a))が前提になる。レンダーグラフは計算パス(コンピュート)の本格投入先になる。

4.3 材質

定義

材質(マテリアル)とは、表面が光をどう跳ね返すかの記述である。現代の標準はPBR(Physically Based Rendering。物理ベースレンダリング)で、「基本色・粗さ(roughness)・金属性(metallic)」という物理に根ざした少数のパラメータで大半の物体を表す。粗さが低いほど反射は鏡に近づき、金属は光を自分の色で反射する。PBRの利点はどの照明環境に置いても破綻しないことで、材質と光の分業(材質は跳ね返し方だけを述べ、光は光の側で決まる)がその根拠である。

なぜ絵が良くなるか

基本PBRで表せるのは「不透明で、表面が1層の物体」までである。現実の物には層と内部がある。車の塗装はクリア層の下に金属フレークが光り、シャボン玉は薄膜の干渉で虹色になり、肌は光が内部へ潜って散ってから出てくる(これが肌の柔らかさの正体)。水やガラスは透過し、髪は繊維の束として異方的に光る。材質の幅とは、表現できる物体の種類の幅そのものであり、キャラクターの説得力(肌・髪・布)はほぼ材質と専用照明の勝負である。

現代の代表方式

  • 多層マテリアル: クリアコート(塗装の透明層)・薄膜(シャボン玉・油膜)・発光・布(繊維の逆行散乱)などをPBRの変種・追加層として持つ。
  • SSS(Subsurface Scattering。表面下散乱): 肌・大理石・葉のように光が内部で散る材質。スクリーン空間の拡散や専用の事前計算プロファイルで近似する。材質パラメータの追加だけでは成立せず、専用の照明・影・(時間再構成での)安定化が要る点が地雷である。髪も同様に専用照明(異方性ハイライト)と専用の影(細い束の自己遮蔽)が要る。
  • 透明・半透明・水: 描画順と合成の問題(手前から描けない)を伴い、forward経路の維持理由になりやすい(後述)。
  • デカール: 弾痕・汚れ・道路標示のように、表面の上へ後から材質を貼る仕組み。
構造上の地雷: バリアント爆発

材質の種類をシェーダーの条件分岐や個別シェーダーの列挙(バリアント)で増やすと、組み合わせが掛け算で爆発する(材質5種 × 影あり/なし × スキンあり/なし × … で数百本のパイプライン)。生成時間・切替コスト・検証コストのすべてが悪化する。必要なのは「材質特徴ビット(その材質がどの機能を使うか)」と「シェーディングモデル(照明の解き方の種類)」の境界設計であり、どの軸をビットで、どの軸をモデル分岐で、どの軸をパイプライン分割で持つかを最初に決めることである。これはパイプライン管理(4.7)と直結する。

このエンジンの現状

金属粗さPBRを1変種として持つ判別共用体(M11で単一構造体から改修済み)。つまり「材質の種類を増やせる型の器」は既にあり、変種は現在1つである。テクスチャは基本色等を持ち、XPBD布は力学専用経路(材質としては通常PBR)。透明・SSS・髪・デカールは未実装。パイプラインは数本を起動時生成、キャッシュなし(正本: 性能アーキテクチャ方針 軸7)。

野心的到達形(能力)

(a)肌・髪・布・水・ガラス・車塗装・発光体が、それぞれ専用の照明特性で破綻なく描ける。(b)デカールで世界の表面を後から汚せる。(c)材質の追加がパイプライン爆発を起こさない境界設計を持つ。(d)すべての材質が時間再構成(4.4)の下で安定する(ちらつかない)。

方式候補と採用条件

  • 境界設計を先に: 材質特徴ビット×シェーディングモデルの設計壁打ちを、変種を2つ目に増やす前に行う(採用条件: CHAR0着手前)。これが唯一の「先に決めないと後で全部払う」項目である。
  • SSS・髪: CHAR0(キャラクター構成)と同時に採用審査。専用照明+影+安定化のセットで見積もる。
  • 透明・水: forward併用経路(4.2の多光源方式がdeferred系へ進んでも、透明物はforwardで描く構成が標準)として設計。

既存実装への波及

判別共用体の器は正しい方向に既に倒してある(強み)。波及はシェーダーの共通区画(UBO)とディスクリプタ構成(材質ごとのテクスチャ集合が増える)、そしてパイプライン管理(キャッシュ・事前コンパイル)に来る。

4.4 画の完成と時間方向の再構成

定義

ジオメトリと光と材質で「正しい明るさ」が求まっても、そのままでは絵として完成していない。AA(Anti-Aliasing。アンチエイリアシング。画素の格子が生む輪郭のギザつき・ちらつきの除去)、露出(明るさの自動調整)、トーンマッピング(HDRの広い輝度を画面の輝度域へ写す変換)、被写界深度・モーションブラーといった「画の完成」の工程群がある。その中心にあるのが時間方向の再構成: 過去のフレームの情報を今のフレームへ再利用して、1フレームでは足りないサンプル数を時間方向に積み増す考え方である。

なぜ絵が良くなるか(そしてなぜ全体の要か)

1画素1サンプルの絵は、細い物(草・髪・遠くの手すり)が画素格子と干渉してちらつく。TAA(Temporal Anti-Aliasing。時間的AA)は、毎フレーム画素内のサンプル位置を微妙にずらし(ジッタ)、過去フレームの結果と混ぜることで、実質的に画素あたり数サンプル〜十数サンプルの品質を得る。さらにこれを発展させ、低い解像度で描いて時間方向の情報で高解像度を復元するのが時間的アップスケーラ(TSR級。商用ではDLSS・FSRが同系)であり、「描く画素数を減らして品質を保つ」という究極の性能技術でもある。

もう1つ決定的な事実がある。4.2のRTGI・RT反射は、ノイズを時間方向に均すことで初めて成立する(1フレームに撃てるレイは少数で、結果はノイズだらけである。デノイザーは時間再構成の親戚である)。つまり時間方向の再構成は「画の仕上げ」ではなく、光の輸送の野心を支える基盤である。

成立に必要な部品(ここが波及の正体)

  • モーションベクタ: 各画素が前フレームで画面上のどこにいたかのベクトル場。すべての動く物(カメラ・剛体・スキン・布・植生の揺れ)が自分の「前フレームの変換」を保持して出力する必要がある。TAA導入が全描画パスへ波及すると言われる理由がこれである。
  • ジッタ: 射影行列への画素内オフセット注入。ジオメトリ全パスが同じジッタを共有する。
  • 履歴バッファ: 前フレームの結果の保持。無効化(カメラカット)の規律が要る。
  • disocclusion判定(前フレームで隠れていた領域の露出検出): 履歴に無い情報を混ぜるとゴースト(残像)になる。深度・法線・速度の照合で棄却する。
  • 反応性マスク: 履歴を信じてはいけない画素(半透明・パーティクル・急変する発光)を描画側が申告する仕組み。
  • デノイザー共有: RTGI・RT反射・RT影のノイズ除去は同じ時間再構成の部品(モーションベクタ・履歴・棄却)を使う。共通基盤として設計すると二重実装を避けられる。
このエンジンの現状

AAは未実装(MSAAもTAAもない)。これは怠慢ではなく意図した保留であり、「絵の様式確定前にTAAを採用しない」という扉が開けて維持されている(モーションベクタ・履歴・ジッタが存在しないことをM11総点検が確認済み。正本: フェーズ2計画「絵の様式に関する3条件」)。露出は手動(CLIと開発UI)、トーンマップはACES実装済み、ブルーム実装済み。DoF・モーションブラー・自動露出・HDR出力(ディスプレイへの広輝度出力)は未実装。

野心的到達形(能力)

(a)静止画でも動画でもちらつかない安定した画。(b)描画解像度と表示解像度の分離(時間的アップスケーラ)により、同じGPUで画質と性能を両取りする。(c)RT系のノイズを共通デノイザーで均せる。(d)自動露出(ヒストグラムベース)・DoF・モーションブラー・HDR出力・色管理(色空間の一貫した取り扱い)まで含む「画の完成」一式。

方式候補と採用条件

  • 自作TAA → 自作TSR級アップスケーラの順。まずTAA(等解像度)で部品一式(モーションベクタ・ジッタ・履歴・棄却・反応性)を成立させ、その上にアップスケーリングを載せる。採用条件: 絵の様式の確定(このエンジンは写実志向をAAA級方針で実質確定しつつある。オーナーの裁定で扉を閉じる)。
  • DLSS/FSR統合は別判断: ベンダー実装の組み込みは自作基盤の後でも可能(部品の要求はほぼ同じ)。採用条件は対象プラットフォームの決定後。
  • 自動露出: 天空状態→露出の配線が既にあるため、ヒストグラム自動露出は時刻システムの自然な拡張として先行導入できる(採用条件: ポスト系で最初)。

既存実装への波及

7領域の中で波及が最も広い。全描画対象への前フレーム変換の保持(エンジンデータ層)、全ジオメトリパスへのモーションベクタ出力(シェーダー層)、射影へのジッタ注入(カメラ層)、履歴画像の資源管理(レンダーグラフ層)。導入が遅いほど対象パスが増えて改修が膨らむため、「いつ様式を確定するか」の判断自体が費用を決める。第8章の着手順でこれを扱う。

4.5 物量 — ジオメトリとアニメーション

定義

物量とは、1フレームに存在してよい物の数と細かさのことである。森の木の1本1本、草の1株1株、群衆の1人1人。物量の技術は「見えている物だけを、必要な細かさだけで描く」ための選別技術であり、カリング(視界外・遮蔽された物の除外)とLOD(Level of Detail。距離に応じた詳細度の切替)が二本柱である。

なぜ絵が良くなるか

世界の説得力は密度で決まる。まばらな森は書き割りに見え、地平線まで描かれた森は世界に見える。ただし物量は品質の掛け算の分母でもある: 物が10倍になれば、影も、間接光の受け手も、読み込む データも10倍になる。物量技術の本質は「数に対して費用が線形に増えない構造」を作ることである。

現代の代表方式

  • インスタンス描画: 同じ形状の物(木・草)を1回の描画命令でまとめて描く。数の基本解。
  • GPU駆動描画: 「何を描くか」の選別(カリング・LOD選択)自体をGPUの計算シェーダーで行い、GPUが自分で描画引数を作る(間接描画)。CPUの関与が物の数に比例しなくなる。
  • メッシュシェーダー: 三角形の生成・選別をGPUの新しいパイプライン段で行う機能。クラスタ(小さな三角形の束)単位の細かいカリングに向く。
  • 仮想化ジオメトリ(Nanite級): メッシュをクラスタの階層(粗い〜細かい)へ事前分解し、実行時に画面上の誤差が一定以下になる階層だけをストリーミングして描く。「ポリゴン数を画素数に比例させる」発想の転換であり、現世代の最高峰。本体はGPU実行よりもオフライン側にある: メッシュのクラスタ分解(meshlet生成)・誤差指標の計算・ページング可能な実行時形式という、アセットパイプラインの大改造が実態である。
  • アニメーション側の物量: スキニング(骨で皮膚を動かす)・モーフ(頂点の混合)・群衆(数百体の簡略アニメ)・IK(Inverse Kinematics。接地や把持のための逆算)・モーションマッチング(大量の収録動作から次の1歩を選ぶ方式)・GPUスキンキャッシュ(スキン結果を再利用して影・複数パスでの二重計算を消す)。
このエンジンの現状

物量の土台はOW4で実証済みの強みである。インスタンス群+2段階可視判定+個体別LOD+直接描画で、常駐100万個体でも描画発行数は一定(シーン40・シャドウ30)、GPUメモリ確保も687件で不変。群選択(可視判定+LOD選択+ID列組み立ての融合走査)は個体あたり約10ナノ秒で物量に対し線形。ただし観測範囲全体の支配区間はこの群選択CPUであり、100万個体で約10ミリ秒(16.6ミリ秒フレームの6割)を占める。間接描画・GPU駆動カリングは「現物量では律速でない」ため不採用判定(覆す条件付き)。メッシュシェーダー・仮想化ジオメトリ・遮蔽カリングは未着手。アニメーションはスキニング+アニメーション再生(M8)とXPBD布(M9)まで。地形は5段LOD+チャンクストリーミング実装済み。

野心的到達形(能力)

(a)画面のポリゴン密度が「画素数準拠」になる(距離によるポリゴンの節約が見た目に現れない)。(b)物の数がCPU時間を支配しない(GPU駆動の選別)。(c)遮蔽カリング(建物の裏の街を描かない)が動的に効く。(d)群衆・植生・地形が同じ物量基盤の上で暮らす。(e)キャラクターはIK・モーションマッチング級の動作品質を持つ。

方式候補と採用条件

  • 群選択の階層化(粗い階層での早期棄却): 性能アーキテクチャ方針 軸6が既に指名している次の一手。採用条件は実運用の常駐個体数の確定(視界距離の制定)。並列化はその次。
  • GPU駆動カリング+間接描画: 採用条件は「AAA級の代表シーン(実アセットの密度)でコマンド記録またはCPU選別が支配要因になる計測」。現在の不採用判定は検証世界前提であり、代表シーンの成立が再判定の引き金である(第8章)。
  • 仮想化ジオメトリ: 野心枠。採用条件は(a)実アセット(数百万ポリ級の彫刻的メッシュ)の採用方針決定 (b)アセットコンパイラ(OW1)へのクラスタ分解・誤差指標・ページング形式の拡張見積もり。アセット実行時形式への最大級の波及点であり、テクスチャの仮想化(4.6)と波及先が同じため同時に審査する。
  • 群衆・モーションマッチング: CHAR0以降。SIM0(シミュレーション実行基盤)との接続で審査。

既存実装への波及

インスタンス基盤・可視ID列・チャンク所有構造は土台として残る。仮想化ジオメトリはアセットコンパイラと実行時形式(OW1の成果物)への版追加が本体(第6章(c))。GPU駆動化はレンダーグラフへの計算パス+間接引数バッファの追加で、器は既にある。

4.6 世界読込 — ストリーミングとテクスチャ

定義

世界読込とは、メモリに収まらない大きさの世界を、プレイヤーの周囲だけメモリへ載せ続ける技術である。ストリーミング(移動に応じた読込・解放)と、その最大の顧客であるテクスチャ(画像データ。容量の主犯)の管理からなる。品質語彙としてはヒッチレス: 読込がフレーム時間の突発的悪化(ヒッチ)として画面に現れないこと、を到達目標に置く。

なぜ絵が良くなるか

ストリーミングは「見えない品質」である。うまく動いている間は誰も気づかず、失敗すると世界が壊れる(ポップイン: 目の前で建物が出現する。ヒッチ: 歩くたびに画面が引っかかる。ぼけ: テクスチャの解像度が間に合わずぼやけたまま)。AAA級のシームレスなオープンワールドとは、ロード画面の削除ではなく、この3つの失敗が起きない読込の設計のことである。

現代の代表方式

  • BC系テクスチャ圧縮(Block Compression。GPUが直接読める固定比圧縮): VRAMと帯域を1/4〜1/8にする。非圧縮運用との差は「あれば良い」でなく桁違いで、実アセットを入れる前提条件に近い。
  • ミップストリーミング: テクスチャの解像度段(ミップ)のうち、いま必要な段だけをVRAMへ置く。遠くの建物に4Kテクスチャの最上段は要らない。
  • 仮想テクスチャ: テクスチャをページ(小タイル)単位で管理し、画面が実際に要求したページだけを読み込む究極形。仮想化ジオメトリと思想が同じで、実行時形式への波及も同じ場所に来る。
  • 非同期転送: 読込データのGPU転送を描画と別のキュー(転送キュー)で行い、フレームを止めない。
このエンジンの現状

チャンクストリーミング基盤はOW2〜OW4で実装済みの強み: 格子・目録・予算・台帳・読込器が接続され、30分反復でメモリ横ばい・読込解放が決定的に再現。地形+植生同居で、LOD切替が読込もGPU再確保も起こさない配置(全段常駐)を実証済み。既知の弱点は2つ: (a)束追加フレームに50ミリ秒級のスパイク(同期的な転送送信とフェンス待機由来と推定、非同期転送キュー未着手) (b)テクスチャの実行時形式が非圧縮で、ミップストリーミングも無い。容量予算の実運用値も未制定(検証世界の実測まで。正本: 評価軸3.5)。

野心的到達形(能力)

(a)移動し続けてもフレーム時間の分布が変わらない(ヒッチレスの定量定義: 束追加フレームのp99がフレーム予算内)。(b)テクスチャ品質が「見る距離で必要な解像度」に常に一致する(ぼけの滞留なし)。(c)VRAM使用量が予算駆動で制御され、超過時の品質縮退が無言でなく方針として起こる。

方式候補と採用条件

  • BC圧縮+ミップ生成をアセットコンパイラへ: 採用条件は実アセット(写実テクスチャ)の導入開始。決定的コンパイルの流儀(同一入力→同一出力)は維持する。
  • 非同期転送キュー: 採用条件は既定(実物量で50ミリ秒級スパイクの再現)に「品質駆動: ヒッチレスを到達形に採用した時点で前倒し」を追加提案する。
  • ミップストリーミング → 仮想テクスチャの順: ページング形式の設計は仮想化ジオメトリと同時に審査(波及先が同じため)。

既存実装への波及

ストリーミング調停・予算・台帳の構造は残る。実行時形式への版追加(第6章(c))とレンダーグラフの部分mip/layer追跡(第6章(b))、転送キュー導入によるキュー所有権(queue ownership。資源をどのキューが使ってよいかの移譲管理)の扱いが波及点である。

4.7 並列実行と実行基盤

定義

実行基盤とは、CPUとGPUの計算資源を使い切り、かつフレーム時間を安定させるための、絵に直接は見えない技術群である。CPU側のジョブシステム(仕事を細かい単位に割ってコア全部へ配る仕組み)、GPU側の非同期コンピュート(描画と計算を別キューで並行させる)、PSO事前コンパイル(PSO = Pipeline State Object。描画設定一式の事前生成。実行中の生成はカクつきの主犯)、動的解像度とVRS(Variable Rate Shading。画面の領域ごとにシェーディングの密度を変える機能)、フレームペーシング(フレームの提示間隔を均す制御)、GPUクラッシュ診断、資源常駐予算の管理までを含む。

なぜ絵が良くなるか

この領域の品質は「平均フレームレート」ではなくフレーム時間の分布に現れる。平均60fpsでも、時々30ミリ秒のフレームが混ざる絵は「カクつく絵」である。AAA級の滑らかさとは分布の裾(p99: 100フレームに1回の悪い方の値)の管理であり、実行基盤はその裾を作る全要因(実行中のパイプライン生成・同期待ち・転送・提示のずれ)を退治する仕事である。また、使い切れていない計算資源は品質の原資である: 非同期コンピュートでGPUの空きを埋めれば、同じハードでより多くの品質(GI・シミュレーション)を買える。

このエンジンの現状

CPUは単一スレッド(世界更新・コマンド記録とも)。GPUは単一グラフィックスキュー+FIFO提示+フレームインフライト2。実表示時刻の計測入口(present_id/present_wait)を持ち、更新脱落の観測までできる(このレベルの提示計測を最初から持つのは強み)。パイプラインは起動時生成でキャッシュなし。GPU計器(パス別・帯別)と検収入口の網は充実。ジョブシステム・非同期コンピュート・動的解像度・VRS・クラッシュ診断は未着手。フレーム時間分布の計測はp50/p99の器あり(評価軸3.4)。

野心的到達形(能力)

(a)CPUの全コアが世界更新・選別・記録を分担する(ジョブシステム)。(b)GPUの描画の空き時間をシミュレーション・GI更新・選別計算が埋める(非同期コンピュート)。(c)実行中のシェーダー/PSO生成が起きない(事前コンパイル+永続キャッシュ)。(d)フレーム時間p99が予算内で、負荷変動には動的解像度・VRSが先に応答して画質の谷を最小化する。(e)GPUクラッシュが再現手順つきで診断できる。

方式候補と採用条件

  • ジョブシステム: 採用条件は既定(CPU律速の実測。群選択10ms/100万個体で実質満ちつつある)+方針の「先に走査数を減らす階層化」を経てから。Rustではワークスティーリング型(仕事を奪い合う分配方式)の採用審査(既存クレートか自作か)を行う。
  • 非同期コンピュート: 採用条件は既定(SIM系で3.0ms超の独立区間の実測)+品質駆動(GI更新パスの導入時)。レンダーグラフのキュー割り当て拡張(第6章(b))が前提。
  • PSO事前コンパイル+永続キャッシュ: 採用条件はマテリアル境界設計(4.3)の確定と同時。バリアント数の管理と一体で設計する。
  • 動的解像度・VRS: 採用条件は時間的アップスケーラ(4.4)の成立後(解像度可変の受け皿がアップスケーラだからである)。

既存実装への波及

フレームループの逐次実行はコンポジションルートに一元化されており、段階単位の並列化は局所改修で済む(軸6の可逆性判定)。非同期コンピュートはレンダーグラフのサブリソース追跡+キュー所有権(第6章(b))が本体。計測・検収の網は全項目でそのまま武器になる。

接合点 a

共通UBO 464バイトと固定バインディング。現在は主要なグラフィックス経路のシェーダー群が1つの共通フレームUBO(464バイトの固定サイズ設定領域)を全体または先頭部分として共有する(個体・材質の設定や計算系の専用バッファは別に持つ)。光源が集合になり、ビューが増え(影・プローブ・反射)、材質が多様化すると固定区画は持たない。小さいframe constants(フレーム定数)と、structured buffer(可変長の構造化バッファ)+ディスクリプタインデクシング(資源を番号で選ぶ方式)への分離移行が必要である。多光源・GI・材質拡張のすべてがこの上に載るため、最初に動く境界になる。

接合点 b

7. 縮退設計の思想 — 低性能デバイスでも最高品質

オーナーの方針の後半「まともに実装すれば低性能デバイスでも最高品質がキチンと動くはず」を、この章で技術の言葉に定義する。

まず正直な物理から始める。計算量は消えない。低性能GPUは単位時間に計算できる量が少なく、「同じ絵」を「同じ時間」で出すことは原理的にできない。ではこの方針は不可能かというと、そうではない。方針の技術的な意味は「品質の落ち方を設計する」ことである。雑な実装は低性能機で「動かない・カクつく・壊れる」へ落ちる。まともな実装は「同じ絵作りのまま、目に付きにくい要素から順に、予測可能に軽くなる」へ落ちる。この落ち方の設計を縮退設計と呼ぶ。

原則1: 機種差は同一方式の品質段階で吸収する

第一の手段は、方式を変えずに量を変えることである: 描画解像度(時間的アップスケーラが受け皿)・影の解像度と距離・プローブの密度・レイの本数・LODの距離・霧のセル数。これらは連続的なつまみであり、同じ方式の中の品質段階なので、絵作り(アートの意図)が壊れない。つまみが増えるほど縮退は滑らかになる。第4章の方式候補が軒並み「解像度・密度・回数」のパラメータを持つ方式に寄せてあるのは、このつまみを最初から持つためである。

原則2: 機能非対応は正直に型化する

ただし、つまみで吸収できない断絶が1つある: ハードウェア機能の非対応である。レイトレーシング非対応のGPUに「レイを減らしたRT」は存在しない。この場合は同じ物理目標(例: この点への間接光)を別の解法(プローブ/スクリーン空間)で近似することになり、「同一方式の解像度違い」では両立しない。このエンジンの流儀に従い、この断絶を無言のフォールバックにせず、品質段階の型として正直に表す: どの解法で動いているかは型と計器に現れ、検収は段階ごとに行う。radiance queryの階層構造(4.2)は、この型化を最初から設計に織り込むための器である。

原則3: 効率は品質である

「極限性能」は縮退とは独立に、全機種の品質を底上げする。同じ16.6ミリ秒から無駄(不要な同期・二重計算・使われない計算資源)を取り除けば、その分を品質に使える。このエンジンの日常の性能規律(計測不要で悪いと分かる無駄を最初から書かない)と計測文化(予算表・GPU計器・p99)は、この意味で品質方針の一部である。低性能機で効くのは高性能機と同じ最適化であることが多い。

8. 能力予算と着手順

最後に、この野心をどの順で作るかの提案である。並びは依存関係順(先行が後続の前提になる順)であり、規模順でも重要度順でもない。フェーズ2計画の既存マイルストーン(OW/SIM/CHAR/UI)との接続を併記する。

判断の枠組みへの提案: 品質駆動の着手条件

現在の性能アーキテクチャ方針の着手条件は全て性能駆動(計測で律速が実証されたとき)である。これに品質駆動(品質目標がその方式を要求すると裁定されたとき)を第二の着手条件として追加することを提案する。大気のベイク済み画像への置換(計測上は問題が無いのに品質目標が方式を要求した例)を一般化するものである。どちらの駆動で着手したかを記録すれば、判断の追跡可能性も保たれる。

用語意味
シャドウマップshadow map = 直訳「影の地図」意訳: 光源から撮った距離の写真。「光源から見えている=影でない」の判定台帳光源から見た深度だけを描いた絵。本番の描画がこれと深度を比べて、その画素が光源から見えているかを判定する。
CSMCascaded Shadow Maps = 直訳「段々滝式に重ねた影地図」(cascadeの原義は段々滝)意訳: 距離別の影地図セット。近く用の細かい地図と遠く用の粗い地図を段々に持つ方向光用に、カメラからの距離帯ごとに別のシャドウマップを持つ方式。近くは細かく遠くは粗く解像度を配分する。本エンジンは4帯を実装済みである。
帯(距離帯)cascade(段)の1つ。本文書では「帯」と訳す意訳: CSMの1段ぶんの受け持ち距離範囲CSMの1つの距離区間。専用の正射影とシャドウマップの層を持ち、帯の境界には重なりとブレンドを置く。本エンジンは4帯である。
テクセルスナップtexel = texture element(テクスチャの升目1つ) / snap = 磁石のようにパチンと吸着すること意訳: 影地図の升目への吸着。カメラが動くたび影の升目がずれてちらつくのを、升目単位でしか動かないよう吸着して止めるカメラの移動でシャドウマップの格子の位相が変わり影がちらつくことを、格子への吸着で止める技法。テクセルはシャドウマップを構成する1つの升目である。
PCF / PCSSPercentage-Closer Filtering = 直訳「(光源に)より近い割合によるぼかし」/ Percentage-Closer Soft Shadows = 直訳「より近い割合による柔らかい影」意訳: 影の多数決ぼかし。「この点は影か?」を周囲の数点に聞き、影だった票の割合で濃さを決める(0か1かでなく0.6の影が作れる) / その発展版で、遮蔽物が遠いほど聞き込みの範囲を広げて、本物の半影のように縁のぼけ幅を変える影の境界を複数サンプルの平均で滑らかにする方式 / 遮蔽物からの距離に応じて半影の幅を変える方式。
半影 / 接触影penumbra = ラテン語 paene(ほとんど)+umbra(影)。「ほとんど影」/ contact shadow意訳: 影の縁のぼんやり帯(光源に大きさがあるため生じる) / 物と床が触れる際の細く濃い影(接地感の決め手)遮蔽物から離れるほど広がる影の柔らかい縁 / 物が接する部分に出る細く濃い影。
レイトレーシング(RT)ray tracing = 直訳「光線の追跡」意訳: 光線の一本釣り。「この方向へ進んだら何に当たるか」を幾何学的に直接調べる光線を飛ばして最初に当たる面を求める計算。近年のGPUは専用の機構を持つ。影・反射・間接光の問い合わせに使う。
クラスタードライティングclustered lighting = 直訳「(空間の)房分けによる照明」(clusterはブドウの房)意訳: 光源の学区割り。視界を小部屋に分け、各小部屋に届く光源だけを名簿にしておく。画素は自分の小部屋の名簿だけ見ればよい視錐台をセルへ分割し、各セルに影響する光源を事前に絞る多光源の標準技法。

間接光と大気の語

用語意味
GIGlobal Illumination = 直訳「大域の照明」(global = 局所でなく世界全体の)意訳: 回り込む光の計算。壁や床で跳ね返って届くぶんまで含めた照明。RTGIはこれをレイトレーシングで解く版大域照明。光源から1回以上跳ね返って届く間接光の計算。RTGIはレイトレーシングで解くGIを指す。
IBLImage-Based Lighting = 直訳「画像に基づく照明」意訳: 風景写真を光源にする照明。周囲の絵の全画素を小さな光源とみなして足し込む周囲環境の絵(環境マップ)を光源として使う照明。
AOAmbient Occlusion = 直訳「周囲光の遮蔽」/ SSAOのSSはScreen Space(画面空間)意訳: 隅の暗がりの近似。物の隙間や巻き込みは周囲の光が入りにくく暗くなる、あの現象環境光遮蔽。近くの遮蔽物により間接光が減る現象の近似。SSAOはスクリーン空間で解く版である。
SSRScreen Space Reflection = 直訳「画面空間の反射」意訳: 画面内リサイクル反射。すでに描いた画面の中から映り込みの材料を探すスクリーン空間反射。描いた画面の中の情報だけで反射を作る方式。
スクリーン空間法screen space = 画面空間(3次元の世界でなく、描き上がった2次元の画面の上で考えること)意訳: 描いた絵の使い回し。画面をそのまま「世界の簡易模型」として遮蔽や反射の推定に流用する。画面の外は原理的に見えないいま描いた画面自体を世界の近似として使い、画面内の情報だけで遮蔽・反射・跳ね返りを推定する方式の総称(SSAO・SSR・SSGI)。安価だが、画面の外と遮蔽の裏の情報は原理的に得られない。
radiance query(放射輝度問い合わせ)「この点からこの方向を見たとき、どれだけの光が来るか」という統一の問い。本文書がGI・反射・RT影の設計目標に置く抽象である。
プローブ
意訳: 探針・観測点。世界に差し込んだ光の温度計のようなもの		世界に置いた光の測定点。周囲の表面はプローブから補間して間接光を得る。DDGIは動的に更新するプローブ方式である。
表面キャッシュsurface cache(cache = 隠し置き場・貯蔵庫)意訳: 壁に書き溜める光の帳簿。一度計算した表面の明るさを貯めて使い回す世界の表面に光の計算結果を貯めて再利用する方式。Lumen級のGIの部品である。
パストレーシングpath tracing = 直訳「(光の)道筋の追跡」意訳: 光の道のくじ引き総当たり。跳ね返りの道筋をランダムに1本ずつ引いて平均すると正解に収束する(数理は第10.3節)光の跳ね返りを確率的に全部追う計算。理論上の正解(参照解)を出すため、検証の物差しに使える。
レンダリング方程式rendering equation(render = 描画する。原義は「差し出す・表現する」)意訳: 絵作りの大元の1本の式。「出る光=自ら光る分+入ってくる光×跳ね返し」。丁寧な導出は第10.3節「表面の明るさ=直接光+跳ね返って届く光の合計」を1行にした式。グラフィックスの全技術はこの式の近似解法である。
環境マップenvironment map = 直訳「環境の地図」意訳: 周囲の風景の全方位写真。箱(キューブマップ)や球に貼って使う周囲の風景を1枚の画像(立方体または球)へ収めたもの。IBLではこれを光源として使う。
ベイク済み画像元来はLUT(Look-Up Table) = 直訳「引くための表」意訳: 計算の作り置き表。毎回計算せず、前もって解いた答えの表を参照するだけにする計算結果をあらかじめ表へ焼いておき、実行時は表を参照するだけにする手法。大気散乱の計算はベイク済み画像化が現代の標準である。
Hosek-Wilkie解析式空の放射輝度を少数の係数の式で近似する解析モデル。安価だが物理的な自由度が低い。本エンジンではOW5第7段(2026-07-30)までの縦切りの暫定としてこれを使い、Hillaire系ベイク済み画像への置換完了時に資産ごと削除した。
天空状態時刻から決定的に導出される、太陽方向・方向光の色と強度・環境光・露出補正段・空の係数・影の有効性の束。エンジン側の純関数が返し、レンダラーは導出済みの状態だけを受け取る。
froxelfrustum(視錐台)+voxel(立体画素)の合成語意訳: 視界のさいの目切り。カメラの視界を奥行き方向にも輪切りにした小箱1つ1つ視錐台をセルへ分割して霧と光を計算する体積表現。
レイマーチray marching = 直訳「光線の行進」意訳: 光線の一歩ずつ進み。霧の中を少しずつ歩きながら「ここの濃さは? 届く光は?」を足し込んでいく計算光線に沿って一定の刻みで進みながら、濃さと届く光を積算する計算。体積雲・体積霧に使う。
ベイク(事前計算)
意訳: 焼き込み。パンを焼くように、計算結果を前もって固めて保存すること		実行前に光などの計算結果をデータへ焼き込むこと。安価だが、焼いた前提が変わる変更(時刻の移動・物の移動)には追随できない。

用語意味
シェーディングモデル / 材質特徴ビット照明の解き方の種類(標準・肌・髪など) / その材質がどの機能を使うかを表すビットの集合。どちらの軸で分けるかがパイプラインの本数を決める。
バリアント爆発材質と機能の組み合わせで、シェーダーとパイプラインの本数が掛け算で増える問題。生成時間・切替コスト・検証コストのすべてが悪化する。
SSSSubsurface Scattering = 直訳「表面下の散乱」意訳: 肌の透け感の正体。光が皮膚の内側へ少し潜り、散ってから出てくる現象(耳を逆光で見ると赤く透ける、あれ)表面下散乱。肌・大理石・葉のように、光が内部で散ってから出てくる材質の表現。
クリアコート / 薄膜clear coat = 直訳「透明な上塗り」/ thin film = 薄い膜意訳: 車のツヤ層(色の上の透明ニス) / シャボン玉の虹色を作る極薄の膜車塗装の透明な層 / シャボン玉のような干渉色の層。多層マテリアルの代表である。
デカールdecal = 転写シール(プラモデルのデカールと同じ語)意訳: 後貼りシール。壁の弾痕や道路の白線を、面の上へ後から貼る表面の上へ後から貼る材質(弾痕・汚れ・道路標示等)。
判別共用体discriminated union = 直訳「判別つきの合併」意訳: 場合分けを型にしたもの。「AかBかCのどれか」を、どれかを確かめてからでないと中身に触れない形で持つ取りうる場合を型で列挙し、どの場合かを判別してから中身に触ることを強制する型。材質の種類を安全に増やすための器として本エンジンが採る。
XPBD布Extended Position-Based Dynamics = 直訳「拡張・位置ベース動力学」意訳: 力でなく位置を直接直す物理。布の点どうしの距離が伸びすぎたら位置を引き戻す、を繰り返す実時間向きの解き方位置を直接補正する実時間物理手法で解く布。本エンジンは布専用のシャドウ経路を持つ。
スキニング / スキンskinning = 直訳「皮を張ること」意訳: 骨に皮を張る処理。骨格の動きに皮膚や服の頂点を追従させる骨(ジョイント)の姿勢に合わせて頂点を動かし、皮膚や服を変形させる処理。モーフは頂点位置の混ぜ合わせによる別方式である。
forward / deferred / visibility buffer
意訳: その場払い方式 / 後払い方式(deferredは「後回しにした」の意。照明の支払いを後でまとめて行う) / 後払いの徹底版(何が見えるかの番号だけ先にメモする)		描きながら照明まで計算する方式 / 材質情報を一旦絵(G-buffer。画面全画素の材質・法線・深度を格納する中間画像群)へ書き、後から照明する方式 / 可視面のIDだけを書き、材質の評価を後段で行う方式。
AA(アンチエイリアシング)
意訳: ぎざぎざ・ちらつき対策。aliasing(偽信号化)への対抗策の意		画素の格子が生む輪郭のギザつき・ちらつきを除去する技術の総称。MSAAは1フレーム内で完結するGPU標準装備の方式である。
TAA(Temporal Anti-Aliasing)
意訳: 時間ためこみ式ぎざぎざ対策。過去フレームを貯めて使い回す		毎フレームサンプル位置をずらし(ジッタ)、過去フレームと混合して品質を稼ぐAA。時間方向の再構成の基本形である。
時間的アップスケーラ(TSR級)temporal upscaler = 直訳「時間を使う拡大器」。TSR = Temporal Super Resolution(時間的超解像)。DLSS = Deep Learning Super Sampling(深層学習超サンプリング)。FSR = FidelityFX Super Resolution意訳: 過去フレームの貯金で解像度を水増しする仕組み。小さく描いて大きくきれいに見せる低い解像度で描き、時間方向の情報から高い解像度を復元する方式。DLSS・FSRが商用の同系である。
ジッタ
意訳: 小刻み揺らし。狙いをわざと毎回少しずらすこと		毎フレーム、画素の中のサンプル位置を微小にずらすこと。時間方向にサンプルを散らし、混合によって画素あたりのサンプル数を稼ぐ。
モーションベクタmotion vector = 直訳「動きの矢印」意訳: 各画素の「前はどこにいたか」メモ。過去フレームから対応点を探すための矢印各画素が前フレームで画面上のどこにいたかを表すベクトル場。時間再構成の必須部品である。
履歴バッファhistory buffer = 履歴の一時置き場意訳: 前フレームの絵の貯金箱前フレームの結果を保持しておく画像。カメラが切り替わったときなどに無効化する規律が要る。
disocclusiondis-(解除) + occlusion(遮蔽) = 直訳「遮蔽の解除」意訳: 物陰から現れたばかりの領域。前フレームには映っていないので過去の貯金が使えない前フレームでは隠れていた領域が、今フレームで露出すること。履歴が無いためゴーストの主因になる。
ゴースト(残像)ghosting = 直訳「幽霊化」意訳: 動く物の後ろに残る半透明の尾。古い絵を間違って混ぜた痕跡前フレームの情報を誤って混ぜたために、動く物の後ろへ尾を参照する欠陥。
反応性マスク履歴を信用してはいけない画素(半透明・急変する発光等)を、描画側が申告する仕組み。
デノイザー
意訳: ざらつき取り。少ない標本のまだら模様を均す係		レイトレーシング等の少ないサンプルの結果からノイズを除く処理。時間再構成と部品を共有する。
露出exposure = カメラ用語(フィルムを光にさらすこと)の訳語意訳: 絵全体の明るさのつまみ。人間の目が暗がりに慣れるのと同じ調整トーンマッピングの前に輝度へ掛ける倍率。カメラの露出設定に相当し、シーン全体の明るさを決める。本エンジンは現在手動である。
ヒストグラム自動露出histogram = 度数分布図意訳: 画面の明るさの分布を集計して、つまみを自動で回す仕組み画面の輝度の分布(ヒストグラム)を集計し、明るさに合わせて露出を自動で決める方式。
HDR / トーンマッピング / ACESHigh Dynamic Range = 直訳「広い明暗の幅」/ tone mapping = 直訳「明暗の写し替え」/ ACES = Academy Color Encoding System(米映画芸術科学アカデミーの色符号化標準)意訳: 太陽から暗闇まで本物の明暗幅のまま計算すること / それを画面が出せる幅へ上手に潰す変換 / 映画業界標準の潰し方カーブ広い輝度域のまま計算すること / それを表示できる輝度へ写す変換 / 映画業界で標準的に使われる変換カーブ。
ブルーム
意訳: 光のにじみ。bloomは花が咲く・ぼうっと広がるの意		高輝度の部分が周囲へにじむ現象の再現。抽出・ぼかし・加算合成の3段で作る。本エンジンは実装済みである。
被写界深度(DoF)Depth of Field = 直訳「ピントの合う場の深さ」。写真用語の訳語意訳: ピントの幅。手前と奥をぼかして「カメラで撮った感」を出す加工ピントの合う奥行きの幅。範囲の外をぼかしてレンズらしい絵にするポスト処理。
モーションブラーmotion blur = 直訳「動きによるぶれ」意訳: 速い物の流れぶれ。シャッターが開いている間に動いた分のぶれの再現露光している間の動きによるぶれの再現。モーションベクタを入力に使う。
ポストプロセスpost-process = 直訳「後工程・後処理」意訳: 撮った後の現像・加工。絵が描き上がってから全体にかける仕上げシーン描画の完成後に画像全体へかける加工の総称(トーンマッピング・ブルーム・被写界深度等)。画面全体を覆う図形を1枚描く、画像から画像へのパスとして実装する。
色管理color management意訳: 色の座標系の取り違え防止。「この数値はどの色空間の値か」を工程間で揃える規律線形・sRGB・広色域といった色空間を工程ごとに取り違えず、一貫して扱うこと。

モーションマッチングmotion matching = 直訳「動作の照合」意訳: 動きの辞書引き。大量に録った実演データから「今の状況に一番合う次の1コマ」を毎フレーム検索する大量に収録した動作データから、次のポーズを検索で選ぶアニメーション方式。
GPUスキンキャッシュskin cache = スキニング結果の貯蔵庫意訳: 変形結果の使い回し。骨で動かした後の頂点を保存し、影の描画などで二度計算しないスキニングの結果を保存し、影など複数のパスでの再計算を消す仕組み。
チャンクchunk = かたまり・ぶつ切りの1個意訳: 世界のタイル1枚。読み込みと片付けはこのタイル単位で行う世界をXZ平面で一定の一辺長に区切った1区画。読込と解除の単位であり、描画対象は所有チャンクを持つ。

10. 数理と物理の背景 — なぜグラフィックスはこう考えるのか

この章は、第4章までの技法の下にある理学(物理と数学)を、単位を保ったまま最初から積み上げる。グラフィックスの数理を扱う本の多くは、量の定義を飛ばして式を出したり、未定義の言葉で別の未定義の言葉を説明したりする。この章はその逆を行く: すべての量を「何を数えているのか」と「単位」から定義し、式は定義の組み合わせとしてだけ出す。

もう1つ、この章が正面から扱うのはグラフィックスが物理を意図的に歪めている箇所である。グラフィックスは理学ではなく工学であり、「毎秒60回、間に合う範囲で最も物理に近い答えを出す」ための近似の体系である。どこで何を捨てたかを知らないと、技法は暗記になる。逆にそれを知っていれば、新しい技法を見ても「ああ、あの捨てた部分をこう繕うのか」と読める。歪めた箇所は本文の随所で 歪み の札で示し、10.11節に目録を置く。

10.1 光をどう数えるか — 単位を保った放射の量

最初の歪み: 光を「線」として扱う

歪み 1: 幾何光学近似

光の正体は電磁波であり、波長(可視光でおよそ400〜700ナノメートル)・回折・干渉・偏光という波の性質を持つ。グラフィックスはこれをほぼ全部捨てて、光を直進する光線(ray)として扱う。これを幾何光学近似という。捨てられる理由は寸法の桁差である: 波の性質が目立つのは障害物が波長と同程度のときで、シーンの物体(ミリメートル以上)は波長より1万倍以上大きい。破れる場所も決まっている: シャボン玉や油膜の虹色(薄膜干渉)、CDの裏面の虹(回折)は波の現象なので、光線の枠では出ない。これらは第4.3章の薄膜マテリアルのように、結果だけを別式で貼り戻す。

量の積み上げ: 束 → 密度 → 密度の密度

光線の世界で「明るさ」を数える量は、粗い量から細かい量へ3段で積み上がる。ここが教科書で最も飛躍しやすい場所なので、1段ずつ確かめる。

第1段: 放射束(ほうしゃそく) Φ [W]。ある面を単位時間に通るエネルギーの総量である。単位はワット(ジュール毎秒)。電球のパッケージに書いてある消費電力と同じ次元の量で、「どこへ向かう光か」「どの面積を通る光か」の情報を持たない、いちばん粗い量である。

第2段: 放射照度(ほうしゃしょうど) E [W/m²]。面が受け取る放射束の面積密度である。「この机の1平方メートルに毎秒何ジュール届いているか」。日焼けの度合いやソーラーパネルの発電量を決めるのはこの量である。ただしまだ「どの方向から来たか」を区別しない: 真上からの1Wも、あらゆる方向からかき集めた1Wも、同じE=1W/m²である。

寄り道: 立体角(りったいかく) [sr]。「方向の広がり」を数える量が要る。平面の角度(ラジアン)が円弧の長さ/半径であるのと同様に、立体角は球面上の面積/半径の2乗で定義する。単位はステラジアン(sr)。全方向(球面全体)は 4πr2r2=4π sr、半球(表面から見える空の全部)は 2π sr である。腕を伸ばした親指の先はおよそ0.00006srで、太陽と満月はどちらも偶然ほぼ同じ0.00006sr程度に見える(だから日食が起こる)。

第3段: 放射輝度(ほうしゃきど) L [W/(m²・sr)]。面積あたり・かつ・方向あたりの放射束の密度である。「この1平方メートルから、この方向の1ステラジアンへ、毎秒何ジュール出ているか」。定義が2重の密度なので取っつきにくいが、グラフィックスの主役はこの量ただ1つである。理由は2つある。

  1. カメラの1画素と目の1視細胞が測っているのは放射輝度である。画素は「小さな面積」から「小さな方向範囲」を通ってきた光だけを受けるからである。第2章の「画素の色」の正体は、その画素へ向かう光線の放射輝度(をRGBで3標本にしたもの)である。
  2. 放射輝度は、何もない空間を進む光線に沿って変わらない(真空中の不変性)。壁が1m先にあっても100m先にあっても、壁の同じ点を見たときの「見かけの明るさ」は同じである — 遠い物は暗くなるのではなく小さくなる(立体角が減る)。受け取る総エネルギーは距離の2乗で減るのに見かけの明るさが変わらないのは、面積と方向の両方で密度を取ったことがちょうど距離依存を打ち消すからである。この不変性があるから、「画素から光線を1本飛ばして、ぶつかった先の放射輝度を求めればよい」というレンダリングの基本戦略が成立する。
放射束 Φ [W] → 面積で割る → 放射照度 E [W/m²] → さらに方向で割る → 放射輝度 L [W/(m²・sr)]

なぜ密度で考えるのかにも触れておく。「1本の光線のエネルギー」や「1点の明るさ」は、面積ゼロ・立体角ゼロの極限なので常に0になってしまい、量として使えない。物理で場(その場所ごとの量)を扱うときは必ず密度にする — 質量でなく密度、電荷でなく電荷密度と同じ作法である。放射輝度は「光の場」の密度表現だと言える。

歪み 2: スペクトルをRGBの3点で代表させる

放射輝度は本当は波長ごとの連続量(分光放射輝度 [W/(m²・sr・nm)])である。グラフィックスはこれを赤・緑・青の3チャネルで代表させる。根拠は人間の目の錐体細胞が3種類しかないこと(3刺激値)で、最終出力が人間向けなら多くの場合は破れない。破れるのは波長依存が急な現象を物理で追うとき — プリズムの分光、薄膜の虹、そして大気のRayleigh散乱(10.4節)のような1/λ4の現象では、3点近似の粗さが色の偏りとして現れうる。このエンジンの大気設計が「RGBの散乱係数」を持つのはこの3点近似の上に立つ工学判断である。

10.2 表面の反射 — BRDFという密度

表面に光が当たると、一部が跳ね返る。「どの方向から入った光が、どの方向へ、どれだけ出るか」を数える関数がBRDF(Bidirectional Reflectance Distribution Function。双方向反射率分布関数。日本語の意味は「入る向きと出る向きの組ごとの、跳ね返りやすさの分布」)である。第4.3章の材質(マテリアル)の物理的な実体はこの関数であり、PBRのパラメータ(基本色・粗さ・金属性)はBRDFの形を少数の数で指定する方法である。

定義を単位から組み立てる。入射側は「その方向から届いた放射照度の増分 dE [W/m²]」で数え、出射側は「その結果増えた放射輝度の増分 dL [W/(m²・sr)]」で数える。BRDFはその比である:

f(入る向き→出る向き) = dLdE 単位: [W/(m²・sr)] ÷ [W/m²] = [1/sr]

変数の定義。正確に書くと、点 x・法線 n の表面に、方向 ω入 の周りの微小立体角 dω入 から放射輝度 L入 の光だけを当てたとき、面が受ける放射照度の増分は dE=L入⋅cosθ入⋅dω入 であり(放射照度の方向分解)、その結果 ω出 方向の出射放射輝度が増える分が dL出 である。BRDFはこの2つの微小量の比 f(x,ω入→ω出)=dL出/dE として定義される — 測度論の言葉なら、入射の方向分布(測度)に対する出射応答の密度、すなわちラドン=ニコディム微分の類似物である。この定義が意味を持つ根拠は光の線形性(入射の重ね合わせに対する応答の加法性)で、これは幾何光学近似(歪み1)で干渉を捨てたことの帰結である。

単位が1/srになるのは、「入ってきたエネルギーを出射方向の全球へどう配り直すかの、方向あたりの密度」だからである。完全な鏡はすべてを1方向へ集中させ(密度は鋭い山)、白い紙はほぼ均等にばら撒く(密度は平ら。これをLambert面と呼び、その値は反射率π — πで割るのは半球で積分すると反射率そのものになるようにするためである)。

BRDFがこの形で定義できる根拠は光の線形性である: 2つの光源を同時に点けたときの明るさは、別々に点けたときの和になる(幾何光学近似で干渉を捨てたおかげで成り立つ)。線形だから「方向ごとの寄与を足し合わせる」という積分の形で反射を書ける。物理的な制約も2つだけある: エネルギー保存(出ていく総量は入った量を超えない — 半球で積分して1以下)と、相反性(入る向きと出る向きを入れ替えても値が同じ — 光路の可逆性)。PBRが「どの照明環境でも破綻しない」(第4.3章)のは、この2つの物理制約を守るように式を作ってあるからである。

歪み 3: 「表面で」反射という虚構

実は光が厳密に「表面で」跳ね返るのは金属くらいである。プラスチック・木・肌のような非金属の拡散反射の実体は、光がわずかに内部へ潜り、分子に何度も散乱されてから出てくる表面下の体積散乱である。BRDFはこの体積現象を「厚みゼロの表面の関数」へ潰した近似だと言える。潜る深さが見た目に効くほど大きい材質(肌・大理石・ろうそく・葉)でこの近似が破れ、それを繕う技法がSSS(表面下散乱、第4.3章)である。「肌はBRDFでは描けない」の理由はここにある。

  • 積分域が半球である理由: 不透明な表面では下半球(ω·n<0)からの入射が無い。透過材質(水・ガラス・肌)ではこの仮定が外れて積分域が全球になり、BRDFはBSDF(Bidirectional Scattering Distribution Function。散乱分布関数)へ一般化される。

この式の理学的な出自 — 放射輸送理論

レンダリング方程式はグラフィックスの発明ではない。これは放射輸送理論(radiative transfer)という理学の一分野の、特殊な場合である。放射輸送理論は「散乱・吸収・発光のある媒質の中を放射(光・粒子)がどう運ばれるか」の一般論で、19世紀末から20世紀半ばに恒星の大気(星の内部から出た光が大気層でどう散乱されて我々に届くか。Chandrasekharの古典が有名)と原子炉の中性子輸送(中性子が減速材にどう散乱されるか)のために発達した。輸送方程式は「位置と方向ごとの密度(まさに放射輝度と同じ構造の量)が、直進・散乱・吸収・発生でどう釣り合うか」を述べる。

グラフィックスのレンダリング方程式(Kajiya, 1986)は、この一般論を「媒質は真空(何もしない)で、散乱は表面でだけ起こる」と特殊化したものである。だからあなたの直観 — 「レンダリング方程式は光の散乱と発想的に関係していそう」 — は正確で、係数まで含めて散乱理論の子孫である。そして大気・霧・雲(10.4節)を描くときは、特殊化を1段戻して「媒質が仕事をする」元の輸送方程式へ帰る。第4.2章のradiance query(放射輝度問い合わせ)という設計目標は、輸送理論の言葉で言えば「任意の点・方向の放射輝度場を評価する口を1つに揃える」ことである。

なぜ解けないか、そして全流派はこの式の近似戦略である

この式の困難は1点に尽きる: 右辺のL入が、別の場所のL出である(壁から入ってくる光は、壁が同じ式で計算した出射光である)。つまり式が自分自身を参照する再帰(積分方程式)であり、閉じた解は特別な場合にしか存在しない。跳ね返り1回ごとに全方向の積分が入れ子になるので、まともに数値化すると次元が爆発する。ここから、リアルタイムGIの全流派が「この積分をどう誤魔化すか」の戦略として読める:

  • モンテカルロ法(パストレーシング): 積分を確率標本で置き換える。方向をランダムに選んで光路を1本ずつ追い、平均を取ると期待値が正解に収束する(大数の法則)。正しさの物差しになるが、収束が遅くノイズが出る(だからデノイザーと時間再構成(第4.4章)が対になる)。
  • 事前計算(ベイク済み画像・プローブ・表面キャッシュ): 積分の一部を先に解いて表に焼く。入力の次元を落とせる部分(大気: 高度と角度だけで決まる、第4.2章のHillaire系のベイク済み画像)や、ゆっくりしか変わらない部分(プローブのGI)がこの戦略に向く。
  • スクリーン空間(SSAO・SSR): いま描いた画面自体を「世界の粗い標本」として積分の材料に流用する。安いが画面外は原理的に見えない。

第4.2章で「GIの方式候補」として並べたものは、実はこの3戦略の混合比の選択である。これがこの章を第4章の後に置いた理由でもある — 方式の目利きは、全員が同じ1本の式を相手にしていると知っていると格段に楽になる。

10.4 体積の散乱 — 大気・霧・雲の物理

10.3節では媒質を真空と置いた。この節でその特殊化を1段戻し、空気そのものが光に仕事をする世界 — 空・霞・雲 — の量を定義する。このエンジンのOW5第7段(Hillaire系大気のベイク済み画像)が実装するのはまさにこの節の数学である。

消散係数 — 「単位距離あたりの引っかかりやすさ」

位相関数 — 散乱の「向きの好み」

散乱で向きを変えた光がどの方向へ行きやすいかの分布を位相関数 [1/sr]という(名前は歴史的な事故で、波の位相とは無関係である)。BRDFの体積版にあたる方向密度で、全方向で積分すると1になるよう正規化する(「散乱された光は必ずどこかへ行く」の数式化。第7a段のテストがこの正規化を数値積分で検査している)。

Rayleigh散乱とMie散乱 — 空が青く、雲が白い理由

  • Rayleigh(レイリー)散乱: 波長よりずっと小さい粒子(空気の分子)による散乱。散乱の強さが波長の4乗に反比例する(1/λ4)。青(約450nm)は赤(約650nm)よりおよそ(650/450)4≈4.4倍散乱されやすい。空を見上げたとき目に届くのは「太陽光のうち大気で横道に逸れて降ってきた光」なので、逸れやすい青が勝つ — 空が青い理由の全部がこの1行である。位相関数はほぼ前後対称で穏やかである。
  • Mie(ミー)散乱: 波長と同程度以上の粒子(水滴・塵・エアロゾル)による散乱。波長依存がほぼ無い(だから雲や霞は白い)。代わりに強い前方偏向を持つ — 進行方向の近くへ集中して散る。太陽の周りが白くまぶしい暈(かさ)はこの前方散乱である。第7a段が採ったCornette-Shanks位相関数は、この前方偏向の強さを非対称係数 g(0.8など)1つで表す標準近似である。

なぜベイク済み画像(表)に焼けるのか

大気の放射輝度の計算は「経路上の各点で、太陽からの透過率×散乱×位相を足し、さらに他所から散って来る光(多重散乱)を足す」という積分の入れ子で、毎画素で真面目にやると高くつく。ここで効くのが大気の対称性である: 地球大気は高さ方向にしか変化しない(水平方向は一様とみなす)。すると透過率は「高度と天頂角の2数」だけで決まり、2次元の表(透過率のベイク済み画像 256×64)に焼ける。多重散乱も同様に低次元化できる(Hillaire 2020の核心はこの分解である)。第4.2章で「事前計算戦略はゆっくり変わる・次元を落とせる部分に向く」と述べたことの、いちばん綺麗な実例が大気のベイク済み画像である。

歪み 4: 大気は「球対称の層」という理想化

実際の大気には雲・水蒸気の偏り・地形による遮蔽があり、水平一様ではない。ベイク済み画像方式はそれらを捨てて成立している。捨てた部分のうち絵に効くもの(雲)は、別の技法(レイマーチする体積雲)として貼り戻す — このエンジンの計画で体積雲が大気のベイク済み画像と別段(別途審査)になっているのは、この理想化の境界が技法の境界だからである。

10.5 カメラの数理 — 射影と深度

3次元の点を画面の画素に対応づける仕組みを、単位と意味を保って追う。ここが分かると、視錐台・深度バッファ・「深度の精度問題」・シャドウマップの座標系(10.6節)がすべて1本につながる。

射影は「割り算」である

遠近法の核心は1つの割り算に尽きる: 遠い物ほど小さく見えるのは、画面上の大きさが距離で割られるからである。カメラを原点に置き、視線方向にz軸を取ると、位置(x, y, z)の点が画面上に映る位置は、比例定数を別にすれば(x/z, y/z)である。相似三角形そのものであり、これ以上の内容はない。透視射影行列という4×4の行列が仰々しく見えるのは、この割り算を行列計算の枠組み(同次座標。割り算を「第4成分wへ分母を貯めておき、最後にwで割る」形に直したもの)へ収めるための帳簿仕事だからで、数学的な中身は割り算1回である。同次座標の言葉で正確に言うと、射影空間 ℝP3 の斉次座標 (x,y,z,1) に線形写像(4×4行列)を掛け、最後に第4成分で割って代表元を取る、という構成である。射影(非線形)を線形代数の道具で扱うための標準的な持ち上げであり、GPUのパイプラインがこの形を固定機能として持つ。

深度は1/zで記録される

深度バッファに入る値は、実はカメラからの距離zそのものではなく、zの逆数に比例する量である(同次座標の割り算の副産物としてそうなる)。これは偶然の産物だが、都合が良い面と悪い面がある。良い面: 1/zは画面上で線形に補間できる(三角形の内部の深度を頂点から正しく補間できるのはこの性質のおかげである)。悪い面: 精度の配分が手前に偏る。1/zは手前で急に変化し遠方でほぼ平らになるため、記録の目盛りが手前に細かく遠方に粗くなる。遠方で「どちらが手前か」の判定が壊れてちらつく欠陥(Zファイティング。深度の精度切れによる縞や明滅)はここから来る。現代の対策は逆Z(深度の0と1を逆に割り当てると、浮動小数点の「0付近に目盛りが密」という性質が1/zの偏りとちょうど打ち消し合う)で、遠距離描画の標準になっている。

画面座標 = (x / z, y / z) ・ 深度バッファの値 ∝ 1 / z　割り算が遠近法のすべて。深度が1/z系であることが精度問題の根

視錐台とは「画面に映る範囲の逆像」である

画面は有限の四角形で、深度にも手前と奥の限界(近クリップ・遠クリップ)を置く。この「画面に映りうる範囲」を世界側から見ると、カメラを頂点とする四角錐の頭を切った立体になる — これが視錐台である。視錐台カリング(4.5章)が数学的にやっていることは、「物の包囲球が、視錐台を成す6枚の平面のどれかの外側に完全にあるか」という平面と球の距離判定6回である。1個あたり数ナノ秒で済む理由がこの単純さである。

10.6 影の数理 — シャドウマップからCSMまで

シャドウマップの原理は「2つのカメラの深度の照合」

影の判定は次の1文に還元される: 「その点は、光源から見えるか?」。シャドウマップ方式はこれを2段で解く。(1)光源の位置にカメラを置いて世界の深度だけを描く(これがシャドウマップ)。(2)本番の描画で各画素の位置を光源のカメラの座標系へ変換し、「私から光源までの距離」と「シャドウマップに記録された、その方向の一番手前の距離」を比べる。記録より自分が遠ければ、間に何かがいる — つまり影である。

影である ⇔ 光源座標系での自分の深度 > シャドウマップ(自分の位置に対応するテクセル)の深度2台のカメラの帳簿の突き合わせ。10.5節の射影をカメラと光源の2回使う。記号で書くと、光源の射影を P光: ℝ³→[0,1]³(光源クリップ空間への写像)、シャドウマップを D: [0,1]²→[0,1](テクセル格子上の深度場)として、点p∈Mが影 ⇔ P光(p)の深度成分 > D(P光(p)のxy成分)

この単純な比較には数値上の罠が2つあり、影の実装の苦労の大半はこの2つとの戦いである。(a)自己影のにじみ(シャドウアクネ): 自分の深度と記録された自分自身の深度は本来同じ値だが、テクセルの解像度と数値誤差でわずかにずれ、「自分が自分の影に入る」まだら模様が出る。対策は比較に小さな下駄(バイアス)を履かせることだが、履かせすぎると影が足元から剥がれる(ピーターパン現象)。(b)解像度の不足: シャドウマップの1テクセルが世界の何メートルを覆うか(世界メートル毎テクセル)が粗いと、影の輪郭が階段になる。

PCFの数理は「二値判定の平均化」

上の比較の結果は影/非影の2値で、そのままでは輪郭がジャギーになる。PCF(影の多数決ぼかし)の数理は、比較を1回でなく周囲N点で行い、「影だった割合」を影の濃さにすることである。重要なのは順序で、「深度を平均してから比較する」のではなく「比較してから割合を取る」。深度の平均は物理的に無意味な値(手前の葉と奥の地面の中間の深度)を作るが、比較結果の平均は「この画素の面積のうち影に覆われた割合」という意味のある量の推定になる。これは10.8節のモンテカルロ的発想(積分をサンプルの平均で推定する)の最初の実例である。

CSMの分割式 — 一様と対数の混合

CSM(4.1章)の本質は解像度予算の配分である。カメラからの距離[近, 遠]を4帯に区切るとき、区切り方には両極がある。一様分割(等間隔)は遠方に手厚く近くに薄い。対数分割(等比: 各帯の遠近比が一定)は、10.5節の「画面上の大きさは1/z」という事実と噛み合う理論最適で、どの帯でも画素あたりの影の解像度が揃う — が、近距離の帯が極端に狭くなりすぎる。実用は両者の混合であり、本エンジンの実用分割(practical split)は混合率0.6で対数側に寄せている(設計正本の確定値)。数式で書けば、i番目の区切りは 混合率×(対数分割の位置) + (1−混合率)×(一様分割の位置) である。

テクセルスナップの数理 — 量子化による不変化

カメラが動くたびにシャドウマップの範囲(正射影)も動くと、世界の同じ場所を覆うテクセルの位相が毎フレームずれ、静止物の影の輪郭がちらちら泳ぐ。対策の数理は量子化である: 正射影の中心を連続に動かさず、シャドウマップの1テクセルぶんの世界幅を刻みとする格子の上にしか置かない(格子への吸着)。すると1テクセル未満のカメラ移動では正射影が全く動かず、静止物の影のテクセル座標が厳密に不変になる。本エンジンはこの不変性を「2フレームの合成経路で静止物の光源クリップ座標が一致する」というユニットテストで機械検査している(補遺5eの成果。「行列が不変」ではなく「行列×相対座標の合成が不変」が正しい契約である、という是正の経緯ごとこのエンジンの記録に残っている)。

10.7 PBRの中身 — マイクロファセット理論

4.3章と10.2章でBRDFを「跳ね返し方の密度」と定義したが、PBRの標準BRDFの中身はどこから来るのか。答えはマイクロファセット理論(microfacet theory。微小面理論)という、統計で表面を記述する物理モデルである。

発想: 表面は小さな鏡の集まりである

どんな表面も、顕微鏡の尺度では小さな平面(微小面)の集まりであり、1枚1枚の微小面は完全な鏡だと考える。表面が「粗い」とは、微小面の向きがバラバラだということである。すると表面の反射は「無数の小さな鏡の統計」になり、パラメータは微小面の向きの分布だけになる。粗さ(roughness)の正体はこの分布の広がりである: 粗さ0はすべての鏡が同じ向き(=1枚の鏡)、粗さ大は向きがてんでばらばら(=ぼけた反射)。

この統計を数式にすると、鏡面BRDFは3つの因子の積になる(Cook-Torranceモデル):

鏡面BRDF = D × G × F ÷ (4 × cosθ入 × cosθ出)D: 向き分布 [1/sr] ・ G: 遮蔽 [無次元] ・ F: フレネル [無次元]
  • D(分布項): 「入射光を出射方向へ跳ね返せる向きの微小面が、どれだけの割合で存在するか」。粗さがここに入る。現代の標準はGGXという分布で、裾が長い(強いハイライトの周りに淡い広がりが残る)性質が実測の材質とよく合う。
  • G(幾何項): 微小面どうしが互いに影を落とし遮り合う減衰。浅い角度で効く。これが無いとエネルギー保存が破れる。
  • F(フレネル項): すべての物は、浅い角度で見ると鏡になるという物理現象(水面を真上から見ると底が見え、遠くの水面は空を映す、あれ)。反射率が視線の角度で変わる効果で、電磁気学(マクスウェル方程式の境界条件)から導かれる。PBRの「金属性」の正体はここにある: 金属はF(正面から見た反射率)が高く色付きで、非金属は低く無色(約4%)である。

この理論の見事さは、「基本色・粗さ・金属性」という直感的なつまみが、それぞれ物理量(アルベド・微小面分布の幅・フレネル反射率)に1対1で対応していることである。PBRが「どの照明でも破綻しない」(4.3章)のは、つまみの裏に物理があり、エネルギー保存と相反性(10.2節)を式が守っているからである。

10.8 積分をくじ引きで解く — モンテカルロ法

10.3節でレンダリング方程式が「解けない積分」であることを見た。ここでは、それでも答えを出す確率論の道具 — モンテカルロ積分 — を最初から組み立てる。パストレーシング・SSAO・RTGI・PCFの多数決・TAAの標本蓄積は、全部この1つの考えの応用である。

原理: 平均で積分を推定する

「関数fの区間全体での積分」を知りたいが、fは1点ずつしか評価できないとする。モンテカルロ法の答えはくじ引きである: 区間からランダムに点をN個選び、fの値の平均に区間の大きさを掛ける。この推定値は、Nが増えるほど本当の積分値に近づく(大数の法則)。重要な性質が2つある。

  1. 誤差は 1/√N でしか減らない。標本を4倍にして誤差が半分、100倍にしてやっと1/10である。この遅さがレイトレーシングのノイズの正体であり、「1フレームでは足りない標本を時間方向に積み増す」(TAA・デノイザー、4.4章)という発想の必然性でもある。
  2. 次元に強い。普通の数値積分(区間を升目に切る)は次元が増えると升目の数が爆発するが、モンテカルロの1/√Nは次元によらない。跳ね返りのたびに積分が入れ子になる(=次元が増える)レンダリング方程式に対して、事実上唯一の正攻法である。

重点サンプリング — くじを賢く偏らせる

精度を上げる王道は、標本を増やすことではなくくじの偏らせ方である。積分への寄与が大きい場所(明るい光源の方向・BRDFの鋭いローブの方向)を高い確率で引き、その分を確率で割って補正する — これを重点サンプリング(importance sampling)という。「寄与の大きいところを重点的に調べ、えこひいきした分は割り引いて帳尻を合わせる」という、世論調査の層化抽出と同じ考えである。GGX分布からの標本化・光源に向けた標本化など、レンダラーの品質はこの偏らせ方の巧拙で決まると言ってよい。

ノイズとデノイズの位置づけ

モンテカルロの推定値は毎回ぶれる(分散を持つ)。画素ごとに独立にぶれるから、絵はざらざらのノイズになる。デノイザー(4.4章)の数理的な役割は、近くの画素・過去のフレームという「ほぼ同じ積分を解いているはずの標本」を借りてきて、実効的なNを増やすことである。時間再構成(TAA)とデノイザーが部品を共有する(4.4章)のは、どちらも「よそから標本を借りて平均する」同じ数理だからである。借りてよい相手か(同じ面か・動いていないか)の判定を誤ると、ゴーストや残像(借りてはいけない標本の混入)になる。

10.9 標本化の数理 — エイリアシングの正体とTAA

エイリアシングとは「標本化が生む偽物の模様」である

画面は連続な像を画素の格子で標本化(サンプリング)したものである。標本化には信号処理の根本定理(標本化定理)がある: 標本の間隔より細かい模様は、正しく記録できないだけでなく、別の粗い模様に化けて記録される。この化けた偽物がエイリアス(alias = 偽名・別名)であり、エイリアシングの語源である。遠くのフェンスの金網が粗い縞に化ける(モアレ)、細い手すりが点線に千切れる、動くと輪郭がちらつく — 全部「画素間隔より細かい情報が偽名で紛れ込んだ」現象である。

重要なのは、これはぼかしで消える汚れではなく、標本化の時点で混入する原理的な偽情報だということである。後からぼかすと偽の模様ごとぼけるだけで、正しい像には戻らない。正攻法は標本化の前に細かすぎる成分を除くか(プリフィルタ)、標本を増やすかの2つしかない。

TAAの数理 — 標本を時間に分散し、指数移動平均で蓄える

画素あたりの標本を増やしたいが、1フレーム内で増やす(スーパーサンプリング)のは費用がN倍になる。TAA(4.4章)の数理は2つの部品からなる。

  1. ジッタ = 標本位置の時間分散。毎フレーム、画素内の標本位置を既知のパターンでずらす。1フレームだけ見ると1標本のままだが、Nフレーム分を重ねれば画素内のN箇所を標本化したことになる。空間で増やせない標本を時間方向に借りる、という発想の転換である。
  2. 履歴混合 = 指数移動平均。フレームnの画素値を xn、蓄積(履歴)を yn として、漸化式 yn=αxn+(1−α)yn−1(混合率 α∈(0,1]、慣習的に0.1程度)で混ぜ続ける。展開すると yn=α∑k=0∞(1−α)kxn−k — 過去のフレームを幾何級数的な重みで平均する指数移動平均であり、重みの実効的な幅(重心)はおよそ 1/α フレームである。画像1枚分の記憶だけで直近約10枚の平均を保持できる、メモリ効率の良い形である。標本の分散はおよそ α/(2−α) 倍へ縮む(独立同分布の仮定下)。αを小さくすると滑らかだが応答が遅く(ゴーストが増え)、大きくすると応答は速いがちらつきが残る — この1母数がTAAの品質チューニングの本体である。

この2部品の弱点がそのまま4.4章の部品一覧に対応する: 過去の標本は「動いた物」の上では別の場所の標本なので、どこから来たかの追跡(モーションベクタ)が要る。追跡できない場所(disocclusion = 物陰から出たばかりの領域)では過去を借りてはならず、借りると偽の記憶(ゴースト)になる。つまりTAAとは「時間方向のモンテカルロ標本化+借りてよい標本の検定」であり、10.8節の数理の時間版である。

10.10 露出の数理 — EVという対数の物差し

現実の輝度は桁で動く: 星明かりの地面はおよそ0.001 cd/m²、室内は100、曇り空は1,000、太陽の直射面は100,000を超える。8桁の幅を持つ量を線形の物差しで扱うのは無理があるため、写真の世界は対数の物差しを使う。それがEV(Exposure Value。露出段)であり、1段 = 明るさ2倍である。EVで+3段は2³=8倍を意味する。人間の明るさの知覚もおおよそ対数的(2倍の輝度が「同じくらいの1段明るい」に感じる)なので、対数は物理の都合と知覚の都合が一致する物差しでもある。

本エンジンの露出の型(設計正本)がこの構造をそのまま写している: UI/CLIの露出倍率(線形)と、天空状態が返す露出補正段(EV。2を底とする段数)を分け、最終倍率 = 露出倍率 × 2^補正段 で合成する。夜の補正が「+2段」なのは「夜は目が慣れて4倍明るく感じる分を絵に入れる」という意味である。HDR(広い明暗幅のままの計算)・トーンマッピング(表示できる幅への圧縮)・自動露出(輝度分布からの段の自動決定)は、すべてこの対数の物差しの上の操作である。
